# Pi 开发协作

本目录只配置开发工具，不改变产品架构或运行依赖。先按 [Agent 入口](../AGENTS.md#执行环境与任务分流) 判断是否适用；职责、授权和交付上限以 [计划](../.dev/plan.md#逐关实施与交接) 为准，实际验证见 [当前交接](../.dev/progress.md#验证结果)。

## 保留什么

| 文件 | 职责 |
|---|---|
| `settings.json` | 资源加载、压缩、有限重试和子代理模型范围；不指定主会话模型 |
| `agents/hvs-implementer.md` | 日常 GLM 5.3 / max，实现与自检 |
| `agents/hvs-simplifier.md` | 已结束专项的 Sol / high 角色定义；不自动复用，重启须重新明确授权分工 |
| `agents/hvs-reviewer.md` | GPT-6.1 Sol / high，独立只读审核 |
| `review.schema.json` | 完整审核 JSON 格式，不作为子调用的 outputSchema |
| `prompts/hvs-work.md` | 可选 `/hvs-work` 入口；自然语言派单同样有效 |
| `pi-host.mjs` | 自检使用的 Pi SDK／公开工具适配，不是调度器 |
| `check.mjs`、`check.test.mjs` | 离线能力、报告格式及拒绝条件检查，不调用模型 |

主会话模型由用户选择，项目不设默认型号或候选列表。日常实现用 GLM、独立审核用 Sol；角色必须是不同会话。已结束专项的定义不授权新任务，也不改变日常分工。high 是工程选择，不声称官方指定。

不新增执行插件、CLI、轮询器或调度平台。主会话使用原生子代理、监督通道和 mission；轮次限制是操作纪律，不保证无人值守、自动重启或恰好执行一次。

## 加载与影响范围

- 项目配置须逐仓信任，不信任整个父目录或 Gold 仓。不改其他 Agent 的专属配置、共享技能或全局安装。
- 包声明固定安装版本，升级须重新验证；不按版本号分支。项目用 `autoload: false` 复用用户级安装，用 `!**`／明确路径筛选资源。
- 项目启用 pi-web-access、pi-subagents 扩展和 `/hvs-work` 提示；主会话自检另允许用户自行安装的可选 `@bacnh85/pi-notify` 通知扩展，不要求安装，也不自动加入子代理。其他未知扩展仍不通过自检。**不自动加载包的协作技能与提示**；其 API guide 按需阅读，通用 recipe 不决定项目分工，也不强制拆成组件所有者、集成所有者或多重审核。
- 内置代理停用，子代理常规扩展为空；插件必需的内部协议工具仍由插件提供。限制不是操作系统沙箱，bash 仍可能写入，故只读纪律、Gold 隔离和 Git 授权必须核查。
- 仅配置变化可 `/reload`；包替换须重启 Pi。新 SDK 进程通过不证明当前会话已热加载；新派单前检查实际注册角色、模型和权限。

## 与包版本解耦

项目只依赖公开工具及当前 guide。`pi-host.mjs` 使用包公开入口、Pi SDK 和注册工具，不导入插件内部源码、不解析终端文案、不猜临时目录。必要能力缺失则暂停，不删检查冒充兼容。

升级时先备份设置与锁文件，只调整安装声明和必要适配。重启后离线检查，再用获准合成任务验证启动、审核输出、退出证明与续接；失败保留现场，按同协议修复或经同意回退。不补丁全局包，不静默改用 CLI 或前台运行。未运行的安装脚本和未测功能据实记录。

## 压缩与重试

自动压缩使用 `reserveTokens=32768`、`keepRecentTokens=20000`；仅 GLM 5.3 覆盖 reserve 为 700000。当前 registry 窗口 1000000，约在 300000 token 触发；其他模型沿用普通设置，阈值随其真实窗口计算。离线检查核对子代理模型和设置，不约束用户所选主模型。

压缩在后续请求前检查，不是严格请求长度上限；保留摘要、近期上下文和原始会话，不清任务计数。压缩本身也可能额度失败。磁盘设置改变不证明既有子进程采用新值。

Pi 瞬时错误最多重试 2 次，provider 层为 0；工作流不再叠加自动重试或换模型。唯一持续例外是下文明确的 GLM 5 小时额度等待。

## 运行时限（暂行）

当前插件公开协议不能真正关闭单个子项的总deadline；删除字段会回退默认时限。按用户明确批准，日常 `hvs-implementer` 单次上限为2小时（`7200000ms`）；审核者维持原1小时，本次未改，已结束专项角色也不调整。这是暂行有限上限，不表示无时限运行已经实现。正常工作不另加更短的总时限或提前停止请求；额度和真实异常仍按故障协议处理。

新派单前核对实际公开角色配置；旧会话续接保留stored contract，磁盘改动不证明旧会话已采用新上限，恢复前单独核对，不静默fallback或修改原始回执。时限自检核对声明与公开执行能力，不代替真实长运行验证。

## 主会话操作协议

### 整关派单与送审核对

默认一次交付当前整关已批准、可执行的工程范围，不因文件多而拆成独立闭环。历史专项的批次不是当前派单计划；先按 [任务协作范围](../.dev/plan.md#任务协作范围) 确认分工和授权。

派单前固定原始需求、范围与非目标、保留行为、允许删掉的保证、数据与兼容边界、验证要求、Git 基线和写入责任。说明哪些已完成可复用、哪些需另行授权；不要求实现者先提交详细文件级施工计划。

一位实现者完成本批接口、集成、测试和配套说明。初次审核、二次审核、最终审核均接收**同一完整任务**、实际全部差异、实现报告与已知缺口，不以底层组件或上一份修复清单代替整体交付。可预先在一个串行 workflow 内安排“初次实现完成 → 初次审核”；实现失败就停止，不边写边审。主会话在结果交回后核对覆盖、证据和取舍，不重复完整技术审核。

### 1. 固定任务与持久交接

配置或包变化后先运行 `PI_OFFLINE=1 node .pi/check.mjs`；在当前聊天激活插件，再用 `subagent({action:"list", agentScope:"project", capabilities:true})` 确认可执行角色和模型。型号覆盖必须先查询 registry。能力发现不是模型已成功调用的证据。

新任务在 `.work/<taskId>/contract.md` 固定说明；taskId 只用字母、数字、连字符或下划线，不复用已结束子空间。创建或随首次 workflow 建立一个原生 mission，关联该说明，不启用 goal。同一任务串行交接，progress 仅保留状态、missionId 和恢复入口。结束后按 [共用归档规则](../CONTRIBUTING.md#收尾检查与工作材料归档) 整体移动子空间；先核对终态并停用残留通知，历史 mission／会话／回执不改写，以归档索引映射旧路径。追溯归档不授权重新执行旧任务。

原生 `state` 的 `delivery` 只记必要事实：任务说明、当前批次与审核轮次、阶段、各角色最新 runId／报告路径，以及未决启动的 key／resumeId／错误。启动前保存未决项，成功收取后清除；保存失败不启动。已有记录或未决启动先核对，不重新初始化。旧任务的历史 cycle/round 保留，不因规则变更自动重置预算。用户明确批准调整上限时记录原／新上限与依据，只调整允许的上限，不清零已用轮次或改写历史回执；后续合法续接在原delivery落实，未决启动先核对。

### 2. 启动、结果与故障

获准的多步骤工作使用**一个外层 `async:true` workflow**，子项由 `await runs.run(...)` 串行等待，不对子项设置仅返启动回执的 `async:true`。初次实现及初次审核、二次审核、最终审核均显式 `context:"fresh"`；初次修复、最终修复续接实现者精确最新 runId。输出通过子调用的 `output` 绑定到本任务子空间下绝对路径，不写入 `archive/`，不要求只读审核者写文件。

审核调用不传 `outputSchema` 或 acceptance 覆盖。审核者输出完整原始 JSON，再附单独的原生 `acceptance-report`；运行时保存报告及回执。主会话从实际 `outputReference` 读取整份报告，以 `node .pi/check.mjs --review /绝对路径/review.json` 校验；不能解析可能附带路径提示的展示文本来猜 verdict。

checked 只是实现交付凭据，不是技术通过；attested 只是审核回执，不代表 verdict 为 pass。必须核对具体 run 终态、实际报告、验证依据及公开退出证明（当前 `processTerminalProof`／`workflowTerminalProof` 为 `observed`）。缺失、截断、rejected 或矛盾则暂停，不自行补字段或降级问题。

启动后记下实际 workflow/run ID 和路径，等待原生完成通知，交互中不 sleep、轮询或仅为等通知调用等待工具。监督询问用原生 supervisor 回复。等待提前返回不代表完成；不能因此销毁会话或换一个执行器重跑。

基础设施、额度、压缩或进程失败后停止交接，记录精确错误、运行状态、cwd／分支／ref 及部分 diff。重启从原 mission、精确 run status 和实际文件恢复；既有有效成果不重跑，活动或终态不明时不再启动写入者。普通失败的重试须明确授权；不静默 fallback、换模型、清预算或新建 mission。

### 3. 审核与修复

执行 [计划的阶段与取舍规则](../.dev/plan.md#逐关实施与交接)：**初次实现 → 初次审核 → 初次修复 → 二次审核 → 最终修复 → 最终审核**，最多三次实施、三次审核，可提前结束。自检、获准的实现超时续接或额度恢复不新增交付阶段；不清已用审核次数、不自动无限恢复。最终审核仍有确认需修复的严重问题或无进展／偏离时暂停讨论，不自动追加第四次。

**审核者应尽可能全面、深入地发现问题，并向主会话完整报告；主会话选择哪些问题值得修复。** 不要求审核者只找严重问题或只审旧清单；报告不设发现／风险数量上限，事实、假设和未验证项须分清。同类问题可清楚归组，不能为缩短报告漏掉发现。主会话逐项按计划的影响／证据／成本取舍，只把确认值得修复且获准的事项交给实现者，记录其他意见的理由；不得按标签自动派补丁。

审核 JSON 的 `must_fix`／`optional` 与 verdict 是审核者的建议及独立技术意见，不是主会话最终修复清单：

- `pass`：审核者未提出 must_fix 建议且有实际依据；父仍核对需求、剩余风险及必要集成检查。
- `changes_required`：审核者建议修复，须说明问题、影响、证据／假设与最小方向；父判断是否值得修复，不自动扩大范围。
- `blocked`：明确缺失的证据、授权、设计或基础设施，不能以无证据声称通过。

保留原报告与父取舍，分歧不靠改写 verdict 消除；未满足明确验收条件不能伪称通过，需改变条件时交人类审定。技术通过不等于关卡放行、科学批准或 Git 授权。

初次修复、最终修复续接原实现者，保持角色／模型／工具。已知精确 runId 先查 status，再尝试 resume；`children.list` 非全部子任务清单，资格由插件判断。用 `runs.run(新key, {resume: 最新runId, task: ...})` 等待并记录新run；报告可能覆盖，先保存旧快照。无可用会话或资格拒绝时暂停，获准才使用明确标注的 fresh fallback，不清次数。

三个审核阶段分别用 `runs.run(新key, {agent:"hvs-reviewer", context:"fresh", task: ...})`，不续接上一审核者；这是正常独立审核，不是 fallback。送审包包含原需求／支持边界、当前完整树与基线、最新实现报告、此前审核报告、父取舍及修复证据；旧判断是资料而非审核结论约束。核对实际会话与之前实现者、审核者不同，不能只凭配置声明fresh。二次／最终审核仍全面深入检查整体及新问题，旧问题和修复差异是起点而非范围上限；按影响复用有效验证并补检查，不每读一个文件重复全仓测试。

新审核阶段在启动前持久记次数及唯一pending；故障不靠新上下文绕过恢复授权或重置预算，保留失败身份及现场后按故障协议处理。现行实现者2小时／审核者1小时、只读纪律、隐私和科学／Git授权均不因完整审核而取消。

### GLM 额度等待

用户已持续授权：**明确的 GLM 5 小时额度耗尽，每隔 30 分钟尝试原模型原角色恢复；周额度立即暂停。** 不授权 fresh fallback、增加轮次、新任务或科学／Git 操作；用户暂停优先，单次明确的恢复时间优先。

依据精确失败 run 的完整 provider 错误判断，不依据模型总结。明确“5 小时／5-hour 使用额度耗尽”且无周额度证据才重试；周额度优先；仅 429、1308、reset 时间或不明确报文都暂停。目前仅实测 429/code1308 携带“已达到 5 小时的使用上限”，周额度真实报文未验证。

1. 核对进程结束并保存部分改动、错误、最新 runId；原审核轮次不变，额度尝试独立记数。
2. 在原 `delivery.quotaRetry` 保存失败 run、attempt、nextAt、scheduleId、状态和证据；保存失败不调度。
3. 用一次性 `schedule.create`、`at:'+30m'`、`sessionOnly:true` 唤醒父会话；脚本只返回带 mission/run 标识的通知，不启动实现者。每次失败至多一个通知，不用 every、sleep 或轮询；结果不明先查 schedule。
4. 唤醒后核对最新状态、用户暂停、精确会话可恢复性及同目录无写入者，保存新的唯一 pending 后才恢复。旧通知不重放，未知错误不猜测；再次明确 5 小时耗尽才安排下一次。
5. 成功、周额度、暂停、完成或授权失效时取消残留通知，保留历史证据。电脑和原会话须运行；重启后核对过期通知，至多恢复一次，不补发累计次数。

定时能力或安全续接缺失则报告，不改用其他执行方式。连续额度恢复、周额度判断等未实测范围必须写入 progress。

## 测试与自检

运行 `PI_OFFLINE=1 node .pi/check.mjs`、`PI_OFFLINE=1 node --test .pi/check.test.mjs` 和 `git diff --check`。能力检查在父 Pi 环境运行，不清除子代理安全环境变量；子代理可以运行测试并阅读父会话的检查报告。

自检覆盖资源、公开 list/get/children.list/validate、模型／工具／验收配置和 compaction/retry，不启动模型。`--output .work/<taskId>/offline.json` 在当前任务子空间保存版本、输入哈希和证据；失败撤销旧通过结果。使用证据前核对输入与版本，不能把陈旧报告当成当前结果。特殊 SDK 布局用 `HVS_PI_PACKAGE_ROOT`，不写全局环境。

静态检查不代替真实调用。配置变更后的新角色用 fresh 调用核实；既有 resume 保留旧契约。合成测试限获准范围，不触碰业务数据／Gold，不为测额度耗尽制造费用。仅报告实际覆盖的启动、完成、续接、故障与重启场景；未测项保持未验证。历史 `.work/archive/check-pi-config.mjs` 不是当前入口。
