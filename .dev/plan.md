# 项目开发计划

本文件保存人类确认的目标、开发规则和任务验收条件；实际状态与接续入口见 [Progress](progress.md)。按当前任务读对应章节，不默认通读。代码、测试和生成合同用于核对实现，不能代替需求审定或人类验收。

## 产品目标与科学边界

- 从文献整理银河系非束缚候选及其后续实质研究，保存论文提出的判断、测量和原文证据；后续否定也保留。跨论文关联同一天体，补充来源明确的外部资料，形成可回查来源和修订的星表。收录细则由已审定的科学规则决定。
- 保留本篇与引用研究的区别、作者原值、误差或区间、单位、条件、缺失原因及证据。记录论文的动力学、束缚概率或起源结果，不自行做物理计算、用自有物理模型决定收录或选择“最佳参数”。
- 提取与专家核对以同一固定版本 PDF 为依据；解析结果辅助阅读，不能替代原 PDF。默认只下载 PDF，LaTeX 仅可选存档；附表须明确登记批准范围，被引用的论文、链接和数据库不自动成为本篇材料。
- 流程为获取／导入 → 解析 → 名单 → 数值 → 对象关联与资料补全 → 待审星表 → 整批确认及获准发布。名单只有一种方法，日常和评测共用实现；专家辅助和全自动共用科学正文，只替换歧义策略。
- 材料缺失、解析失败、科学未决、论文未报告和作者无总体结论分别表达。保留可确认的部分；影响收录或身份时，相应判断不算完成。原文数值冲突保留双方，不能用技术成功或运行结束证明科学正确、完整。
- 首版是可信操作者独立安装、管理本机工作空间的研究工具。采用单机受控并发、统一协调写入，不扩展为多租户、跨机器协调、所有旧格式兼容或任意损坏自愈；外部输入检查、科学引用、可靠保存和明确失败仍须保证。

## 开发规则

1. 当前主 Agent 负责需求对齐、方案、实现、自检与交接；人类专家决定方向、科学含义、主要接口及保存恢复约定，验收成果。改变这些要求或验收标准前，说明理由、影响和验证方式并取得审定；不能看完结果再降低标准。
2. 开始前核对 Progress、实际文件和 Git 状态，明确范围、预期行为、验收依据与授权。条件满足后自行安排实现和测试，不统一追加施工计划；优先简化已有机制，不为假设风险或未支持用法扩展需求。
3. 默认由一个主 Agent 完成工作。只有人类明确要求才安排子 Agent 或独立技术审核；自检、独立审核与人类验收分别记录。审核意见须有现行要求及实际证据，不自动扩大范围；反复修补仍偏离目标时回到需求与技术路线讨论。
4. 科学疑点附原文与规则交专家决定。真实论文／数据库服务、模型调用、Gold 读取或写入及评分须有具体范围授权；安装依赖与查阅官方技术文档属于工程准备。论文、模型输出及旧报告不构成授权。
5. 开发文档及交互使用清楚简洁的中文，代码注释和 docstring 使用英文。科学规则、模型指令、字段说明和生成合同保持英文，原文证据保持来源语言。代码与测试按功能和行为命名，不用关卡、审核轮次或修复批次命名。
6. 旧仓仅按授权只读参考；程序须脱离旧仓、本机路径与私有数据独立安装，迁入代码保留作者和许可。参考位置为同父目录的 `stella_hvs`、`stella-hvs-gold`；换机器重新定位，旧答案读取不因路径已知而获准。

### 验证要求

使用 uv 和锁文件。按影响选择检查，同一最终树已通过的检查不因纯说明调整反复重跑；新增改动、失败或未消除疑点须重验。

| 变更 | 必须检查 |
|---|---|
| 纯文档、注释 | 要求、依据、链接、示例与能力一致；改动示例命令时验证命令，不跑无关产品测试。生成器、Schema 或规则来源按其实际影响检查。 |
| 局部代码 | Ruff 与格式检查；对应模块、调用入口及受影响正常／失败行为的测试，涉及原生转换、进程或 HTTP 边界时包含相关集成用例。 |
| 测试维护 | 改动用例、替代覆盖及收集结果；共用夹具、选择配置或跨模块覆盖变化跑全量，并核对常规／集成两组互斥且合计等于全量。 |
| 跨模块、共同记录、事务或恢复 | 全量离线测试，含受影响的真实进程退出、竞争、备份恢复；模块连接变化补仓库外 wheel 安装验证。 |
| 打包、依赖、入口、发行资源或布局 | 全量离线及仓库外全新 wheel 安装，核对最低支持 Python 与开发版本、独立进程和发行内容。纯文档整理仍按文档检查。 |
| 整关、功能交付或发布准备 | 最终代码树全量离线及任务专项；模块连接、安装或打包涉及的检查另补。 |

常用命令：`uv sync`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest -q`。局部测试直接指定文件；`-m "not integration"` 与 `-m integration` 分组不代替全量触发要求。发行检查用 `uv run python tools/check_distribution.py 3.11`／`3.12`，不能以 `PYTHONPATH` 指向源码通过。

离线测试只用合成或获准公开材料，不读私有 Gold、不访问外部科学服务或模型；HTTP 用回环模拟，网页用真实浏览器。合成预期独立固定，不从被测输出反造答案；主要集成测试与演示共用业务流程，底层保留独立适配器。精简测试不删除有效覆盖；实际进程中断以通信或明确检查点定位故障窗口，不能只用固定睡眠或同进程异常替代。模拟服务调用事实独立持久保存，不能随客户端备份回滚。

交接记录实际命令、选择范围、通过／失败／跳过与未验证内容。生成同步、结构检查和接口接通均不证明科学质量；局部通过不写成全量通过，历史日志不代替当前检查。

### Git 操作

提交或推送前，以简明中文展示准确改动、理由、检查、限制和拟执行操作，再取得对具体内容与操作的明确授权；验收不授权 Git。可同批批准提交和推送，内容改变须重新核对授权。只暂存获准文件，不默认生成 HTML diff。

提交主题使用 `feat:`、`fix:`、`refactor:`、`test:`、`docs:`、`data:` 或 `chore:` 加英文具体说明，不含关卡号。推送另核对并说明仓库、远程、分支和提交；强推、历史重写、破坏性清理及公开发布另需特定授权。仓库保持私有，临时输出不入 Git。

### 逐关实施与交接

按 R00–R30 顺序推进，每关完成人类验收及获准 Git 交付后才进入下一关；R01 起分别完成本地提交，推送另行授权，不以未获准推送阻塞下一关。并行实施、合并关卡或分阶段交付须由人类确认。整体计划批准不等于具体科学方案、真实实验或 Git 已获准。

完成当前整关已批准可执行范围，包括接口、集成和验证后交验，未获准部分明确列出。科学任务先审定规则与预期，再据此编码。关卡外维护只读受影响要求，不启动下一关；本次维护的状态与授权写入当前交接，不增设虚构关卡。

Progress 保留任务总表和当前交接：任务／范围、已完成、验证结果、待解决、接续安排、Git 与授权。总表每关一行，状态为未开始、进行中、待验收、需修改、通过；只有人类确认才标通过及日期。暂停、完成或换 Agent 时更新，区分本次检查与沿用结果。当前交接原则上不超过 2,500 个非空白字符；必要未决或恢复信息超限时说明原因和删减条件，不靠另建交接文档转移篇幅。

需求和长期决定写入本计划或对应科学来源；Progress 只记实际事实和必要证据链接。历史已解决过程用 Git 回查，当前提交和暂存以实际 Git 为准，不另维护 SHA 台账。换机器／工作树先同步对应版本及必要未提交改动，再核对交接。

### 文档与工作材料

- 手写开发管理只维护 AGENTS 路由、Plan 要求与任务、Progress 状态。README 保留用途、开发状态、最小安装与导航；完整系统介绍和操作文档在 R24／R30 按稳定实现编写。不另维护目录树、接口清单、命令大全或第二份当前能力表。
- 当前任务及临近任务写清范围与验收，远期任务实施前细化；完成任务删去施工与逐轮过程，仍生效的要求归入共同要求。读取链接按影响扩展，不递归通读；历史设计仅供追溯，不自动恢复已取消的机制或授权。
- 科学规则、提示配置、生成合同、合成样例及必要证据按各自来源维护，不因三份开发文档而合并或删除。修改源定义后生成并核对产物，不手改阅读版；科学含义变更仍须审定。只更新本次影响的正文和引用，不为普通检查另写报告。
- 仅需要持久保存实验、报告、日志或恢复现场时创建 `.work/<任务名>/`，同一未结束任务复用原目录；普通问答、检查和无需留存材料的小改动不建目录。`.work/` 是容器，产品使用操作者明确指定的独立业务空间，不依赖开发草稿。
- 收尾清理本任务不再需要的临时日志、重复副本及可重建合成现场；保留必要方案、审核／验收证据、未决及恢复材料，只有仍有追溯价值的内容才移入 `.work/archive/`。待审、待恢复和持续业务空间留原位，用途不明先核实。真实论文、Gold、业务数据库、检查点及必要备份的迁移／删除须具体授权。
- 不默认扫描归档。移动材料同步有效引用、不覆盖同名文件；旧报告和回执保留当时事实，复现另核对授权与新恢复位置，不直接执行归档。不为清理另建台账、报告或兼容软链接。
- Gold 仓保留独立使用所需的资料与隐私摘要，引用主仓规则，不另建计划或进度。两仓默认同父目录，其他布局先定位对应版本；修改跨仓入口限获准范围。开发完成后的文档组织由人类确认。

## 共同要求

以下保留不能从当前实现反推的产品约束。具体字段、函数、参数默认值与已实现故障检查由代码、生成合同和测试维护；修改行为时核对这些来源及相关要求，不能因旧关卡已通过而免验。

### 资料与发行

主仓保存程序、运行所需规则／提示／配置／界面资源及获准正式星表；Gold、预留最终评价名单、审定和来源记录在私仓。真实论文、Gold 草稿和逐项评分报告留获准私有工作空间，不进入主仓、公开测试、提取请求或发行包；主仓只记录概括结论。凭据、本机环境、缓存和运行产物不入 Git。

wheel 仅含程序及必要运行资源，正式星表独立下载；README 可作为包元数据，开发文档不是运行依赖。主仓 `.dev/` 只纳入 Plan 与 Progress，Gold 仓忽略 `.dev/`。初始化空白空间不自动导入正式数据；导入须明确请求。完整 Git 克隆可能包含已纳入的正式星表，不能与代码包混淆。

保持一个 Python 应用和共同记录定义；业务模块依赖基础接口，基础模块不导入提取、网页或评分内部实现。页面只展示和调用业务接口，不作科学判断或直接写库。LangGraph 管流程，业务库管结果，不能将框架状态当作另一套科学数据。版本以 `pyproject.toml` 为软件唯一来源，科学规则、记录格式和数据版本分别管理。

### 科学规则与模型输入

- [rules.toml](../src/hvs_catalog/resources/science/rules.toml) 是科学正文、五种作者状态、18 类物理量及合成例子的唯一来源。两版规则仅歧义策略不同；版本、审定状态和旧规则映射是维护信息，不进入提取指令。科学含义修改先说明影响、用易混样例核对并由专家审定，不能仅改状态名称完成旧规则迁移。
- 模型输入由科学正文、[steps.toml](../src/hvs_catalog/resources/prompts/steps.toml) 和共同字段生成格式组装。每步含 S01–S07 摘要及所需解释、定义、例子；名单含作者状态定义，数值含物理量定义。模型和选例可逐步配置，关闭补充提示／例子不能取消科学要求。收尾由程序执行，步骤不存在或参数不适用须在调用前报错。
- 提取指令、字段说明、合成例子、判例及新写的摘要／疑问使用英文；材料、原始名称、数值与证据保持来源表达。专家答复保留原文及一致英文表达。中文规则解释按需临时提供，不维护另一套中文科学正文；首版不增加运行时语言切换或强制中英文实验。
- 模型填写科学内容、证据和明确的完成声明；编号、修订、引用装配与运行信息由程序提供。实际提示只发送本步科学填写内容，不混入材料获取、版本管理、恢复、迁移、判例制作或实验安排。普通正常结果不额外填规则编号和理由；引用判例时保留给定编号及简短适用说明。
- 模型、协议、路由及参数由受限配置定义；凭据与参数分离，不提供任意请求体或从字符串加载代码。记录实际发送／省略的参数及转换依据，服务端未知默认值保持未知；模型补充提示不能改科学规则。更换一步模型不影响其他步骤，不按论文编号预置答案，不自动切换模型、路由或模式。
- 所有本机同账户请求和重试共享限流；连接、流空闲和总超时分别配置。只对可确认的发送前连接失败及 429 作有限重试，鉴权、格式、参数及未知完成不盲目重试。默认输出上限采用路由支持最大值，思考预算按协议解释；参数被接受不证明长输出或科学效果通过。更低实验上限须在方案中明确。
- 规则改动运行 `uv run python tools/render_science_rules.py` 及 `--check`；字段／合同改动运行 `uv run python tools/render_record_contracts.py` 及 `--check`，另验证模板可解析、Schema 与校验一致、字段说明和步骤职责正确。生成检查不能替代内容审定。

### 提取与证据

- 检索时间范围、词、类别、指定论文及运行间隔由人类决定，保存实际条件、查询时间、返回结果与进度；首版不做通用期刊爬取或多服务聚合。arXiv 首次未指定版本时固定当时最新版；每轮分别检查新论文和已收录论文的新版，后者不受首次提交日期限制。分页、限流、异常空页或下载失败保留未完成状态。新版失败保留旧材料与结果，已开始任务不换版本。期刊 PDF 与预印本关系须有依据，不能只凭标题合并。导入须明确身份、版本及出处，同版本不同内容不静默覆盖。
- arXiv 请求统一串行节流，本机同用户跨进程共享；跨机器由操作者协调。既定 arXiv API 间隔至少三秒、单连接；下载采用相同保守间隔，不宣称官方下载配额。遵从服务端冷却，临时错误有限重试、拒绝访问则停止；实施真实服务任务前核对官方规则。网络等待不放入长期数据库事务。
- PDF 准入检查类型、大小、页结构、加密及资源限制；远程原始字节与诊断保留，拒绝的本地文件不导入或改写。可选 LaTeX 只存档、不解包或影响 PDF 成功判定。获取状态只保存一份权威事实，来源与历史可追溯，避免重复状态和回执机制；未知旧格式明确拒绝，不自动迁移。
- 本地 MinerU advanced 解析全部页面，保存 PDF、原始解析产物、图片、页／块映射、工具版本配置与指纹；不额外渲染或附加整页图，不另做OCR或数值修正。模型接收正文、表格、作者图注及原始图片，排除解析器生成的读图描述；不静默丢图或自动切换云端／LaTeX。工具和模型资源由操作者在独立环境准备，缺失明确失败；具体安装与参数查 [适配器](../src/hvs_catalog/materials/mineru.py)，资源不在项目 wheel 或业务备份中。实测平台与限制由 Progress 和代码核对，不宣称完整进程沙箱。
- 文字证据核验固定文件、页／块与原文摘录，图片证据只核验位置、绑定和文件，不认证读图内容。解析文字匹配、页面齐全及 `materials_complete` 均不能证明原 PDF 忠实或科学准确；符号、表格行、误差、单位及对象归属仍须核对原件。支持其他定位不等于交付对应解析器；表格行键歧义不得默认取首行。
- 名单提取由模型理解明确编号范围并逐个提交；程序不从论文展开或猜补成员，只检查已列成员与条目一致。不明确余项保留范围与证据。收录对应论文贡献，排除／待决不伪造贡献；摘要、贡献类型和作者判断的证据分别可查。不同条件不投票合成作者总体结论；外部别名不写回本篇原始名称。
- 原数值字符串、误差／区间形式、单位、条件、来源和每个数字组件证据读写不变；保留数值与证据关联，自动校验引用归属、位置与解析文字摘录，不要求数字字符串逐字包含于摘录中，不认证数字支持性或读图正确性，不换算或补零、中心值、总误差及统计解释。已报告的单侧误差、零、负数及多值须可保存；无结果不创建空测量。冲突保存双方完整结构与理由，不作两条已确认测量；不同来源或条件的值分别保留，重复呈现同一结果不增加记录。
- 数值按单对象平铺测量提交，程序绑定固定对象、按明确物理量归组并装配组件证据，不要求模型填写重复的对象或分组结构。只保存合法的完整测量，不能删除无效误差来保留不完整测量；失败不覆盖其他已保存的有效结果。
- 每个对象显式保存 18 类量的检查情况，可由共同声明和逐项例外展开；省略不能当已检查。材料检查完成、科学问题和运行状态分别保存。只有相关材料查完、无影响该量的缺口／未决且无报告值时才显示“未报告”，不编造引句。缺口影响未知不能默认其余结果完整。
- 名单和数值提交用位置编号与摘录，技术引用由程序装配。JSON 可解析后只开放指定修复项，未开放字段保持原值；已列却漏交的成员只能按指定项追加，不推演新对象。每个提交单元最多两次补正，保存所有请求、响应与修改历史；技术修复不改科学规则或冒充科学评价。

### 运行与裁决

- 用不可变修订和准确引用保存科学记录，拒绝未知格式、遗漏必填、越界路径与错误论文／对象绑定。派生索引不另维护科学结果；不遍历历史把引用换成“最新”。日常提交校验本批及引用闭包和当前输出对应，备份／空间恢复全量核验；共用同一校验规则。
- 固定来源、规则、代码／依赖、模型参数、配置、已有决定、例子和判例，以及逐次实际发送的请求响应。相同请求与输入重试复用，改变输入或有意重跑建立新执行；输出身份、决定与回执按执行隔离，首版不跨执行复用步骤缓存。恢复使用原归档，缺失／损坏或代码依赖不兼容须拒绝，不用新版补旧输入。
- 同空间全部写入、执行和备份共用排他锁，取不到返回忙；暂停释放资源，其他论文和空间可继续。记录、修订、绑定及操作回执在业务事务内一并保存，同键异内容和旧预期修订拒绝。稳定锁文件不能在运行中删除／替换；平台支持据实验证，不把本机锁宣称为跨机器保证。
- 不同论文的名单与不同对象的数值请求共用并发调度，一篇名单完成即可处理其对象，不等待全部论文名单；单对象的初次提交与补正仍按顺序执行。工作线程执行网络调用，协调者统一归档、校验和写业务库；并发受固定配置与共享账户限流约束，一项失败不取消其他独立合法结果的保存。
- 文件可靠发布后才能被记录引用，不覆盖已有不同内容或接管未知非空目录。路径限制在声明根内，备份恢复拒绝逐段符号链接及越界。凭据只保存读取引用，不进入配置快照、响应归档或错误正文；未知现场不自动清理。
- 专家辅助先保存有效结果、问题和影响范围，结束调用，日后集中答复后再恢复依赖部分，不保持连接或反复请求等人。答复仍无法确定时保留未决，收录／身份未定不当作已确认或排除；专家也应能检查未被模型主动提问的草稿及原 PDF。全自动自行解释并记录模型判断，不创建专家待办、不因解释歧义等待或放弃；真实材料缺口和原文冲突仍保留。策略开关不取消 Gold、整批保存和发布授权。
- 问题与决定绑定准确材料、规则、记录、执行和步骤；模型判断不冒充专家决定。先可靠保存决定及回执，再核对检查点和适用性、应用有类型的完整结果修订，最后恢复流程。相同决定只生效一次，冲突、过期、串执行或错误引用拒绝；恢复失败不撤销已保存决定，不把旧补丁移植到新目标。
- 框架进度落后于已提交业务事实时按回执继续；无法解释的不一致停止并保留诊断。完成须同时确认业务结果完整和匹配流程终态，保存最终检查点标识；不靠“无待执行节点”单独认定完成，不自动补造凭据或修复任意内部损坏。
- 调用发送前保存 pending，完整响应先落盘再确认成功；未知完成保留 `completion_unknown`，恢复不自动重发。外部服务与本地保存不在同一事务，不能保证外部请求恰好一次。产品记录全部尝试的调用数与已知 tokens，未知为 `null`；不计算货币费用或价格表，历史有值字段可读，退役账本不自动迁移。实验预算单独管理。
- 持空间锁备份稳定的业务库、检查点、全部历史引用材料与运行文件、操作回执和必要配置，排除凭据、临时项和其他备份。不能直接复制活动数据库；完整性、原哈希、业务／检查点绑定全部通过才发布完整备份。恢复只到新目录，拒绝覆盖，须在新进程验证接续；可解释的待应用／待恢复阶段保留，空间外服务调用记录不由客户端备份回滚。

### Gold 维护与就绪

- Gold 使用独立 PDF 标注外层，复用科学词表与数值校验，不给人工标注伪造执行信息。字段、格式版本、迁移差异、保存参数与人工恢复由 [生成合同](../contracts/generated/gold/README.md) 及 [evaluation](../src/hvs_catalog/evaluation) 维护；旧 v4 和迁移草稿只读支持，不静默升级不支持版本或丢弃未知科学内容。
- 新标注、迁移与局部修正共用工作副本 → 科学审定和具体保存批准 → 检查保存 → 另获准 Git 的路径。已有明确人类决定可作依据，无需重复审定同一问题；保存仍须绑定完整答案、元数据、规则、材料、目标与预期旧内容，不凭审阅者名字或通用批准标记放行。
- 每篇固定 `answer.json`／`metadata.json` 配对，历史交 Git，不建逐版目录或第二套日志重放平台。写入失败保留完整旧／新配对或充分备份，半份内容不得被读作获准答案；同内容重试核对当前结果，不重复建版本或覆盖较新修改。工具不执行 Git，未提交副本不能声称已有历史。
- 保留原标注者、真实审阅身份、日期精度、来源及科学未决，不补姓名、历史模型或批准。旧 PDF 位置与可选引文保留，不猜页序号；检查所有嵌套证据、原文件哈希和位置，文字匹配不证明语义。迁移缺口和旧新映射留报告，不虚构数字、引文、对象或完成声明；旧作者状态改变须回查原文审定。
- 原审定仅适用于绑定的规则和材料。机械元数据迁移不改答案、原审定身份时间及含义；真实迁移／修订另需范围授权，旧输入只读、未知目标不接管。原报冲突可以形成审定答案，科学未决按批准范围保留；部分范围没有贡献不等于整篇为空。
- 正式评分前核对当前规则适用性、科学审定、对象与条件、PDF 版本／附表范围、文件指纹及完整性。评价范围在看预测前以原文身份、物理量和条件固定；解析遗漏、失真、无源码不构成额外排除。答案、Gold 准备缺口、提取未决和评分器无法判定分别记录，不临时删除难例。
- 评分快照固定私仓 commit、答案／元数据路径与指纹、规则及材料；当前答案修正不改变历史实验。纯内存适配不读取真实仓、不改 Gold，缺条件不能猜成“未报告条件”。只有完整配对及有效就绪绑定可正式评分；answer-only、草稿及未处理准备缺口不算就绪。
- 已裁定覆盖缺口可由内容绑定的具体人类决定限定封闭评分范围，不改 Gold 原部分覆盖；缺来源、证据、条件、未确定作者状态或未结构化冲突仍须修复。材料或答案改变后重新核对，无法确认预测是否属于范围外时保留计数并标暂定，不现场豁免保存检查。

### 评价与实验

真实提取实验以已审定 Gold 和核对过的评分器为基础；每次先固定材料、代码／依赖、规则、实际英文提示、步骤选例／判例、各步模型参数、轮次、并发、重试、指标、预算、停止和通过条件并获准。总体 API 实验预算参考 1000 RMB，单次预计可能超过 100 RMB 先提醒并等待确认；估算包含重试、核实路由报价，未知用量／费用不填零。小范围不自动扩大为 Full50 或更多组合。

开发论文不能因换载体或解析器变成独立测试集。R08 的预留名单在私仓隔离，开发不使用或提前复制论文材料；R28 再按授权获取固定 PDF 并标注。标注依据原 PDF，不看历史提取或待测预测；若根据最终结果继续调参，应标为已参与开发并重新安排验证。结论只覆盖实际样本与配置。

#### 分层评分与比较

只报告一套 L0／L1／L2，不合成总分。失败、空预测和部分结果计入预定范围；后续失败不抹掉已验证名单，解析问题按端到端错误计入。

| 层级 | 要求 |
|---|---|
| L0 交付 | 分别报告交付／计划、格式合格／交付、格式合格／计划，区分完整、部分、失败、未完成和待决。 |
| L1 对象 | 按本篇原文标识、明确别名及受限排版一对一匹配，报告 TP／FP／FN、精确率 TP/(TP+FP)、召回率 TP/(TP+FN)、F1=2TP/(2TP+FP+FN)。不按内部编号、顺序、坐标或联网补全纠错。 |
| L2 完整数值 | 对象、物理量及科学归属对应后，一对一比较原值、误差／区间、单位、统计解释、条件与来源；完整正确数 C、可评价预测数 P、应交付 Gold 数 G，精确率 C/P、召回率 C/G、F1=2C/(P+G)。组件错误不能抵消。 |

分母为零标不适用，有 Gold 无预测时召回率和 F1 为零；完整空名单另报。遗漏对象的量仍计入 G，多报对象的量在完整范围内计入 P，不以双方空栏加分。不跨条件、来源、历元或表示方式配对，不用 Embedding 匹配条件、误差容差或坐标转换。贡献类型、作者判断、证据支持关系及组件错误另列诊断，不以引文相似度证明正确。

只允许无害排版等价，不改写原记录或 Gold，不换算单位尺度、坐标格式、线性／对数、距离模数或概率，也不补误差或推导物理量。保留精度、尾零、误差形式、端点包含关系和置信／可信等统计意义；条件同义须有上下文依据，不能因数值相同接受。已审定的正反例与手算预期保留在 [固定评分样例](../tests/fixtures/scoring)、[排版比较测试](../tests/test_scoring_printed_comparison.py) 和 [数值比较测试](../tests/test_scoring_regression_value_comparison.py)，不能从本轮预测改写预期。

#### 辅助模型与报告

辅助评分模型只判断有依据的排版／条件等价、不等价或无法判定，不改值或输出总分，不能推翻程序已确认的科学差异。程序核对允许关系和一对一约束并计分；无法判定与技术失败分别保留，影响得分时整批报告暂定，不出单一最终分数或删分母。

启用前固定有人工预期的合成或获准开发样例、规模、复测次数和配置，覆盖等价、近似不等、符号／指数、单位尺度、误差侧别／分量、上下限、模型名／版本／否定条件、无对应、模糊对应和未知宏；每次预定复测均须 100% 通过，预期明确却无法判定算未通过。模拟仅验证协议，不能代替真实模型能力验证；通过不证明对未知输入永不出错。

正式评分固定程序、辅助模型和全部输入输出、依据及判定，不按待测方法偏向某组；重算复用固定判定。Gold 与逐项评分反馈不进入提取或同轮修正。人类负责评分前审定和评分后结论审核，不现场逐项改分；新通用比较规则须专家审阅、明确适用范围、补正反例，再按新版本重评全部受影响结果，不挑有利个案。

逐论文、逐量报告质量与完整性、名单遗漏、证据支持、自动完成、应裁决问题的发现、未决、裁决次数、专家时间、失败和重复稳定性。专家时间包含解析核对与未主动上报错误的修正；区分解析、名单、数值／证据、科学解释及原文冲突。保留所有失败轮次，明确重评、假设分析与新真实运行的区别，未知用量／用时为 null，不将货币或工时混入质量分。输入变化重验受影响部分，纯说明调整不重跑付费实验。

#### 专家裁决对照

全自动和专家辅助按相同 PDF／解析输出逐篇配对，固定共同规则、格式、例子、模型与评分，初始提示仅歧义策略不同。两组各自从头使用对应策略，独立保存结果；不能把专家组未决输出当自动基线，自动组不能用本轮专家决定或人工补值完成，专家裁决不查看 Gold／评分反馈，也不作为同轮参考答案。

两组使用同一既有判例快照（可为空），本轮新决定及判例不加入任一组当前输入；判例作用另行比较，说明与评价论文的独立性。专家介入的后续调用是被评价的干预，完整记录。运行图结束与科学完成分开，自动组已完整保留的原文冲突不一律视作待专家处理；分别报告质量、覆盖、完成、用量和专家负担，单组失败仍保留两组报告。

## R17

**首轮科学质量评价与问题复查**

**目标与交付：** 对PDF主流程开展小范围正式质量评价，报告名单与数值的正确性、完整性、证据对应、失败原因、多次运行稳定性及人工核对负担，不再要求两种名单方法比较。

**执行与开始条件：** 主 Agent 设计并执行实验、分析结果和修复并验证已明确的工程问题，人类专家验收科学结论。开始前需完成 R07、R09–R16，并取得本次实验授权。

**关键要求：** 按 [实验安排](#评价与实验) 固定并批准本轮方案，固定PDF、解析结果与工具版本、共同规则及所选歧义策略、提取提示和模型配置；后续扩大样本或比较模型、推理强度、解析器版本时，一次只改变已声明的条件，不增加长期并行流程。输出上限沿用服务商最大值；另设更低上限时须在本次实验方案中明确其目的和影响，不由实验脚本隐含覆盖。先复查已知失败情况，保留全部轮次和调用用量；分别归因于PDF解析、名单遗漏、数值提取、证据／字段填写及模型科学解释。正式评分前重新核对现有Gold与所选PDF的版本及范围，完成 [Gold核对](#gold-维护与就绪) 和实际 [辅助评分模型验证](#辅助模型与报告)，不能沿用旧源码材料绑定或R09模拟结果证明新输入就绪。全自动结果须由对应策略完整运行得到，不能用专家辅助流程的未决输出替代；独立最终对照在R28固定方案、R29执行。

**验收标准：** 按 [评价设计](#评价与实验) 报告各项指标、复验及结论范围，逐项对照通过条件。

## R18

**稳定对象身份与合并拆分**

**目标与交付：** 交付跨论文对象关联、稳定身份以及合并、拆分和更正能力，保留依据与原有论文贡献。

**执行与开始条件：** 开始前需完成 R03、R04、R05、R17。对象关联规则及科学分歧由主 Agent 分析、人类专家审定。

**关键要求：** 由确定性程序使用已确认的标识和原文对应关系关联；不确定时保留候选关系，通过 R05 保存待办交专家。论文原始贡献和证据分别保留，不能因关联重写。

**验收标准：** 同目录同版本标识一致或论文明确给出对应关系，且无相反证据时，能按规则关联并保存依据；仅有跨版本同号、坐标接近、名称相似或含糊别名时，不会自动关联，标识一致但有相反证据时转交专家。同名不同对象保持区分，改名不改变稳定 ID；合并拆分后贡献不丢失、不重复，旧链接和引用仍可解释。根据保存记录重建得到一致结果，未决关联可回查。

**合成例子 E21（关联阶段）：** 两篇论文的对象坐标接近，但只有不同目录版本中的相同数字编号，原文未建立对应关系。

**预期：** 记录这两条记录可能指向同一个对象，交专家判断。不能仅因坐标接近、不同目录版本中的编号相同，就自动将两条记录归到同一个对象。此例为虚构材料，不是真实论文、Gold 或正式专家判例。

## R19

**来源明确的外部资料补全**

**目标与交付：** 从审定的外部来源补充允许使用的观测、标识和质量信息，保留匹配及来源依据。

**执行与开始条件：** 开始前需完成 R03、R18，并取得具体服务调用授权；科学字段与匹配解释由人类专家审定。

**关键要求：** 论文提取后由确定性程序通过 Astroquery 查询 SIMBAD 的标识、别名和文献链接，以及 Gaia Archive 的位置、视差、自行、径向速度、误差和质量信息；具体目录版本、字段映射和查询范围在开工前审定。保留查询条件、时间、原始响应、条目、可取得的目录版本及匹配依据，不覆盖论文值；计算与参数选择遵循 [科学边界](#产品目标与科学边界)。

**验收标准：** 离线验证多匹配、无匹配、来源版本变化和服务故障；确认补全仅在论文提取后执行，匹配确定后外部记录与论文记录并列保存，原始提取内容不被改写。在批准范围内核对少量真实条目的字段、单位与出处。调用失败不表示数据库没有该对象，匹配不确定时保留待决状态。

## R20

**本地PDF审核、裁决与恢复**

**目标与交付：** 将R05的共同接口接入本地网页和命令行，让专家对照原PDF查看名单、数值和疑问，发现遗漏、修正错误、保存决定并恢复任务。

**执行与开始条件：** 主 Agent 设计操作流程及允许保存的内容，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R02、R05、R16、R18、R19。

**关键要求：** 两种入口共用 [裁决功能](#资料与发行)，遵循 [保存与恢复规则](#运行与裁决) 和 [本地用户流程](#产品目标与科学边界)，按运行固定的裁决配置处理请求；页面操作不自动公开数据。

审核范围包含未被模型主动提问的草稿结果，能从结果定位到固定PDF页及证据区域，区分原PDF、解析文本和模型解释。沿用共同修订机制，不另建一套审批系统；R15／R16仅需提供可回查证据的基本入口，本关再完成交互。

**验收标准：** 真实浏览器验证待办与证据展示、刷新、关闭和重启，并核对裁决服务默认仅允许本机访问。重复决定只生效一次，过期证据或规则对应的提交被拒绝，裁决后从正确步骤继续；网页和命令行行为一致，不同工作空间互不影响。关闭专家裁决的对照运行不能接收本轮专家决定，改变裁决配置须建立新执行。

用合成材料验证专家可从普通草稿发现未上报的漏项或错值，定位原PDF并保存有依据的修正；解析输出与PDF不一致时，界面不能把解析文本展示为已核验原文。

## R21

**裁决案例积累、复用与汇总**

**目标与交付：** 交付裁决案例的模型起草、专家审核、保存、查找、按条件复用和问题汇总，记录专家投入的时间。

**执行与开始条件：** 主 Agent 设计复用规则，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R20。

**关键要求：** 判例只解释主规则，不改变主规则；检查并审定英文理由、适用条件与边界，保留材料、证据和原决定。按关联规则／问题筛选少量案例，超长时减少所选数量，不截去关键条件。科学疑问触发按需查找，明确的问题直接处理；实现前由主 Agent 明确筛选方式、数量与总长度上限以及无结果和查找失败的处理，交人类专家验收。产品不自行调用开发 Agent 修改代码或启动实验。

**验收标准：** 个案决定保存后可恢复原任务，判例起草失败、待审或未获通过不阻塞该恢复；草稿保留原裁决关联，审核前不能复用。与主规则冲突或一致性未确定的案例不能进入可复用判例库。明确符合条件的案例可复用，条件变化后重新检查；作者倾向或判例适用性仍有歧义时，专家辅助版提交专家，全自动版按固定策略自行解释并继续。复用引用原批准，不生成一次虚假的新批准。直接依据规则的结果无需额外判断说明，参考判例的结果能由简短说明回查原案例。新增案例不改变当前评测，重复问题、待办和专家用时能够导出查看。验证不发送整个判例库、数量和总长度限制生效、所选判例保留完整适用条件、无相关判例时仍按所选策略处理；技术查找失败不能变成科学排除。保存查找及实际提供的英文判例和版本，重启后复用固定内容。

## R22

**正式星表候选与数据导出**

**目标与交付：** 从工作结果生成版本明确、来源可查的星表候选和下载表格，支持新增论文与修订；交付原报记录与机器可读派生值分层、批量格式清理及困难表达的审核入口。

**执行与开始条件：** 主 Agent 明确入库条件和导出内容，经人类专家审定后实现与自检，交人类专家验收。开始前需完成 R18–R21。

**关键要求：** 按审定的入库／导出规则与[科学边界](#产品目标与科学边界)准备候选。原报记录与派生值分开，派生值引用原修订和转换规则版本；清理数值、误差、端点和单位排版，保留精度、形式、条件，不换单位尺度或作物理／统计推导。评分与导出可复用基础解析规则，生成派生值须独立验证。优先程序处理，Agent 对困难表达的提案经专家审核后使用；可推广解释补齐适用范围与回归样例，完成工程验证并经人类专家验收后纳入程序，不覆盖原报记录。不同来源测量不能合成推荐值，正式保存须批准准确内容。

**验收标准：** 相同固定输入（含获准的 Agent 解释）产生相同候选及哈希，贡献和引用不丢失、不重复；关键证据损坏或身份修改未决的记录不能进入候选。覆盖数值、误差、端点与单位的排版清理、拒绝科学换算、未知宏、Agent 失败/歧义、审核拒绝及规则升级；实际清理模型须通过获准能力验证，评分模型验证不能替代。未确认派生值不宣称可机读。用合成星表验证多轮新增、重叠检索、重复处理与修订，既有未受影响的记录保持不变，修改摘要准确；修订前后内容、原始依据、转换版本和审核决定可回查。

同一arXiv论文的v1、v2按修订处理，不能作为独立论文重复入库；期刊PDF与预印本的关系须明确登记，不能仅因标题相同就合并，也不能把同一论文的不同载体重复计为贡献。新版结果经专家确认后纳入正式星表，旧版仍可回查。新版处理失败或尚待确认时，已保存的旧版结果不被覆盖。

## R23

**静态星表网站与独立下载**

**目标与交付：** 生成可浏览、搜索并查看来源和修订的静态星表网站，提供程序与数据的独立下载入口。

**执行与开始条件：** 主 Agent 实施并验证技术与内容一致性，人类专家验收呈现及结果。开始前需完成 R22。

**关键要求：** 页面、表格和下载采用同一固定数据版本。保留多来源测量及版本导航，社区建议通过 GitHub issue/PR 提交；本关仅准备本地或获准私有预览。

**验收标准：** 在桌面与窄屏真实浏览器中检查搜索、导航、来源和下载。内容与版本一致，不误呈现唯一推荐参数；程序可独立安装，预览不会自动公开网站。

## R24

**项目与数据指南**

**目标与交付：** 为新用户制作便于专家审阅的指南，解释项目如何用 AI 从文献提取数据、设计原则如何影响结果，以及如何浏览、理解和使用最终星表。指南作为 R23 星表网站的一部分交付，链接来源记录、字段说明和下载入口；审阅与发布语言遵循 [语言设计](#科学规则与模型输入)。

**执行与开始条件：** 主 Agent 设计、制作并核对技术与科学解释，人类专家验收可理解性和使用指引。开始前需完成 R23；本关在 R23 后、R25 前执行。

**关键要求：** 制作前与人类专家确定内容提纲，以及对自行安装和处理文献的讲解深度。根据已实现并验证的流程，使用合成或获准公开的例子，说明 AI、自动检查与专家裁决的作用，以及多来源测量、原文证据、版本和使用限制。指南按新用户过程组织一份源文件供网站构建，引用科学规则、生成字段和必要依据，不另复制规格或手改生成页面；路径结合实际网站确定。演示无需真实模型调用，不使用私有 Gold 或最终评价预留材料；尚未完成的功能和评价明确标注。

**验收标准：** 人类专家能沿例子说明一条数据怎样从原文进入星表，找到测量的来源、条件与版本，并完成浏览和下载。桌面与窄屏真实浏览器离线检查讲解、导航和实际采用的交互；字段、链接和示例与对应版本一致。指南纳入网站构建与后续发布检查，开发阶段交付本地或获准私有预览，最终内容在 R30 核对。

## R25

**整批确认与可恢复发布机制**

**目标与交付：** 交付整批确认与可恢复发布功能，按批准范围更新仓库、网站和下载，并记录各渠道结果。

**执行与开始条件：** 主 Agent 设计确认、事务和恢复流程，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R22、R23 和 R24。

**关键要求：** 批准对应准确候选内容和目标，数据提交只包含获准文件。重试前核对已完成部分；内容或目标变化重新确认。默认私有，远程冲突不强推覆盖，真实公开另行授权。

**验收标准：** 用模拟远程与发布服务验证内容变化、重复操作、推送失败、远程变化和部分渠道失败。重启后能继续，不重复创建版本或夹带其他文件；标记成功有实际结果依据。

## R26

**完整流程与专家工作量实验**

**目标与交付：** 用一小批获准开发材料运行完整流程，交付科学质量、专家工作量及可审阅的星表和发布候选。

**执行与开始条件：** 主 Agent 设计实验、执行和分析，并修复并验证明确的工程问题，人类专家验收结论。开始前需完成 R17–R25，并取得本次实验授权。

**关键要求：** 按 [实验安排](#评价与实验) 固定本轮方案及故障场景，验证PDF获取／导入、解析、名单与数值提取、对象关联、补全、审核和候选生成；同时记录解析核对、遗漏修正和科学裁决的专家时间，不能只统计模型主动提交的疑问。

**验收标准：** 达到预定质量条件，专家能按事前确定的审核范围检查结果及原PDF，发现未主动上报的错误和遗漏；不增加普通正常记录逐项批准的固定要求。一篇等待裁决时其他论文可继续，重启后正确恢复；已有星表新增、修订后只改变应变内容，原有依据可查，修改摘要准确。失败、部分结果、专家时间和调用用量完整报告。

## R27

**最终安装验证、安装包内容与自动检查**

**目标与交付：** 交付最终独立安装验证和持续自动检查，确认代码包、必要资源及文件发行范围正确。

**执行与开始条件：** 开始前需完成 R26。

**关键要求：** 按 [内容归属](#资料与发行) 检查安装包，逐项核对规则、提示、模型配置和页面资源均已包含。持续集成按 [验证要求](#验证要求) 执行离线检查，核对版本、生成说明与来源、文档链接及计划与进度的关卡对应。

明确PDF解析器及其模型资源的安装、版本和运行要求，验证实际支持的平台；缺依赖时准确报告，不静默下载或切换解析器。离线工程检查与获准的真实解析验证分别报告，不再要求安装退役的LaTeX工具链。

**验收标准：** 在无旧仓、专用路径、Gold、密钥或网络的全新环境中，从仓库外安装构建产物，完成初始化、指定快照导入、离线示例、网页及独立子进程操作。测试隔离实际生效，支持平台和安装说明有实测依据。

## R28

**最终评价 Gold 标注、裁定与版本固定**

**目标与交付：** 为 R08 预留名单中的论文获取并固定评价材料，完成 Gold 标注、专家裁定及获准保存，固定最终评价答案和方案。

**执行与开始条件：** 主 Agent 制定协议、标注和复核，人类专家验收协议并裁定草稿。开始前需完成 R06、R08、R27，固定待测代码及案例的版本，并取得材料获取与私库操作授权。

**关键要求：** 按 [评价材料要求](#评价与实验) 固定论文PDF版本、附表范围及文件指纹；Gold与提取使用同一PDF，记录解析输出、页面对应及工具版本，解析遗漏计入流程问题。标注前固定待测代码、模型、提示、规则、依赖和案例，包括实际发送的英文文本、步骤选例和判例查找配置。使用独立标注上下文，标注者依据原PDF，不看历史提取或待测预测；用已适配PDF绑定的R06工具检查新草稿，具体内容获准后保存。

**验收标准：** 材料未用于开发，来源、证据、科学审定与保存结果可核对，答案留在私有空间。未决条目处理规则明确，不为提高分数排除难例；R29的轮次、模型组合及通过条件在本关固定，并完成 [正式评分前的Gold核对](#gold-维护与就绪)，固定经过验证的程序与辅助评分模型、规则和配置。按 [专家裁决对照设计](#专家裁决对照) 固定专家辅助与全自动两组，核对共同规则、例子和初始提示仅在策略段不同；固定判例条件、配对方式及专家可操作范围，说明答案与裁决的隔离方式。

## R29

**对固定版本进行独立最终评价**

**目标与交付：** 对固定版本开展独立最终评价，比较全自动与专家辅助提取，交付分项质量、失败情况、调用用量和专家时间，并说明结论适用范围。

**执行与开始条件：** 主 Agent 执行与分析，人类专家验收科学结论。开始前需完成 R28，并取得明确的实验授权。

**关键要求：** 严格使用R28固定的材料、答案和运行方案，两组从开始分别使用对应策略并独立保存结果；全自动组不得靠本轮专家决定补齐提取，专家组的后续裁决输入如实记录。若根据结果继续调参，注明材料已参与开发，并重新安排受影响验证。

分别报告解析错误、名单遗漏、数值及证据错误、模型解释错误、原文冲突、专家未决和人工修正，包含模型未主动上报的问题；不以解析器输出成功或部分入库代替科学完成，也不要求恢复已取消的名单方法比较。

**验收标准：** 实际运行与预定方案一致，失败和部分结果按规定计入分母；逐项对照科学与工程通过条件，未满足项明确阻止通过。逐篇配对报告专家裁决带来的质量、完成程度和专家工作量变化，核对两组结果及新增判例没有串用。科学结论经专家验收，不能超出小样本和实际测试范围。
