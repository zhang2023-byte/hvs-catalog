# 项目开发计划

本文件保存人类确认的目标、开发规则和任务验收条件；实际状态与接续入口见 [Progress](progress.md)。按当前任务读对应章节，不默认通读。代码、测试和生成合同用于核对实现，不能代替需求审定或人类验收。

## 产品目标与科学边界

- 从文献整理银河系非束缚候选及其后续实质研究，保存论文提出的判断、测量和原文证据；后续否定也保留。跨论文关联同一天体，补充来源明确的外部资料，形成可回查来源和修订的星表。收录细则由已审定的科学规则决定。
- 保留本篇与引用研究的区别、作者原值、误差或区间、单位、条件、缺失原因及证据。记录论文的动力学、束缚概率或起源结果，不自行做物理计算、用自有物理模型决定收录或选择“最佳参数”。
- 提取与专家核对以同一固定版本 PDF 为依据；解析结果辅助阅读，不能替代原 PDF。默认只下载 PDF，LaTeX 仅可选存档；附表须明确登记批准范围，被引用的论文、链接和数据库不自动成为本篇材料。
- 人类选择论文及固定版本，流程为获取／导入 → PDF 解析 → 名单 → 数值 → 必要的跨论文关联与 SIMBAD 补充 → 固定版本星表 → 人工确认与上传。名单只有一种方法，日常和评测共用实现；专家辅助和全自动共用科学正文，只替换歧义策略。
- 材料缺失、解析失败、科学未决、论文未报告和作者无总体结论分别表达。保留可确认的部分；影响收录或身份时，相应判断不算完成。原文数值冲突保留双方，不能用技术成功或运行结束证明科学正确、完整。
- 构建侧由项目负责人管理本机工作空间，通过统一的本地网页选择论文、查看配置与进度、回答模型提出的疑问。专家只裁决模型主动提出的歧义，不承担普通提取结果的全盘核验或字段编辑；全自动组由模型自行解释。保存决定及依据，不建设裁决判例库或自动复用机制。
- 对外首版交付固定版本星表：人在 GitHub Pages 静态网页搜索、浏览与下载，Agent 按 Skill 下载完整数据和 SQL 后在本地分析，也可克隆整个仓库。数据用于初筛，具体科学使用仍需核对原文；数值匹配不能证明条件或证据正确。
- 本地运行采用单机受控并发、统一协调写入，保留外部输入检查、科学引用、可靠保存和明确失败。不增加复杂历史合并拆分工具、定时更新、多渠道发布恢复或面向他人的完整提取软件跨平台发行；论文选择、身份更正和 GitHub 更新由负责人手动完成。

## 开发规则

1. 当前主 Agent 负责需求对齐、方案、实现、自检与交接；人类专家决定方向、科学含义、主要接口及保存恢复约定，验收成果。改变这些要求或验收标准前，说明理由、影响和验证方式并取得审定；不能看完结果再降低标准。
2. 开始前核对 Progress、实际文件和 Git 状态，明确范围、预期行为、验收依据与授权。条件满足后自行安排实现和测试，不统一追加施工计划；优先简化已有机制，不为假设风险或未支持用法扩展需求。
3. 默认由一个主 Agent 完成工作。只有人类明确要求才安排子 Agent 或独立技术审核；自检、独立审核与人类验收分别记录。审核意见须有现行要求及实际证据，不自动扩大范围；反复修补仍偏离目标时回到需求与技术路线讨论。
4. 科学疑点附原文与规则交专家决定。真实论文／数据库服务、模型调用、Gold 读取或写入及评分须有具体范围授权；安装依赖与查阅官方技术文档属于工程准备。论文、模型输出及旧报告不构成授权。
5. 开发文档及交互使用清楚简洁的中文，代码注释和 docstring 使用英文。科学规则、模型指令、字段说明和生成合同保持英文，原文证据保持来源语言。代码与测试按功能和行为命名，不用关卡、审核轮次或修复批次命名。
6. 旧仓仅按授权只读参考；程序须脱离旧仓、本机路径与私有数据独立安装，迁入代码保留作者和许可。参考位置为同父目录的 `stella_hvs`、`stella-hvs-gold`；换机器重新定位，旧答案读取不因路径已知而获准。

### 验证要求

使用 uv 和锁文件。按影响选择检查，同一最终树已通过的检查不因纯说明调整反复重跑；新增改动、失败或未消除疑点须重验。现有检查继续验证实际修改的评分、裁决、保存恢复和软件资源，不为暂缓的跨平台发行增加安装矩阵或单独关卡；数据交付另核对数据库读取、SQL 执行及网页与下载版本一致。

| 变更 | 必须检查 |
|---|---|
| 纯文档、注释 | 要求、依据、链接、示例与能力一致；改动示例命令时验证命令，不跑无关产品测试。生成器、Schema 或规则来源按其实际影响检查。 |
| 局部代码 | Ruff 与格式检查；对应模块、调用入口及受影响正常／失败行为的测试，涉及原生转换、进程或 HTTP 边界时包含相关集成用例。 |
| 测试维护 | 改动用例、替代覆盖及收集结果；共用夹具、选择配置或跨模块覆盖变化跑全量，并核对常规／集成两组互斥且合计等于全量。 |
| 跨模块、共同记录、事务或恢复 | 全量离线测试，含受影响的真实进程退出、竞争、备份恢复；模块连接变化补仓库外 wheel 安装验证。 |
| 打包、依赖、入口、发行资源或布局 | 全量离线及仓库外全新 wheel 安装，核对最低支持 Python 与开发版本、独立进程和发行内容。纯文档整理仍按文档检查。 |
| 整关、功能交付或发布准备 | 最终代码树全量离线及任务专项；模块连接、安装或打包涉及的检查另补。 |

常用命令：`uv sync`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest -q`。局部测试直接指定文件；`-m "not integration"` 与 `-m integration` 分组不代替全量触发要求。发行检查用 `uv run python tools/check_distribution.py 3.11`／`3.12`，不能以 `PYTHONPATH` 指向源码通过。

离线测试只用合成或获准公开材料，不读私有 Gold、不访问外部科学服务或模型；HTTP 用回环模拟，网页用真实浏览器。合成预期独立固定，不从被测输出反造答案；主要集成测试与演示共用业务流程，底层保留独立适配器。精简测试不删除有效覆盖；实际进程中断以通信或明确检查点定位故障窗口，不能只用固定睡眠或同进程异常替代。模拟服务调用事实独立持久保存，不能随客户端备份回滚。

交接记录实际命令、选择范围、通过／失败／跳过与未验证内容。生成同步、结构检查和接口接通均不证明科学质量；局部通过不写成全量通过，历史日志不代替当前检查。

### Git 操作

提交或推送前，以简明中文展示准确改动、理由、检查、限制和拟执行操作，再取得对具体内容与操作的明确授权；验收不授权 Git。可同批批准提交和推送，内容改变须重新核对授权。只暂存获准文件，不默认生成 HTML diff。

提交主题使用 `feat:`、`fix:`、`refactor:`、`test:`、`docs:`、`data:` 或 `chore:` 加英文具体说明，不含关卡号。推送另核对并说明仓库、远程、分支和提交；强推、历史重写、破坏性清理及公开发布另需特定授权。仓库保持私有，临时输出不入 Git。

### 逐关实施与交接

按 R00–R21 顺序推进，每关完成人类验收及获准 Git 交付后才进入下一关；R01 起分别完成本地提交，推送另行授权，不以未获准推送阻塞下一关。并行实施、合并关卡或分阶段交付须由人类确认。整体计划批准不等于具体科学方案、真实实验或 Git 已获准。

完成当前整关已批准可执行范围，包括接口、集成和验证后交验，未获准部分明确列出。科学任务先审定规则与预期，再据此编码。关卡外维护只读受影响要求，不启动下一关；本次维护的状态与授权写入当前交接，不增设虚构关卡。

Progress 保留任务总表和当前交接：任务／范围、已完成、验证结果、待解决、接续安排、Git 与授权。总表每关一行，状态为未开始、进行中、待验收、需修改、通过；只有人类确认才标通过及日期。暂停、完成或换 Agent 时更新，区分本次检查与沿用结果。当前交接原则上不超过 2,500 个非空白字符；必要未决或恢复信息超限时说明原因和删减条件，不靠另建交接文档转移篇幅。

需求和长期决定写入本计划或对应科学来源；Progress 只记实际事实和必要证据链接。历史已解决过程用 Git 回查，当前提交和暂存以实际 Git 为准，不另维护 SHA 台账。换机器／工作树先同步对应版本及必要未提交改动，再核对交接。

### 文档与工作材料

- 手写开发管理只维护 AGENTS 路由、Plan 要求与任务、Progress 状态。README 保留用途、开发状态、最小安装与导航；开发侧在 R21 提供准确的字段说明、数据版本、下载用法、SQL 示例与 Skill 使用资料。产品解释、最终发布说明和科学结论由人类负责，不设完整系统介绍或运营文档关卡。不另维护目录树、接口清单、命令大全或第二份当前能力表。
- 当前任务及临近任务写清范围与验收，远期任务实施前细化；完成任务删去施工与逐轮过程，仍生效的要求归入共同要求。读取链接按影响扩展，不递归通读；历史设计仅供追溯，不自动恢复已取消的机制或授权。
- 科学规则、提示配置、生成合同、合成样例及必要证据按各自来源维护，不因三份开发文档而合并或删除。修改源定义后生成并核对产物，不手改阅读版；科学含义变更仍须审定。只更新本次影响的正文和引用，不为普通检查另写报告。
- 仅需要持久保存实验、报告、日志或恢复现场时创建 `.work/<任务名>/`，同一未结束任务复用原目录；普通问答、检查和无需留存材料的小改动不建目录。`.work/` 是容器，产品使用操作者明确指定的独立业务空间，不依赖开发草稿。
- 收尾清理本任务不再需要的临时日志、重复副本及可重建合成现场；保留必要方案、审核／验收证据、未决及恢复材料，只有仍有追溯价值的内容才移入 `.work/archive/`。待审、待恢复和持续业务空间留原位，用途不明先核实。真实论文、Gold、业务数据库、检查点及必要备份的迁移／删除须具体授权。
- 不默认扫描归档。移动材料同步有效引用、不覆盖同名文件；旧报告和回执保留当时事实，复现另核对授权与新恢复位置，不直接执行归档。不为清理另建台账、报告或兼容软链接。
- Gold 仓保留独立使用所需的资料与隐私摘要，引用主仓规则，不另建计划或进度。两仓默认同父目录，其他布局先定位对应版本；修改跨仓入口限获准范围。开发完成后的文档组织由人类确认。

## 共同要求

以下保留不能从当前实现反推的产品约束。具体字段、函数、参数默认值与已实现故障检查由代码、生成合同和测试维护；修改行为时核对这些来源及相关要求，不能因旧关卡已通过而免验。

### 资料与发行

主仓保存程序、运行所需规则／提示／配置／界面资源及获准正式星表；Gold、预留最终评价名单、审定和来源记录在私仓。真实论文、Gold 草稿和逐项评分报告留获准私有工作空间，不进入主仓、公开测试、提取请求或发行包；主仓只记录概括结论。凭据、本机环境、缓存和运行产物不入 Git。

wheel 仅含程序及必要运行资源，正式星表独立下载；README 可作为包元数据，开发文档不是运行依赖。主仓 `.dev/` 只纳入 Plan 与 Progress，Gold 仓忽略 `.dev/`。初始化空白空间不自动导入正式数据；导入须明确请求。完整 Git 克隆可能包含已纳入的正式星表，不能与代码包混淆。

保持一个 Python 应用和共同记录定义；业务模块依赖基础接口，基础模块不导入提取、网页或评分内部实现。本地工作台页面只展示和调用业务接口，不作科学判断或直接写库，不另建提取后端。公开静态网站从获准固定数据快照生成，不依赖常驻在线数据库服务或本地提取服务。LangGraph 管流程，业务库管结果，不能将框架状态当作另一套科学数据。版本以 `pyproject.toml` 为软件唯一来源，科学规则、记录格式和数据版本分别管理。

### 科学规则与模型输入

- [rules.toml](../src/hvs_catalog/resources/science/rules.toml) 是科学正文、五种作者状态、18 类物理量及合成例子的唯一来源。两版规则仅歧义策略不同；版本、审定状态和旧规则映射是维护信息，不进入提取指令。科学含义修改先说明影响、用易混样例核对并由专家审定，不能仅改状态名称完成旧规则迁移。
- 模型输入由科学正文、[steps.toml](../src/hvs_catalog/resources/prompts/steps.toml) 和共同字段生成格式组装。每步含 S01–S07 摘要及所需解释、定义、例子；名单含作者状态定义，数值含物理量定义。模型和选例可逐步配置，关闭补充提示／例子不能取消科学要求。收尾由程序执行，步骤不存在或参数不适用须在调用前报错。
- 提取指令、字段说明、合成例子及新写的摘要／疑问使用英文；材料、原始名称、数值与证据保持来源表达。专家可用自然语言答复，保留原文及一致英文表达，输入与转写方式在 R18 明确；不要求专家填写结构化补丁。中文规则解释按需临时提供，不维护另一套中文科学正文；首版不增加运行时语言切换或强制中英文实验。
- 模型填写科学内容、证据和明确的完成声明；编号、修订、引用装配与运行信息由程序提供。实际提示只发送本步科学填写内容及适用的本次专家答复，不混入材料获取、版本管理、恢复、迁移或实验安排。普通正常结果不额外填规则编号和理由；首版不查询、制作或注入裁决判例。
- 本轮计划修订不改科学规则、提示来源或生成合同。当前科学规则 0.2.1 与既有接口中的判例支持、结构化修订及评分协议不表示这些能力属于新首版要求；R17／R18 实施时按已确认范围核对并同步受影响的来源、代码与生成资料，科学含义变更仍须审定。
- 模型、协议、路由及参数由受限配置定义；凭据与参数分离，不提供任意请求体或从字符串加载代码。记录实际发送／省略的参数及转换依据，服务端未知默认值保持未知；模型补充提示不能改科学规则。更换一步模型不影响其他步骤，不按论文编号预置答案，不自动切换模型、路由或模式。
- 所有本机同账户请求和重试共享限流；连接、流空闲和总超时分别配置。只对可确认的发送前连接失败及 429 作有限重试，鉴权、格式、参数及未知完成不盲目重试。默认输出上限采用路由支持最大值，思考预算按协议解释；参数被接受不证明长输出或科学效果通过。更低实验上限须在方案中明确。
- 规则改动运行 `uv run python tools/render_science_rules.py` 及 `--check`；字段／合同改动运行 `uv run python tools/render_record_contracts.py` 及 `--check`，另验证模板可解析、Schema 与校验一致、字段说明和步骤职责正确。生成检查不能替代内容审定。

### 提取与证据

- 人类手动选择指定论文、版本、检索范围并发起运行，保存实际条件、查询时间、返回结果与进度；首版不做定时检索、新版自动处理、通用期刊爬取或多服务聚合。arXiv 首次未指定版本时固定当时最新版；已有显式新版检查命令保留，是否检查和纳入由人类决定。分页、限流、异常空页或下载失败保留未完成状态。新版失败保留旧材料与结果，已开始任务不换版本。期刊 PDF 与预印本关系须有依据，不能只凭标题合并。导入须明确身份、版本及出处，同版本不同内容不静默覆盖。
- arXiv 请求统一串行节流，本机同用户跨进程共享；跨机器由操作者协调。既定 arXiv API 间隔至少三秒、单连接；下载采用相同保守间隔，不宣称官方下载配额。遵从服务端冷却，临时错误有限重试、拒绝访问则停止；实施真实服务任务前核对官方规则。网络等待不放入长期数据库事务。
- PDF 准入检查类型、大小、页结构、加密及资源限制；远程原始字节与诊断保留，拒绝的本地文件不导入或改写。可选 LaTeX 只存档、不解包或影响 PDF 成功判定。获取状态只保存一份权威事实，来源与历史可追溯，避免重复状态和回执机制；未知旧格式明确拒绝，不自动迁移。
- 本地 MinerU advanced 解析全部页面，保存 PDF、原始解析产物、图片、页／块映射、工具版本配置与指纹；不额外渲染或附加整页图，不另做OCR或数值修正。模型接收正文、表格、作者图注及原始图片，排除解析器生成的读图描述；不静默丢图或自动切换云端／LaTeX。工具和模型资源由操作者在独立环境准备，缺失明确失败；具体安装与参数查 [适配器](../src/hvs_catalog/materials/mineru.py)，资源不在项目 wheel 或业务备份中。实测平台与限制由 Progress 和代码核对，不宣称完整进程沙箱。
- 文字证据核验固定文件、页／块与原文摘录，图片证据只核验位置、绑定和文件，不认证读图内容。解析文字匹配、页面齐全及 `materials_complete` 均不能证明原 PDF 忠实或科学准确；符号、表格行、误差、单位及对象归属仍须核对原件。支持其他定位不等于交付对应解析器；表格行键歧义不得默认取首行。
- 名单提取由模型理解明确编号范围并逐个提交；程序不从论文展开或猜补成员，只检查已列成员与条目一致。不明确余项保留范围与证据。收录对应论文贡献，排除／待决不伪造贡献；摘要、贡献类型和作者判断的证据分别可查。不同条件不投票合成作者总体结论；外部别名不写回本篇原始名称。
- 原数值字符串、误差／区间形式、单位、条件、来源和每个数字组件证据读写不变；保留数值与证据关联，自动校验引用归属、位置与解析文字摘录，不要求数字字符串逐字包含于摘录中，不认证数字支持性或读图正确性，不换算或补零、中心值、总误差及统计解释。已报告的单侧误差、零、负数及多值须可保存；无结果不创建空测量。冲突保存双方完整结构与理由，不作两条已确认测量；不同来源或条件的值分别保留，重复呈现同一结果不增加记录。
- 数值按单对象平铺测量提交，程序绑定固定对象、按明确物理量归组并装配组件证据，不要求模型填写重复的对象或分组结构。只保存合法的完整测量，不能删除无效误差来保留不完整测量；失败不覆盖其他已保存的有效结果。
- 每个对象显式保存 18 类量的检查情况，可由共同声明和逐项例外展开；省略不能当已检查。材料检查完成、科学问题和运行状态分别保存。只有相关材料查完、无影响该量的缺口／未决且无报告值时才显示“未报告”，不编造引句。缺口影响未知不能默认其余结果完整。
- 名单和数值提交用位置编号与摘录，技术引用由程序装配。JSON 可解析后只开放指定修复项，未开放字段保持原值；已列却漏交的成员只能按指定项追加，不推演新对象。每个提交单元最多两次补正，保存所有请求、响应与修改历史；技术修复不改科学规则或冒充科学评价。

### 运行与裁决

- 用不可变修订和准确引用保存科学记录，拒绝未知格式、遗漏必填、越界路径与错误论文／对象绑定。派生索引不另维护科学结果；不遍历历史把引用换成“最新”。日常提交校验本批及引用闭包和当前输出对应，备份／空间恢复全量核验；共用同一校验规则。
- 固定来源、规则、代码／依赖、模型参数、配置、本执行已有决定和例子，以及逐次实际发送的请求响应。相同请求与输入重试复用，改变输入或有意重跑建立新执行；输出身份、决定与回执按执行隔离，首版不跨执行复用步骤缓存。恢复使用原归档，缺失／损坏或代码依赖不兼容须拒绝，不用新版补旧输入。
- 同空间全部写入、执行和备份共用排他锁，取不到返回忙；暂停释放资源，其他论文和空间可继续。记录、修订、绑定及操作回执在业务事务内一并保存，同键异内容和旧预期修订拒绝。稳定锁文件不能在运行中删除／替换；平台支持据实验证，不把本机锁宣称为跨机器保证。
- 不同论文的名单与不同对象的数值请求共用并发调度，一篇名单完成即可处理其对象，不等待全部论文名单；单对象的初次提交与补正仍按顺序执行。工作线程执行网络调用，协调者统一归档、校验和写业务库；并发受固定配置与共享账户限流约束，一项失败不取消其他独立合法结果的保存。
- 文件可靠发布后才能被记录引用，不覆盖已有不同内容或接管未知非空目录。路径限制在声明根内，备份恢复拒绝逐段符号链接及越界。凭据只保存读取引用，不进入配置快照、响应归档或错误正文；未知现场不自动清理。
- 专家辅助仅对模型主动提出的歧义建立待办：先保存有效结果、问题、证据和影响范围，结束调用，专家答复后再处理依赖部分，不保持连接或反复请求等人。普通结果可展示，但不要求专家全盘核验、修正字段或逐项批准。答复仍无法确定时保留未决，收录／身份未定不当作已确认或排除。全自动自行解释并记录模型判断，不创建专家待办、不因解释歧义等待或放弃；真实材料缺口和原文冲突仍保留。策略开关不取消 Gold 操作及发布授权。
- 问题沿用类别、问题正文、证据和影响对象／物理量等必要信息；正文统一说明歧义位置、依据、合理解释、模型倾向的处理及需要专家决定的事项。有合理候选时标 A／B，没有可靠建议则明确说明，不强造选项。专家以自然语言回答，可选择建议、提出其他意见或继续未决；不开发通用复杂选项系统。
- 问题与答复绑定准确材料、规则、记录、执行和步骤；模型判断不冒充专家决定。先可靠保存原答复及回执，核对检查点和适用性，再将问题、证据、相关结果和答复送回提取模型；模型完成受影响内容，程序校验、保存并恢复流程。相同答复重复提交不创建重复处理，冲突、过期、串执行或错误引用拒绝；恢复失败不撤销已保存答复，不把旧答复移植到新目标。保留原问题、答复、后续模型请求及结果，不加工为可复用判例。
- 框架进度落后于已提交业务事实时按回执继续；无法解释的不一致停止并保留诊断。完成须同时确认业务结果完整和匹配流程终态，保存最终检查点标识；不靠“无待执行节点”单独认定完成，不自动补造凭据或修复任意内部损坏。
- 调用发送前保存 pending，完整响应先落盘再确认成功；未知完成保留 `completion_unknown`，恢复不自动重发。外部服务与本地保存不在同一事务，不能保证外部请求恰好一次。产品记录全部尝试的调用数、已知 tokens、调用与流程时间戳、失败及重试，未知为 `null`；不记录专家实际工作时间，问题创建至答复提交的等待时长不能称为专家工时。不计算货币费用或价格表，历史有值字段可读，退役账本不自动迁移。实验预算单独管理。
- 持空间锁备份稳定的业务库、检查点、全部历史引用材料与运行文件、操作回执和必要配置，排除凭据、临时项和其他备份。不能直接复制活动数据库；完整性、原哈希、业务／检查点绑定全部通过才发布完整备份。恢复只到新目录，拒绝覆盖，须在新进程验证接续；可解释的待应用／待恢复阶段保留，空间外服务调用记录不由客户端备份回滚。

### Gold 维护与就绪

- Gold 使用独立 PDF 标注外层，复用科学词表与数值校验，不给人工标注伪造执行信息。字段、格式版本、迁移差异、保存参数与人工恢复由 [生成合同](../contracts/generated/gold/README.md) 及 [evaluation](../src/hvs_catalog/evaluation) 维护；旧 v4 和迁移草稿只读支持，不静默升级不支持版本或丢弃未知科学内容。
- 新标注、迁移与局部修正共用工作副本 → 科学审定和具体保存批准 → 检查保存 → 另获准 Git 的路径。已有明确人类决定可作依据，无需重复审定同一问题；保存仍须绑定完整答案、元数据、规则、材料、目标与预期旧内容，不凭审阅者名字或通用批准标记放行。
- 每篇固定 `answer.json`／`metadata.json` 配对，历史交 Git，不建逐版目录或第二套日志重放平台。写入失败保留完整旧／新配对或充分备份，半份内容不得被读作获准答案；同内容重试核对当前结果，不重复建版本或覆盖较新修改。工具不执行 Git，未提交副本不能声称已有历史。
- 保留原标注者、真实审阅身份、日期精度、来源及科学未决，不补姓名、历史模型或批准。旧 PDF 位置与可选引文保留，不猜页序号；检查所有嵌套证据、原文件哈希和位置，文字匹配不证明语义。迁移缺口和旧新映射留报告，不虚构数字、引文、对象或完成声明；旧作者状态改变须回查原文审定。
- 原审定仅适用于绑定的规则和材料。机械元数据迁移不改答案、原审定身份时间及含义；真实迁移／修订另需范围授权，旧输入只读、未知目标不接管。原报冲突可以形成审定答案，科学未决按批准范围保留；部分范围没有贡献不等于整篇为空。
- 正式评分前核对当前规则适用性、科学审定、完整答案、PDF 版本／附表范围、文件指纹及完整性。评价记录范围在看预测前固定，按同篇论文、对象和物理量进行数值评分；条件、来源和证据保留供原文核对，不以模型判断条件等价作为评分前置。解析遗漏、失真、无源码不构成额外排除。答案、Gold 准备缺口、提取未决和评分器无法判定分别记录，不临时删除难例。
- 评分快照固定私仓 commit、答案／元数据路径与指纹、规则及材料；当前答案修正不改变历史实验。纯内存适配不读取真实仓、不改 Gold，缺条件不能猜成“未报告条件”。只有完整配对及有效就绪绑定可正式评分；answer-only、草稿及未处理准备缺口不算就绪。
- 已裁定覆盖缺口可由内容绑定的具体人类决定限定封闭评分范围，不改 Gold 原部分覆盖；缺来源、证据、条件、未确定作者状态或未结构化冲突仍须修复。材料或答案改变后重新核对，无法确认预测是否属于范围外时保留计数并标暂定，不现场豁免保存检查。

### 评价与实验

工程提供评分、两组运行、固定配置和结果导出；实验论文、样本量、运行安排和通过条件由人类专家事先确定，最终实验分析与科学结论由人类负责。先复用 R16 已保存的三篇完整提取结果接通评分，不为接通接口重新提取；如需新的开发实验，再由人类从获准的现有 Gold50 等开发材料中选定范围，不默认选十篇或跑满五十篇。

真实提取实验以已审定 Gold 和核对过的评分器为基础；每次先固定材料、代码／依赖、规则、实际英文提示、步骤选例、各步模型参数、轮次、并发、重试、指标、预算、停止和通过条件并获准。总体 API 实验预算参考 1000 RMB，单次预计可能超过 100 RMB 先提醒并等待确认；估算包含重试、核实路由报价，未知用量／费用不填零。小范围不自动扩大为 Full50 或更多组合。

#### 分层评分与比较

使用当前完整提取输出和 Gold，不另造简化提取流程。评分完全由程序完成，不开发或启用真实辅助语义模型；只报告一套 L0／L1／L2，不合成总分。失败、空预测和部分结果计入预定范围；后续失败不抹掉已验证名单，解析问题按端到端错误计入。

| 层级 | 要求 |
|---|---|
| L0 交付 | 分别报告交付／计划、格式合格／交付、格式合格／计划，区分完整、部分、失败、未完成和待决。 |
| L1 对象 | 按本篇原文标识、明确别名及受限排版一对一匹配，报告 TP／FP／FN、精确率 TP/(TP+FP)、召回率 TP/(TP+FN)、F1=2TP/(2TP+FP+FN)。不按内部编号、顺序、坐标或联网补全纠错。 |
| L2 数值提取准确性与完整性 | 在同篇论文、已匹配对象及同一物理量内一对一配对，比较完整数值结构：原值、对称／非对称误差及分量、区间与端点、单位、上下限和已报告的数值／统计结构；不只比中心值。完整匹配数 C、可评价预测数 P、应交付 Gold 数 G，精确率 C/P、召回率 C/G、F1=2C/(P+G)。组件错误不能抵消。 |

分母为零标不适用，有 Gold 无预测时召回率和 F1 为零；完整空名单另报。遗漏对象的量仍计入 G，多报对象的量在完整范围内计入 P，不以双方空栏加分；原文冲突的各个结构化备选值均保留，重复候选不能重复消耗同一 Gold 记录。同对象、同物理量内先最大化完整数值的一对一匹配，再以固定顺序为剩余项配对并列出差异、遗漏和多报；剩余项诊断不增加 C，不根据条件措辞限制配对。对象标识仅按 NFC、Unicode 负号和空白折叠处理，不删连字符或忽略大小写。该口径于 2026-10-06 获人类确认；新增数值排版等价仍须事先审定。

条件措辞、来源描述、历元／参考系说明和证据不进入语义等价判断，也不用其模型解释筛选数值配对；保留原记录及关联供核对。数值相同只支持数值匹配，不能证明科学条件、归属解释或证据支持正确；作者判断、贡献类型及这些问题不并入 L2，也不据此声称整体科学准确率。

只允许审定的无害排版等价，不改写原记录或 Gold，不换算单位尺度、坐标格式、线性／对数、距离模数或概率，不补误差、推导物理量或引入未经审定的容差。保留精度、尾零、误差形式、端点包含关系和置信／可信等数值结构。未知表达及技术失败单列；影响分数时报告暂定或明确未评分范围，不以删除难例获得最终分数。参考旧仓的程序匹配思路，但规则与容差不照搬；已审定正反例和独立手算预期在 [固定评分样例](../tests/fixtures/scoring)、[排版比较测试](../tests/test_scoring_printed_comparison.py) 及 [数值比较测试](../tests/test_scoring_regression_value_comparison.py) 按新范围维护，不能从本轮预测反造预期。

#### 结果与客观运行记录

正式评分固定程序版本、比较规则、Gold／预测及材料快照，保存配对依据、未配对记录和组件差异，重算同一输入应一致。Gold 与逐项评分反馈不进入提取、专家裁决或同轮修正。新通用比较规则须专家审阅、明确适用范围、补正反例，再按新版本重评全部受影响结果，不挑有利个案。

逐论文、逐量导出交付状态、对象与数值指标、遗漏、多报、未决和技术失败；客观运行记录包含尝试、调用数、已知 tokens、重试、失败、流程／调用时间戳及问题创建、答复提交、恢复事件。未知为 null，保留失败和部分轮次，区分重评分与新真实运行。问题等待时间不代表专家投入时间，不增加人工工时统计、普通结果审核或未主动上报错误的修正工作流。输入变化重验受影响部分，纯说明调整不重跑付费实验。

#### 专家裁决对照

全自动和专家辅助按相同固定 PDF／解析输出逐篇配对，固定共同规则、格式、例子、模型与评分，初始提示仅歧义策略不同。两组各自从头使用对应策略，独立保存结果；不能把专家组未决输出当自动基线，自动组不能用本轮专家答复或人工补值完成，专家裁决不查看 Gold／评分反馈，也不作为同轮参考答案。

两组均不注入裁决判例。专家组只回答模型主动提出的歧义，答复后的模型调用如实记录；不增加对普通结果的全盘审核或人工改值。运行图结束与科学完成分开，自动组已完整保留的原文冲突不一律视作待专家处理；分别报告数值质量、覆盖、完成、未决及客观用量，单组失败仍保留两组结果。

#### 独立评价与人类分工

R08 预留的十篇（Test10）继续在私仓隔离，开发不获取、复制或使用。是否进行独立评价、何时开展、如何标注与分析由人类决定，不属于本轮开发关卡，也不作为建表或网站交付的前置条件。开发侧交付可供人类使用的两组结果、评分、固定配置和客观调用记录，不另建设最终评价产品。

若以后开展独立评价，先冻结待测提取、裁决和评分版本、模型／提示／规则及评价方案，再取得对应材料与 Gold 操作授权；标注依据固定原 PDF，不看历史提取或待测预测。开发论文不能因换载体或解析器变成独立测试集；根据独立结果继续调参后，明确材料已参与开发并重新安排验证。结论只覆盖实际样本与配置。

## R18

**统一本地提取工作台与自然语言裁决**

**目标与交付：** 交付本地网页，统一论文选择、配置确认、运行启动、进度查看、待决问题和结果摘要；专家只回答模型主动提出的歧义，答复送回模型完成受影响内容并继续提取。

**执行与开始条件：** R17 验收及获准 Git 交付后，主 Agent 按已确认的交互范围明确最小页面、答复保存和模型继续处理接口，再实施与自检，由人类验收。复用 R05／R16 业务库、调度、保存和恢复能力；现有结构化修订接口不等于已实现自然语言答复回送模型，须核对并同步受影响的提示、记录和生成合同。

**关键要求：**

- 启动本地服务后自动打开浏览器，提供手动打开本地地址的备用方式，默认仅本机可访问。在同一工作台输入 arXiv 标识或选择已导入固定 PDF，确认本批论文及数量；显示默认模型、推理、并发和歧义策略配置，可在开始前选定支持的配置。运行及恢复使用冻结配置，不能在已有执行中静默更换。
- 显示各论文的获取／导入、PDF 解析、名单、逐对象数值和结果保存阶段，以及运行、待裁决、完成、失败状态；提供结果摘要、错误和客观调用记录。独立论文／对象可继续处理，不因一个问题暂停整批；进度展示实际业务事实，不虚构整体百分比或科学正确性。
- 新问题在原工作台显示待办提示，由专家点击查看；不为每个问题另开浏览器。问题与固定 PDF、证据、相关结果和影响范围关联，采用[统一问题正文](#运行与裁决)。专家以自然语言选择 A／B、提出意见或保留未决，保存原答复及一致英文表达；不要求填写 JSON，不做普通结果全盘核验或直接编辑错值／归属。
- 实现“模型提问 → 保存问题及相关结果 → 专家答复 → 保存答复 → 将问题、证据、相关结果和答复送回模型 → 模型完成受影响内容 → 程序校验、保存并继续”。调用在等人前结束，恢复只处理依赖部分；专家答复不是自动确认全部结果，也不抹去真实材料缺口或原文冲突。
- 页面调用共同业务接口，不直接写库或另建科学判断、审批及多用户系统。刷新、关闭和重开只读取现有运行，不意外启动或重发模型调用；继续处理由明确操作触发，重复提交、过期答复和未知完成沿用[保存恢复规则](#运行与裁决)。只保存本次决定及依据，不开发判例库、检索复用或专家工时统计。

**验收标准：** 在真实浏览器用合成 PDF／问题和模拟模型验证论文选择、配置、阶段状态、问题提示、原 PDF 证据查看及自然语言答复全过程；答复可靠保存后，模型收到正确绑定的上下文并仅完成受影响内容。重复提交只触发一次有效处理，过期或串执行输入被拒绝；刷新、关闭、重启、后续调用／保存失败与恢复不会丢失答复、污染其他结果或重发未知完成请求。全自动运行不生成专家待办或接收本轮专家答复，等待裁决不阻止其他独立任务。真实论文与模型调用另按具体范围授权，不以页面演示证明科学效果。

- 确定性程序根据同目录同版本的明确标识或原文明确对应关系关联，建立稳定对象标识并保存依据；名称相似、坐标接近、跨目录版本同号或含糊别名不能单独证明同一天体。相反证据和不确定关系明确保留，由人类手动决定必要映射；不扩展为普通提取结果的全盘裁决界面或复杂历史合并拆分工具。关联不重写论文原名、贡献或证据，多来源测量分别保存，不合成推荐参数。
- SIMBAD 在论文提取后查询，只补充本关审定的标识、别名、文献链接及测量字段；保存查询条件、时间、原始响应、匹配依据、可取得的来源／文献与版本信息。外部记录与论文值并列，不能覆盖或冒充论文直接报告；多匹配、不确定、无匹配与查询失败分别表达，技术失败不能解释为对象不存在。
- 导出只依赖明确固定的输入与数据版本，保留来源追溯。原报字符串与程序解析的机器可读值分开，派生值记录对应原修订及解析规则；只做已审定的排版清理，不换单位尺度、不推导物理量或统计解释。不另开发困难表达的模型解释／案例复用机制；未支持表达保留原值及解析状态，不声称已机读。
- 数据格式、SQL／表格结构和字段在本关确定，不预先把示意文件名当作合同。人类手动选择新增论文、同一论文新版或结果更正，再生成并确认新快照；同一 arXiv 论文 v1／v2 不重复计为独立贡献，旧结果不因新版失败被覆盖。更新历史由 GitHub 保存，不开发定时更新、历史更正平台或多渠道发布恢复。

**验收标准：** 离线验证明确关联／含糊关系／相反证据、同名不同对象、SIMBAD 多匹配／无匹配／故障和原值保持；固定输入生成一致数据内容及哈希，测量、贡献与来源不丢失或重复。验证数据库／表格能读取，机器可读值的排版解析符合独立预期，未知表达与未决身份有明确状态。用人类事先选定的小批获准材料和少量 SIMBAD 条目，核对从 arXiv 获取／固定 PDF 导入、解析、提取、必要裁决、关联／补充到导出的端到端流程，不再另设晚期实验关卡。

## R21

**GitHub Pages、独立数据下载与 Agent Skill**

**目标与交付：** 从同一获准星表快照生成 GitHub Pages 静态网页，提供搜索、浏览、来源和下载；交付可单独下载的完整数据、配套 SQL、字段／版本说明及指导 Agent 本地分析的 Skill，也支持克隆整个仓库。

**执行与开始条件：** R20 验收及获准 Git 交付后，结合实际数据规模确定静态网页、独立下载命令及文件布局，实施与自检，由人类验收。直接文件或其他 GitHub 下载方式在本关确定，“下载包”不要求压缩包、安装器或完整提取环境。公开仓库／Pages 目标与许可由人类决定，实际上传与更新由人类手动完成，开发交付不自动公开。

**关键要求：** 页面、完整数据、SQL 和 Skill 使用同一明确数据版本，可查各来源、条件和出处，不把多来源结果展示为唯一推荐参数。网页从固定快照生成，不建设常驻在线数据库服务。Skill 说明怎样下载完整星表、读取字段／关系、执行 SQL、在本地分析和回查原文；使用者无需安装提取系统。公开资源仅含获准星表与必要使用资料，不含私有 Gold、逐项评分反馈、原始业务空间或凭据。产品叙事、最终发布说明和科学结论由人类完成，开发侧只提供与实际实现一致的必要技术资料，不另设指南或运营系统关卡。

**验收标准：** 桌面与窄屏真实浏览器验证搜索、浏览、来源链接和下载；在独立目录仅下载完整数据和 SQL 即可读取与查询，Skill 指引能使 Agent 使用同一版本完成本地筛选并找到来源，克隆方式也可取得相同数据。核对页面、文件、版本与字段一致，公开候选范围正确；只做所需数据使用检查，不增加完整提取软件的跨平台发行矩阵。交付可审阅的网站与数据候选及必要使用资料，由人类确认并手动发布。
