# 项目开发计划

本文件保存人类确认的目标、开发规则和任务验收条件；实际状态与接续入口见 [Progress](progress.md)。按当前任务读对应章节，不默认通读。代码、测试和生成合同用于核对实现，不能代替需求审定或人类验收。

## 产品目标与科学边界

- 从文献整理银河系非束缚候选及其后续实质研究，保存论文提出的判断、测量和原文证据；后续否定也保留。跨论文关联同一天体，补充来源明确的外部资料，形成可回查来源和修订的星表。收录细则由已审定的科学规则决定。
- 保留本篇与引用研究的区别、作者原值、误差或区间、单位、条件、缺失原因及证据。记录论文的动力学、束缚概率或起源结果，不自行推导物理结论、用自有物理模型决定收录或选择“最佳参数”。身份关联所需的坐标解析与角距计算按R20审定规则执行，不改写论文值；首版不做历元传播。
- 提取、标注与原文核对以同一固定版本 PDF 为依据；解析结果辅助阅读，不能替代原 PDF。默认只下载 PDF，LaTeX 仅可选存档；附表须明确登记批准范围，被引用的论文、链接和数据库不自动成为本篇材料。
- 人类确定论文、版本和运行范围，Agent 通过共同业务接口执行获取／导入 → PDF 解析 → 名单 → 数值 → 星表构建与发布复核循环 → 固定版本星表 → 网页与下载，提交报告供人类审阅，最终由人类确认与上传。星表构建由程序完成保守关联与 SIMBAD 补充；发布复核由 Agent 提出、人类批准，结果只作为版本化输入回到构建，不手改构建产物，见[R21](#r21)。名单与歧义处理各只有一种方法，日常和评测共用全自动实现。
- 解释歧义由模型根据本篇证据和科学规则选择最合理的解释并简短记录依据。材料缺失、解析失败、原文错误／冲突、论文未报告和作者无总体结论分别表达。明显作者错误须由原文、定义或明确逻辑矛盾支持，不能仅凭常识排除异常但可能成立的值。无法解释的同对象、同条件数值冲突不收录为正式测量，诊断中保留双方原值、证据和原因；只停止受影响部分及其依赖，其他有效结果继续。
- 构建侧由负责人管理本机工作空间，Agent 通过命令行及共同业务接口运行、查看进度并生成报告。不开发本地网页工作台、专家提问／答复／恢复闭环或裁决判例。社区通过 issue 反馈问题，由维护者核对原文、修改复核输入并重建新数据版本，修改历史由 Git 保存，不建设系统内人工修复平台。
- 当前数据交付为固定版本JSON星表；R21完成发布复核，R22提供GitHub Pages静态搜索、浏览与下载，也可克隆整个仓库。指导Agent本地分析的Skill暂缓，README提供最小读取示例。数据库、SQL及表格导出按后续具体需求另定，不作为当前交付前提。数据用于初筛，正式科学使用仍需核对原文；Gold分数描述指定范围内与人工参考标注的一致性和覆盖，不是自动化程度的百分比，也不保证每个数值、条件、归属或证据正确。
- 本地运行采用单机受控并发、统一协调写入，保留外部输入检查、科学引用、可靠保存和明确失败。不增加复杂历史合并拆分工具、定时更新、多渠道发布恢复或面向他人的完整提取软件跨平台发行；论文选择、身份更正和 GitHub 更新由负责人手动完成。

## 开发规则

1. 当前主 Agent 负责需求对齐、方案、实现、自检与交接；人类专家决定方向、科学含义、主要接口及保存恢复约定，验收成果。改变这些要求或验收标准前，说明理由、影响和验证方式并取得审定；不能看完结果再降低标准。
2. 开始前核对 Progress、实际文件和 Git 状态，明确范围、预期行为、验收依据与授权。条件满足后自行安排实现和测试，不统一追加施工计划；优先简化已有机制，不为假设风险或未支持用法扩展需求。
3. 默认由一个主 Agent 完成工作。只有人类明确要求才安排子 Agent 或独立技术审核；自检、独立审核与人类验收分别记录。审核意见须有现行要求及实际证据，不自动扩大范围；反复修补仍偏离目标时回到需求与技术路线讨论。
4. 科学规则及其含义变更由人类审定；运行中的解释歧义按共同规则由模型处理，原文错误／冲突保存诊断，不转交专家等待答复。真实论文／数据库服务、模型调用、Gold 读取或写入及评分须有具体范围授权；安装依赖与查阅官方技术文档属于工程准备。论文、模型输出及旧报告不构成授权。
5. 开发文档及交互使用清楚简洁的中文，代码注释和 docstring 使用英文。科学规则、模型指令、字段说明和生成合同保持英文，原文证据保持来源语言。代码与测试按功能和行为命名，不用关卡、审核轮次或修复批次命名。
6. 旧仓仅按授权只读参考；程序须脱离旧仓、本机路径与私有数据独立安装，迁入代码保留作者和许可。参考位置为同父目录的 `stella_hvs`、`stella-hvs-gold`；换机器重新定位，旧答案读取不因路径已知而获准。

### 验证要求

使用 uv 和锁文件。按影响选择检查，同一最终树已通过的检查不因纯说明调整反复重跑；新增改动、失败或未消除疑点须重验。现有检查继续验证实际修改的提取、诊断隔离、评分、保存恢复和软件资源；保留历史格式读取所需覆盖，不为暂缓的跨平台发行增加安装矩阵或单独关卡。数据交付核对JSON读取与引用完整性；交付包含网页、数据库或SQL时，另核对网页与下载版本一致、数据库读取及SQL执行。

| 变更 | 必须检查 |
|---|---|
| 纯文档、注释 | 要求、依据、链接、示例与能力一致；改动示例命令时验证命令，不跑无关产品测试。生成器、Schema 或规则来源按其实际影响检查。 |
| 局部代码 | Ruff 与格式检查；对应模块、调用入口及受影响正常／失败行为的测试，涉及原生转换、进程或 HTTP 边界时包含相关集成用例。 |
| 测试维护 | 改动用例、替代覆盖及收集结果；共用夹具、选择配置或跨模块覆盖变化跑全量，并核对常规／集成两组互斥且合计等于全量。 |
| 跨模块、共同记录、事务或恢复 | 全量离线测试，含受影响的真实进程退出、竞争、备份恢复；模块连接变化补仓库外 wheel 安装验证。 |
| 打包、依赖、入口、发行资源或布局 | 全量离线及仓库外全新 wheel 安装，核对最低支持 Python 与开发版本、独立进程和发行内容。纯文档整理仍按文档检查。 |
| 整关、功能交付或发布准备 | 最终代码树全量离线及任务专项；模块连接、安装或打包涉及的检查另补。 |

常用命令：`uv sync`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest -q`。局部测试直接指定文件；`-m "not integration"` 与 `-m integration` 分组不代替全量触发要求。发行检查用 `uv run python tools/check_distribution.py 3.11`／`3.12`，不能以 `PYTHONPATH` 指向源码通过。

离线测试只用合成或获准公开材料，不读私有 Gold、不访问外部科学服务或模型；HTTP 用回环模拟，网页用真实浏览器。合成预期独立固定，不从被测输出反造答案；主要集成测试与演示共用业务流程，底层保留独立适配器。精简测试不删除有效覆盖；实际进程中断以通信或明确检查点定位故障窗口，不能只用固定睡眠或同进程异常替代。模拟服务调用事实独立持久保存，不能随客户端备份回滚。

交接记录实际命令、选择范围、通过／失败／跳过与未验证内容。生成同步、结构检查和接口接通均不证明科学质量；局部通过不写成全量通过，历史日志不代替当前检查。

### Git 操作

提交或推送前，以简明中文展示准确改动、理由、检查、限制和拟执行操作，再取得对具体内容与操作的明确授权；验收不授权 Git。可同批批准提交和推送，内容改变须重新核对授权。只暂存获准文件，不默认生成 HTML diff。

提交主题使用 `feat:`、`fix:`、`refactor:`、`test:`、`docs:`、`data:` 或 `chore:` 加英文具体说明，不含关卡号。推送另核对并说明仓库、远程、分支和提交；强推、历史重写、破坏性清理及公开发布另需特定授权。仓库保持私有，临时输出不入 Git。

### 逐关实施与交接

按 R00–R22 顺序推进，每关完成人类验收及获准 Git 交付后才进入下一关；R01 起分别完成本地提交，推送另行授权，不以未获准推送阻塞下一关。并行实施、合并关卡或分阶段交付须由人类确认。整体计划批准不等于具体科学方案、真实实验或 Git 已获准。

完成当前整关已批准可执行范围，包括接口、集成和验证后交验，未获准部分明确列出。科学任务先审定规则与预期，再据此编码。关卡外维护只读受影响要求，不启动下一关；本次维护的状态与授权写入当前交接，不增设虚构关卡。

Progress 保留任务总表和当前交接：任务／范围、已完成、验证结果、待解决、接续安排、Git 与授权。总表每关一行，状态为未开始、进行中、待验收、需修改、通过；只有人类确认才标通过及日期。暂停、完成或换 Agent 时更新，区分本次检查与沿用结果。当前交接原则上不超过 2,500 个非空白字符；必要未决或恢复信息超限时说明原因和删减条件，不靠另建交接文档转移篇幅。

需求和长期决定写入本计划或对应科学来源；Progress 只记实际事实和必要证据链接。历史已解决过程用 Git 回查，当前提交和暂存以实际 Git 为准，不另维护 SHA 台账。换机器／工作树先同步对应版本及必要未提交改动，再核对交接。

### 文档与工作材料

- 手写开发管理只维护 AGENTS 路由、Plan 要求与任务、Progress 状态。README 保留用途、开发状态、最小安装与导航；开发侧在 R22 提供准确的字段说明、数据版本、下载用法与最小读取示例，SQL示例仅在对应交付获准时提供。产品解释、最终发布说明和科学结论由人类负责，不设完整系统介绍或运营文档关卡。不另维护目录树、接口清单、命令大全或第二份当前能力表。
- 当前任务及临近任务写清范围与验收，远期任务实施前细化；完成任务删去施工与逐轮过程，仍生效的要求归入共同要求。读取链接按影响扩展，不递归通读；历史设计仅供追溯，不自动恢复已取消的机制或授权。
- 科学规则、提示配置、生成合同、合成样例及必要证据按各自来源维护，不因三份开发文档而合并或删除。修改源定义后生成并核对产物，不手改阅读版；科学含义变更仍须审定。只更新本次影响的正文和引用，不为普通检查另写报告。
- 仅需要持久保存实验、报告、日志或恢复现场时创建 `.work/<任务名>/`，同一未结束任务复用原目录；普通问答、检查和无需留存材料的小改动不建目录。`.work/` 是容器，产品使用操作者明确指定的独立业务空间，不依赖开发草稿。
- 收尾清理本任务不再需要的临时日志、重复副本及可重建合成现场；保留必要方案、审核／验收证据、未决及恢复材料，只有仍有追溯价值的内容才移入 `.work/archive/`。待审、待恢复和持续业务空间留原位，用途不明先核实。真实论文、Gold、业务数据库、检查点及必要备份的迁移／删除须具体授权。
- 不默认扫描归档。移动材料同步有效引用、不覆盖同名文件；旧报告和回执保留当时事实，复现另核对授权与新恢复位置，不直接执行归档。不为清理另建台账、报告或兼容软链接。
- Gold 仓保留独立使用所需的资料与隐私摘要，引用主仓规则，不另建计划或进度。两仓默认同父目录，其他布局先定位对应版本；修改跨仓入口限获准范围。开发完成后的文档组织由人类确认。

## 共同要求

以下保留不能从当前实现反推的产品约束。具体字段、函数、参数默认值与已实现故障检查由代码、生成合同和测试维护；修改行为时核对这些来源及相关要求，不能因旧关卡已通过而免验。

### 资料与发行

主仓保存程序、运行所需规则／提示／配置／界面资源及获准正式星表；Gold及其私有工作材料在私仓。真实论文、Gold 草稿和逐项评分报告留获准私有工作空间，不进入主仓、公开测试、提取请求或发行包；主仓只记录概括结论。凭据、本机环境、缓存和运行产物不入 Git。

wheel 仅含程序及必要运行资源，正式星表独立下载；README 可作为包元数据，开发文档不是运行依赖。主仓 `.dev/` 只纳入 Plan 与 Progress，Gold 仓忽略 `.dev/`。初始化空白空间不自动导入正式数据；导入须明确请求。完整 Git 克隆可能包含已纳入的正式星表，不能与代码包混淆。

保持一个 Python 应用和共同记录定义；业务模块依赖基础接口，基础模块不导入提取、网页或评分内部实现。Agent 使用共同命令行与业务接口，不直接写库或另建提取后端。公开静态网站从获准固定数据快照生成，不依赖常驻在线数据库服务或本地提取服务。LangGraph 管流程，业务库管结果，不能将框架状态当作另一套科学数据。版本以 `pyproject.toml` 为软件唯一来源，科学规则、记录格式和数据版本分别管理。

### 科学规则与模型输入

#### 分层评分与比较

使用当前完整提取输出和 Gold，不另造简化提取流程。评分完全由程序完成，不开发或启用真实辅助语义模型；只报告一套 L0／L1／L2，不合成总分。2026-10-16人类批准按当前合同重构：仅严格匹配或已批准的有限格式等价计为匹配，其余表达全部计为不匹配；取消无法判断、辅助模型及暂定分数分支。输入损坏、版本／材料错绑属于输入错误，明确拒绝评分，不能冒充模型科学错误。此约定替代下文历史评分版本中的未决／暂定机制。失败、空预测和部分结果计入预定范围；后续失败不抹掉已验证名单，解析问题按端到端错误计入。

### 跨论文关联

1. 使用同目录同版本的明确标识，或附原文证据的明确对应关系。原字符串保留，仅按已定义的编号解析与无害格式规范化比较；不凭名称相似、论文局部序号、Gaia未知版本或跨版本同号推断身份。
2. 标识不足时，可用明确配对、可解析且可比较的原报告坐标关联，阈值不超过5角秒。RA/Dec按共同证据位置或相同非空条件配对；重复相同坐标可复用，不任取不同候选值。只为匹配解析常见单位和时分秒格式，不改论文值。
3. 参考系依次来自坐标条件／证据、明确坐标目录来源；普通现代赤道坐标未标注时可假设ICRS并记录依据及warning。已知参考系可转换，明确矛盾或不支持的参考系不被默认值覆盖；不传播历元、不假定缺失观测历元。
4. 按角距升序确定性处理候选，每次合并检查整个对象组。同一Gaia版本的不同source ID阻止直接及传递合并。自动检测同篇接近条目的行证据矛盾：标识明确绑定各自行且各有唯一可解析时分秒坐标，证据位置相距超过5角秒，而提取位置仅与其中一行相符。保留原值和引文并阻止合并；不猜含糊或纯图像证据，不声称已校正科学值或核验PDF。
5. 双方通过可靠编号查询指向同一SIMBAD对象且无身份冲突时，可补充合并并保存依据。坐标得到的主名不反向成为可靠编号证据，相同可疑坐标得到相同SIMBAD结果不能解除来源矛盾。
6. 保守关联规则保持；另有SDSS标准格式派生查询键和限定PSR B/J、RX J前缀。SDSS仅从已有完整名称按HHMMSS.ss±DDMMSS.s截断，不取整、不猜缺失位数，保留论文原标识；派生键仅用于SIMBAD查询，不作为自动合并依据。裸B/J短名不放开，查询provenance记录原标识、源记录、证据及派生规则。仍不新增依据坐标SIMBAD同名的补充合并；超出自动规则的归并或拆分只经R21复核输入。潜在重复、同名异指及未决冲突保留；拒绝关联记录原因，不阻塞其他对象。任一采用的关系只有坐标依据时保留warning，组内其他可靠关系不消除该提示。

- 星表由同一条构建命令产生，输入为固定提取选择、冻结SIMBAD响应和版本化复核输入，输出完整catalog；待复核清单是写在catalog之外的工作文件（默认输出目录旁的`.queue.json`），不随catalog发布。发布构建加`--release`，清单有待处理项时拒绝输出。复核输入为空时，归组、来源和科学值与R20保守构建一致；按新规则选出的显示名和schema新增字段除外。
- 循环：构建 → 程序列出待复核项 → Agent提出决定、依据和证据 → 人类批准 → 写入复核输入 → 从零重建，直到清单为空或只剩已记录的未决项。任何环节都不手改catalog产物。新论文、社区纠错和身份更正都走同一循环并生成新数据版本。
- 复核输入是仓库内的`catalog-review/`目录，不放进catalog产物或.work，经Git审阅修改；理由、说明、证据位置和批准人等文字一律用英文。三个文件：`papers.json`为绑定表及逐篇数值复核，每个论文版本及其科学哈希只出现一次，有更正的论文另记PDF哈希；`identity.json`为merge、separate、name、simbad决定；`corrections.json`为转录更正。每条记录一行或数行，可直接手改；`object`只是阅读标签，构建不使用。
- 决定通过源记录节点引用论文并绑定表中哈希。论文结果变化时，该论文的复核及所有涉及它的决定失效进入清单，其余继续有效；更新表中哈希即重新批准这些记录。`catalog bind-review`只补缺失的哈希和SIMBAD响应绑定，从不刷新已有绑定；`catalog compare`按源记录比较两个catalog，用于审阅重建差异。
- 每条决定有理由、证据和批准（日期加批准人）；provenance保存实际采用的完整决定。不建审批网页、工作台或专家问答闭环；清单和建议以文件交人类审阅，Agent在对话中汇报。

### 身份与显示名

- 待复核清单列出未归组、但可能是同一对象的记录组：规范化后同名（忽略大小写、空白和连字符）、5角秒内未合并、SIMBAD main_id相同（不论匹配方法），或被冲突规则拒绝的关联。相同SIMBAD对象只生成复核项，不放宽自动合并。每组须有merge、separate或未决结论；未决保持分开并记录原因，不阻塞发布。仅靠坐标且采用的匹配角距大于1角秒时另生成simbad复核项；获准选择或撤销才能处理该项，5角秒查询半径不变。
- 决定类型为merge、separate、name（覆盖显示名并保存名称别名）、simbad（为对象组指定或撤销SIMBAD对应）及correct（固定PDF可证实的提取转录更正）。name与simbad须对准完整的最终对象组，组成员变化时失效。不做编号登记和跳转；公开发布前不承诺编号稳定。
- display_name默认取组内使用该名称的论文数最多的含字母标识，按上条同一规范化计数，显示最常见写法。并列时取较短者，再按固定字典序。通用局部编号按R20加论文标识，只在无其他标识时使用；SIMBAD main_id作为别名。个别不合适的名称用name决定覆盖：局部HVS/HiVel编号有唯一标识（SDSS/J坐标名、Gaia编号等）时以唯一标识为显示名，“局部编号 (论文)”保留为别名。名称别名不冒充论文原始标识。

### SIMBAD快照

- 构建只读冻结响应，不联网，一个数据版本对应一份完整快照。冻结的是SIMBAD原始返回，不是旧结论：匹配、状态和名称每次重新推导；查询日期在provenance中记录。
- 身份决定基本稳定后，按最终对象组生成query-plan，人类批准范围后全量查询到新目录，作为该数据版本的唯一快照，再重建。不与旧响应目录混用，因为query命令会复用目录中已有的响应，包括失败的。失败响应不删改，移到同级目录后只重试一次。重查后新出现的SIMBAD冲突、合并或被SIMBAD否定的决定进入待复核清单。
- 依赖SIMBAD的决定绑定响应哈希，响应刷新后重新复核。开发迭代中只为新出现的对象补查到同一目录；每个新数据版本发布前按同一流程全量刷新。首次公开沿用该版本2026-10-25的全量快照，见[R22数据版本](#数据版本)。

### 数值归属标记

- 单星JSON字段为`attribution`，例外理由为`attribution_reason`；`papers.json`例外使用同名`attribution`键。每条文献值标为own（本篇自己测定或计算的值，及直接列出的公开巡天测量，如Gaia自行、SDSS视向速度）、cited（从其他论文取得的数值）或mismatch（不是该量定义，如视向分量的最小v_GRF、弹射速度或渐近速度记为v_GRF）。三类都保留在JSON里；只有own参与默认值，其余在页面默认折叠。真正的三维速度下界不因下界形式算mismatch，仍按来源区分own/cited。以公开目录、势模型或转引输入计算出的新量属于own；来自其他论文的原输入，以及其他论文已计算并发布到目录中的派生结果（如Bailer-Jones距离、StarHorse距离、Marchetti距离与逃逸概率），照用时仍为cited，不论原文写adopted、taken from、from X et al.或引自本组Paper I。
- 由Agent复核：先按condition和引文中的quoted、cited、from X et al.、as reported by等规则粗分，再读条件与引文判断，仍不能判断时查固定PDF。不新增提取模型阶段或API调用；判断不了的按own处理，并在该论文的note中写明值路径和原因。
- `papers.json`逐篇记录cited/mismatch例外（值路径和简短理由），未列出的值为own。迭代构建允许有未复核论文并在清单中列出；发布构建要求所有有贡献的论文都有复核记录。
- 人类审阅Agent提交的规则与统计、全部mismatch、多篇研究对象（至少HVS1、US 708、S5-HVS1）的全部标记，以及按固定种子随机抽取的50条值，不逐值人工核对。Agent可读取固定成果、原文证据和本地固定PDF用于复核。新论文是否在提取提示中直接区分own/cited另行审定。

### 转录更正

- correct仅处理提取内容与固定PDF不符且原文能确定正确内容的情况，包括错列、抄错数字、复制其他星坐标、别名错字。论文本身就是该数、物理量定义不符、原文自相矛盾或与其他论文冲突时不使用correct，按定义与来源照录；证据不足的身份问题保持未决。
- 每条更正记录原提取的值或标识路径、改动字段（`[提取值, 更正值]`，null表示无此字段）或撤回、PDF页码与表行/正文定位、理由和批准。改动字段必须与原提取一致；原文找不到对应内容时可撤回该值，不凭模型补造。科学或PDF哈希变化时决定失效并进入清单。
- 构建顺序为固定输入校验→更正后的内存视图→保守关联及身份决定→冻结SIMBAD匹配→显示名/别名与数值归属→标准单位派生→完整校验与输出。单星JSON使用更正后的内容，被更正的标识或值带`correction`（决定编号和固定PDF证据），`evidence`仍为原提取证据；provenance保存原提取内容、更正内容及完整决定。更正前后路径用原提取索引定位，撤回不能使后续路径错位。
- 论文科学文件永远保留。未更正内容必须逐项一致，更正及撤回均须能按决定逐条对账，不允许无解释丢失或重复。名称新增别名另存，不改变原始标识证据数量。

### 标准单位派生值

- 构建时由程序为可解析的值附加标准单位派生值：速度km/s，距离与银心距离kpc，坐标deg，视差mas，自行mas/yr，概率0–1。误差、上下限和约数标记（~、≃）一并派生；距离模数和不能明确解析的值不派生，只显示原文。
- 派生只做确定的单位换算，不改原值、原单位、condition或论文科学文件。

### 数据结构与验收

- 单星JSON是唯一的单星数据源，使用获准更正后的值和标识，为每条值增加归属标记和派生值，并保存名称别名与更正标记；原提取内容及更正追溯放在provenance；旧格式仍可验证。字段说明从共同记录定义生成。"最新值"等展示选择不写入单星JSON。
- 合成测试覆盖：空复核输入时归组与科学内容等同R20；复核目录展开、绑定补全与失效；merge/separate/name/simbad/correct生效及冲突拒绝；更正改变关联结果、更正标记防篡改、原提取可追溯、撤回不移位；有待处理项或未复核论文时发布构建拒绝输出、清单不进catalog；单位换算和不可解析值；原值与证据不变；重复构建逐字节一致。
- 真实数据核对：Brown／MMT体系的HVS1、US 708（即HVS2）和S5-HVS1各为一个对象，同名异指（如其他巡天的局部HVS编号）保持分开；显示名不重复，或重复者有separate决定；待复核清单只剩已记录的未决项；来源与原提取证据数量和R20一致；未更正值逐项一致，更正按决定与provenance逐条对账。按共同验证要求运行检查。

### 默认值规则

- 候选只取有`standard`派生的own值；cited、mismatch及不能派生的值（如距离模数）不参与，只在Literature显示原文。
- 按档次选取：带误差的点估计 > 无误差的点估计 > 界限（单侧显示为> 或 <，两侧显示为a–b）；取最高非空档中最近一篇论文的值。"最近"按arXiv ID的提交年月和编号排序，显示的年份也由arXiv ID推得。带误差优先避免图上估读的近期约数压过正式测量（如US 708的RV取917 ± 7而非约750）；相比只按点估计与界限分档，按当前catalog改变20个默认值，其中v_GRF、d、RV共10个。
- 同篇在该档有多个候选时，取JSON中该论文该量的第一个，其余计入+N；Literature中该篇的代表值用同一规则。这只是可复现约定，不表示论文更看重该值；默认值来源论文对该量有多个own值很常见（v_GRF 95例、P_unbound 166例，多为不同势模型或总速度与最小速度并列），悬停和About须说明。
- P_unbound只用论文直接报告的未束缚概率，不由P_bound推算；P_bound同样单列。
- 没有own候选时显示—，不回退到cited。cited值多转引自本星表外的论文，挂在转引者名下会错误归属；星页勾选Show quoted可见。当前只有cited的对象：距离45、RV 16、P_unbound 9、v_GRF 4；v_GRF只有mismatch的35个。
- 显示用R21的标准单位派生值，保留原文有效位数。约数前加~。误差写法：对称为± e，非对称为+u −l。缺失为—。
- 默认值只在生成步骤中计算一次，首页、恒星页Latest和CSV共用，浏览器不重新做科学判断。

### 下载与实现

- stars.csv一星一行：名称、别名（以`; `连接）、Gaia DR3号、RA/Dec（deg）、Papers、First，以及Latest values各量的值、对称或上下误差、上下界、界限与约数标记和来源arXiv ID。单位写在列名里（如`v_grf_km_s`），值、误差和界限列都是纯数字，~、>、<只放在标记列；不放condition、证据和状态列。
- 首页索引和CSV由同一生成步骤产出。README补读取catalog和CSV的最小示例。
- 用tools/下的生成脚本，以--catalog、--output和--repository（GitHub仓库地址，用于issue链接）生成可独立预览的静态站，使用原生HTML/CSS/JavaScript，不引入框架、CDN或外部脚本。默认值、显示字符串、引文清理、页码链接、来源简称和+N分组都由Python生成为视图JSON，JS只渲染；规则用合成数据的pytest覆盖。
- 恒星页按需加载对应视图JSON。恒星页地址用显示名生成的短地址，重名时加最短区分后缀，不暴露catalog_id。使用相对路径和hash导航，支持刷新、前进后退和Pages子路径。
- 部署参照旧仓`deploy-pages.yml`的官方三步（configure-pages、upload-pages-artifact、deploy-pages），改为在CI中checkout后按锁文件用uv安装，先`hvs-catalog catalog verify catalog`，再运行生成脚本产出站点并上传；生成站点不提交进Git。只用`workflow_dispatch`手动触发，不随push部署；不设`enablement: true`，由人类公开仓库后在Settings → Pages选GitHub Actions再触发。issue链接用`${{ github.server_url }}/${{ github.repository }}`。CI只部署，不跑浏览器测试。
- 真实浏览器验证用Playwright，作为开发依赖并写入锁文件；浏览器二进制按工程准备本地安装，测试只访问本机回环服务。
- 文本一律转义，不执行资料中的HTML，不依赖在线数据库。
- 视觉：系统字体、浅色底、一种强调色；数字用等宽数字并右对齐；不用阴影、渐变、卡片和图标装饰。
- 先只生成首页，以及HVS1、US 708、S5-HVS1和一颗单篇Gaia候选的恒星页，交桌面与手机截图。人类确认后再全量生成。

- 研究者任务：
  - 从首页10秒内找到v_GRF最高的对象；
  - 粘贴Gaia DR3号能找到对象；
  - 从HVS1的最新速度两次点击到达PDF原页；

- 程序核对：每个默认值符合[默认值规则](#默认值规则)的档次、最近论文与同篇首个，cited、mismatch和无派生值从不成为默认值；US 708的RV为917 ± 7、S5-HVS1的距离来自8884 pc而非距离模数；页面、CSV、zip与catalog数据版本一致。
