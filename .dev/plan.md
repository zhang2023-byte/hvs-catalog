# 项目开发计划

本计划规定本次从零建设的分工、实施顺序、交付与验收。产品行为见 [产品设计](../docs/design.md)，通用开发、验证和授权见 [维护规范](../CONTRIBUTING.md)，实际状态见 [progress](progress.md)。

本文件按章节阅读，阅读范围与收尾要求见 [计划的按需阅读与压缩](../CONTRIBUTING.md#开发计划的按需阅读与压缩)。

## 开发方案

### 人员与开发工具

| 角色 | 职责 |
|---|---|
| **当前主 Agent** | 与人类专家对齐需求，负责技术方案、科学草稿、实现、自检、原始需求核对、文档和交接。 |
| **人类专家** | 审定需求、架构与科学含义，验收成果，决定关卡放行及数据、Git、发布等操作授权。 |

GPT 在 Codex 使用，GLM 在 ZCode 使用。人类专家按任务难度选择模型和工具；复杂任务交给能力足够的模型，较简单且边界明确的任务可使用较低成本模型，确定性工作优先使用程序工具。主 Agent 可以提出建议，不擅自更换模型或执行工具；不固定型号、推理档位或跨模型流水线。

### 开发方式与独立审核

默认由一个主 Agent 负责当前任务，从需求对齐到实现、自检和交付，不设常驻的规划、实现和审核交接链。自检须核对原始需求、实际支持路径、正确性与复杂度，不因测试数量多就认定成果完整或科学正确。

只有人类专家明确要求时，才安排独立技术审核或多 Agent 协作。主 Agent 可以说明理由并建议，不自行启动子 Agent 或审核者；任务复杂、存在风险或关卡含代码，都不自动触发额外协作。具体任务、审核范围和分工按本次明确要求安排，不沿用历史派单、轮次或预算。

获准的独立审核应基于实际成果、现行要求和可核对证据，检查正确性、复杂度及相关失败路径；已复现问题、代码依据和假设风险分别说明。必修建议须指出违反的现行要求及受支持路径。主 Agent 根据实际影响、证据和修复成本作出取舍，审核意见不自动扩大需求或形成修复循环；改变规格、科学含义或验收条件仍交人类专家审定。同类缺陷反复出现或成果偏离需求时，回到技术路线和需求讨论，避免继续堆补丁。

自检、独立技术审核和人类验收分别如实记录，不能相互冒称。确认的范围内缺陷仍须修复或明确说明阻塞，不因未安排独立审核而忽略。以上规则只管理开发协作；产品中的提取、评分、清理和科学裁决按业务设计执行。

### 逐关实施与交接

1. 开始前按 AGENTS 入口核对实际文件、Git 状态及 progress 的当前交接，再定位本关全文和相关设计；优先简化已有实现，不根据历史讨论推定未记录的决定。
2. 主 Agent 与人类专家对齐目标、范围、非目标、验收条件、验证方式和授权；要求明确且开始条件满足后，自行安排实现与测试，无需统一追加文件级施工计划。必要设计和影响评估遵循 [开发工作约定](../CONTRIBUTING.md#开发工作约定)。各关要求的先行设计、科学审定和实验批准须在使用前完成；整体计划通过不代表这些细节已获批准。
3. 主 Agent 完成当前整关已批准、可执行的范围，包括接口、集成、测试和配套说明，自检并核对原始需求后交人类专家验收。未获准的科学审定、真实服务验证和 Git 操作单列，不自行补足授权。科学任务先给出审定的规则与预期结果，后续代码据此验证；独立审核仅按 [启用条件](#开发方式与独立审核) 安排。局部测试或组件通过不能代替整关完成；确需分阶段交付时先说明原因、剩余范围和最终集成责任，交人类专家同意。
4. 按 R00–R30 顺序逐关推进。每关完成验收及获准的 Git 交付后，才进入下一关；R01 起每关分别提交和推送，操作要求见 [Git 规范](../CONTRIBUTING.md#git-操作)。并行实施或合并关卡须经人类专家同意。
5. 暂停、完成工作或更换 Agent 前，主 Agent 按 [工作空间规范](../CONTRIBUTING.md#工作空间创建使用与清理) 对照实际改动和验证结果，检查并修正受影响文档的漂移，核对链接与生成内容同步；需审定或暂不能修正的差异写入 progress。重要决定按 [文档职责](../CONTRIBUTING.md#文档维护与防止漂移) 写回对应正文，不留在临时交接中作为唯一依据。
6. 工作材料按上述规范按需创建、复用和清理，仅归档仍有保留价值的材料。关卡通过时，按 [计划压缩要求](../CONTRIBUTING.md#开发计划的按需阅读与压缩) 清理已完成的执行安排。主 Agent 统一更新 progress 的任务行和当前交接，记录实际检查、必要材料及未决事项；暂停或换 Agent 也须更新交接。获准的协作者交回报告，不竞争写进度。

#### 通用交接格式

progress 的**任务总表**每关一行，记录验收状态、日期和简短结论。状态为“未开始、进行中、待验收、需修改、通过”；只有人类专家确认后才填写“通过”和验收日期。

**当前交接**固定为六项，每项事实只在对应栏目详细记录：

| 项目 | 写什么 |
|---|---|
| 任务与范围 | 当前任务及涉及的文件。 |
| 已完成 | 已交付的成果；产品能力可链接 README。 |
| 验证结果 | 实际命令、结果和未验证范围；较长命令用代码块或列表。 |
| 待解决 | 接续所需的未决问题、已知限制及待专家决定事项。 |
| 接续安排 | 下一步由谁做、开始条件及完成后交给谁。 |
| Git 与授权 | 具体获准内容和操作、实际完成情况、仍待批准的操作。 |

当前交接的压缩与长度遵循 [进度文件维护](../CONTRIBUTING.md#进度文件的压缩)。实施转入验收时同步调整接续安排，记录实际执行 Agent、模型和验证范围；如获准安排独立审核，保留实际报告、结论和取舍入口，不能只依赖聊天或压缩摘要。提交与暂存以实际 Git 状态为准，不手工维护当前提交 SHA；没有明确批准依据不能视为获准。

同一工作目录可直接读取交接；换工作树或机器时先同步对应提交及必要的未提交改动，再核对文件与交接是否一致。含答案材料的存放和主仓交接范围见 [Gold 隐私要求](../../hvs-catalog-gold/README.md#操作与隐私)。

## 验证与实验安排

工程检查遵循 [验证要求](../CONTRIBUTING.md#验证要求)，各关另列需覆盖的场景。实验输入固定、指标、失败处理及最终评价独立性遵循 [评价设计](../docs/design/evaluation.md#评价gold-与持续改进)。

真实提取实验须先完成 R07 的 Gold 审定和 R09 的评分核对。主 Agent 在各实验开工前提出材料、模型组合、重复轮次、通过条件及预算，取得对应范围批准。更换模型及按步骤选择模型的功能先用模拟服务验证。最终评价论文在 R08 固定预留名单并排除开发使用，材料在准备实际标注与提取时获取并固定版本，R28 标注、R29 评价。

模型 API 实验总额参考 1000 RMB；单次预计可能超过 100 RMB 时先提醒并等待确认。费用估算包含步骤、轮次和重试，实际型号、协议、路由及报价在准备实验时核实；未知用量或费用保留未知。小范围运行不自动扩大为 Full50 或更多组合。

提取模型统一接收英文指令，按 [英文输入的核对与评价](../docs/design/evaluation.md#英文输入的核对与评价) 在 R17/R26 检查实际效果，R28 固定最终评价输入。首版不实现运行时语言选择，也不要求发布前完成中英文对照；专家文档在 R30 完成发布前英文化核对。

引用错误来源的内容进入待审正式星表、同一决定重复生效或私有答案泄露，都属于必须修复的程序问题。科学指标具体要达到多少，在相应科学任务中确定。

## R00

**项目基础文档与系统目录设计**

**目标与范围：** 交付两仓的八份基础文档及 Git 忽略规则，明确总体设计、完整开发计划与维护要求。

**执行与开始条件：** 主 Agent 编写，人类专家验收；工程骨架从 R01 开始。

**交付要求：** 八份文档的读者、正文职责与更新时机统一见 [文档职责表](../CONTRIBUTING.md#文档维护与防止漂移)。设计说明科学范围、模块职责、依赖与理由；31 关写明主要交付、依赖分工和验收标准。两仓忽略规则落实 [内容归属](../docs/design/architecture.md#内容进入哪里)。

**验收标准：** 八份文档及两仓忽略规则齐全，职责表要求的内容能在对应正文找到。文件与章节链接有效，规则一致；31 关所需成果来自更早关卡，progress 与计划对应。内部实现由主 Agent 自行安排，未决问题有明确处理责任。接手者无需读会话即可找到工作范围、验证结果、未决事项和接续安排。

主 Agent 逐项检查并说明限制，人类专家审核架构、科学范围、开发方案及全部关卡。链接检查通过仍须内容审核。本关只完成文档，不建立源码、环境、测试、数据库或正式数据。科学细则在 R03 审定，数据结构在 R04 实现，实验条件在对应任务确定。

## R01

**文件架构与最小工程骨架**

**目标与交付：** 建立可以独立安装的最小 Python 包，提供命令行帮助和版本查询，以及安装与验证说明。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R00 的人类专家验收及获准 Git 交付。架构调整由主 Agent 提出并交人类专家审定。

**关键要求：** 只建立当前需要的工程文件，依赖管理按维护规范执行；版本与发行范围分别遵循 [版本设计](../docs/design/architecture.md#保存恢复与版本) 和 [内容归属](../docs/design/architecture.md#内容进入哪里)。

**验收标准：** 在没有旧仓、Gold、密钥和本机专用路径的全新环境中，能安装构建产物，并从仓库外及独立子进程查询帮助和版本。实际支持的平台和安装步骤写入 README。

## R02

**LangGraph 持久化与恢复演示**

**目标与交付：** 用合成材料交付一个可暂停、保存决定并在程序重启后恢复的 LangGraph 演示，说明框架进度与业务数据的分工。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R01。框架不满足要求时由主 Agent 提出设计调整，交人类专家验收。

**关键要求：** 演示验证 [保存与恢复规则](../docs/design/architecture.md#保存恢复与版本)，使用独立的合成演示空间；共享入口、测试组织及旧空间边界见 [合成演示与回归验证](../docs/design/architecture.md#合成演示与回归验证)。

**验收标准：** 实际终止进程并重新启动，能找回待办、沿用固定输入并复用已保存结果。相同决定只生效一次，冲突或错误绑定的决定被拒绝。用独立持久调用记录说明“收到响应但尚未保存就退出”可能造成重复调用及真实服务计费风险，不模拟金额；演示不访问网络。不自动迁移或删除旧空间；已有验收不替代修改后版本的验证。

## R03

**科学规则、对象识别与资料补全规则**

**目标与交付：** 按 [科学规则的维护来源](../docs/design/extraction.md#科学规则的维护来源) 交付经人类专家审定的结构化文献提取规则、自动生成的阅读版，以及容易混淆的输入和预期结果；在产品设计中审定提取后的对象关联、资料补全及星表维护要求。本关确定提取规则的具体子目录、文件格式和生成方式。

**执行与开始条件：** 主 Agent 起草科学设计，人类专家逐项验收。开始前需完成 R00 的设计审定及 R02 的验收与获准 Git 交付。主 Agent 不自行决定科学规则。

**关键要求：** 明确论文与对象收录、当前贡献与引用、单个对象与群体、条件、单位、误差和缺失值、后续否定及证据要求。确定对象识别、外部资料范围、检索覆盖和自动通过或交专家的条件；审定评价目标及专家裁决对照中的科学边界。

**验收标准：** 阅读版由规则材料生成，规则、说明和例子一致，能避免无依据地把群体或条件结论归给单个对象。采用或修改规则有科学理由，未决问题不进入依赖它的实现。具体科学取值和阈值在本关审定，评分公式在 R09 实现前审定；科学边界遵循产品设计。

**交付核对：** 按 [科学规则维护](../CONTRIBUTING.md#科学规则维护) 检查英文来源、生成工具和阅读版：旧规则及字段对应完整，正文、定义和例子一致，生成结果可重复，`--check` 能发现过期阅读版；版本、审定状态及旧规则对应不进入提取指令。科学验收后更新来源的审定状态。

本关确定科学规则及系统各环节的科学边界。完整英文填写格式在 R04 确定；步骤选例和提示组装在 R13 交付，R14–R16 接入具体提取步骤；判例筛选方式与篇幅上限在 R21 实施前审定。系统合成例子 E20、E21 分别在 [R09](#r09)、[R18](#r18) 核对，提取合成例子由规则材料维护。

## R04

**核心数据格式与自动生成的格式说明**

**目标与交付：** 实现论文、来源包、贡献、名单、对象、外部资料、裁决和运行/发布记录，并从定义自动生成数据格式说明。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R03。科学表达问题由主 Agent 提出方案并交人类专家审定后再编码。

**关键要求：** 按 [记录职责](../docs/design/records.md#记录职责) 表达 R03 审定的科学含义，保留原始表达与统一格式的对应关系。本篇研究摘要采用简短自由文本并附原文证据，贡献类型单独记录。记录有版本、来源和可检查的引用；具体字段与保存格式在编码前确定。字段名、状态编码及给提取者的字段说明使用英文，由共同定义生成各步骤的填写格式，程序负责的运行信息不要求提取者填写。

**验收标准：** 合法记录保存后读回内容不变，生成说明与定义一致；研究摘要、贡献类型及各自证据能够分别回查。版本未知、引用损坏或对象/论文对应错误会报错；缺失、区间和特殊值按规则表达，提取失败不被记成成功空结果。运行清单能保存并读回专家裁决配置，不要求模型逐项填写该配置。

按 [S04 及作者状态定义](../docs/science-rules.md#s04-record-the-authors-overall-boundness-assessment) 核对各状态可保存；用合成记录验证作者状态、待裁决和未完成分别表达，处理失败不能冒充已判定的科学结果。

## R05

**工作空间、运行记录与裁决基础**

**目标与交付：** 交付独立工作空间、配置与运行记录、备份恢复，以及创建和查询裁决待办、保存决定的共同接口。

**执行与开始条件：** 主 Agent 先与人类专家确认待办、决定保存和恢复接口，再实施与自检，交人类专家验收。开始前需完成 R02、R04；记录含义采用 R03/R04 已审定的设计。

**关键要求：** 初始化保护已有资料，不同空间互不影响，数据修改完整保存。导入要求见 [内容归属](../docs/design/architecture.md#内容进入哪里)，执行锁与决定保存顺序见 [保存与恢复](../docs/design/architecture.md#保存恢复与版本)；网页与裁决命令在 R20 接入。

**验收标准：** 用模拟流程验证重复初始化、并发启动、保存中断和重启。待办、决定、论文与步骤对应正确；相同决定只生效一次，冲突或过期决定被拒绝。恢复备份后，材料、业务结果和框架进度保持一致，在仓库外也能运行。

覆盖 [专家裁决配置](../docs/design/review.md#专家裁决开关) 的保存与恢复：配置改变后建立新执行，两组的决定和后续结果不能混用。

### R05 验收场景

以下场景不限定测试数量；按受影响行为回归。主要集成场景使用共享提取流程，底层保留独立适配器验证，组织要求见 [合成验证](../docs/design/architecture.md#合成演示与回归验证)，不得减少有效覆盖。

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A01 | 新建或空目录初始化、重复初始化、传入非空未识别目录 | 已有资料和配置逐字节保留；非空未识别目录整体拒绝；两个空间互不影响。 |
| A02 | 暂存或发布初始化时中断、未知版本、误开旧独立演示空间 | 未发布目录不当作完成；已完整发布空间可打开；不接管、回滚或删除未知残留，提示另选空目录。 |
| A03 | 两个独立进程同时启动同空间任务 | 只有一个推进，另一个返回忙；无重复模拟服务调用、步骤结果或决定。 |
| A04 | 持锁进程终止、暂停后再启动；同时使用另一空间 | 锁可重新获得，另一空间独立运行；运行中删除或替换锁文件为不支持操作，不要求数据库保存 inode／ctime 身份。 |
| A05 | 保存记录、导出再读回，指定旧修订查询 | 原数值字符串、引文和准确引用保留；不能把旧引用替换成新修订。 |
| A06 | 批量提交前中断、旧修订并发更新、同操作键重试 | 事务全部成功或全部未提交；旧预期修订和同键异内容拒绝，同内容重试只返回原回执。 |
| A07 | 固定输入后修改本机配置、改变方法/模型/裁决开关 | 恢复仍用原快照；改变输入的请求建立新执行，同请求键异输入拒绝。 |
| A08 | 改动或删除当前执行所依赖的来源/规则/运行归档，传入不匹配流程版本 | 缺失、哈希错误和不兼容代码明确阻止推进；不读取当前新版替代原输入；无关历史在备份／空间恢复时全量核验。 |
| A09 | 跨空间/执行/步骤提交决定，替换正文上下文但复用请求键 | 错误绑定和异内容重放拒绝；相同显示问题不造成决定串用。 |
| A10 | 同问题重复答复、冲突答复、替代问题后提交旧答复 | 重复成功只保存一次；冲突及过期新提交拒绝；旧成功回执可查但不重新生效。 |
| A11 | 专家答复仍未决 | 答复可靠保存，问题显示已答复但仍未决；无补丁或科学排除；独立任务可随后推进。 |
| A12 | 专家组与纯 AI 合成组使用相同论文 | 关闭组拒绝本轮专家决定及衍生结果；模型判断不进入专家决定，换执行标识不能绕过隔离。 |
| A13 | 合法组合补丁应用、字段顺序颠倒、重复恢复 | 校验和应用含义一致；新修订仅一次，旧记录不变，决定关联可查。 |
| A14 | 新名单与论文贡献跨记录更新，漏掉必要更新 | 完整批次及当前输出通过共同校验；不完整更新整体拒绝，不能靠保留旧记录绕过对应检查。 |
| A15 | 决定保存前、保存后未应用、应用事务中、应用后未恢复分别退出 | 前者无半份决定；已保存决定可查；未提交结果不出现；已应用结果不再生成第二份修订。 |
| A16 | 恢复中节点重入、框架已推进但调用者未收到完成响应 | 复用操作回执和步骤结果；检查后报告实际状态，模拟服务及决定应用没有额外一次。 |
| A17 | 模拟服务收到响应、业务保存前退出 | 能恢复但可能再次调用；独立服务调用日志显示额外调用，不能宣称外部调用只发生一次。 |
| A18 | 决定保存后目标被其他操作修订；检查点串执行或缺业务结果 | 旧补丁不能移植；决定和错误可回查；不一致执行停止，不把恢复失败写成科学结论。 |
| A19 | 在等待答复、待应用、已应用待恢复、完成四种状态备份恢复 | 在新目录新进程中核对记录/材料/检查点并接续；回执完整，重复提交保护仍有效。 |
| A20 | 备份中断、缺文件、错误哈希、损坏数据库或不匹配检查点 | 无完整标记的备份不可用；坏备份不发布有效空间，源空间不被修改。 |
| A21 | 恢复目标已存在、文件路径越界、符号链接逃逸 | 明确拒绝，已有目录及空间外文件逐字节不变。 |
| A22 | 仓库外全新环境安装 wheel 后启动新空间并恢复 | 新模块可导入，通过公共接口完成保存/裁决/备份/恢复；清除 `PYTHONPATH`，无旧仓、Gold、凭据或源码路径依赖。 |

日常提交以本批记录及准确引用的闭包验收，仍检查当前输出对应、操作键、预期修订和原子性；备份／空间恢复继续完整核验历史。完成依据使用匹配流程的实际终态及保存的最终检查点标识；不要求框架私有表字节摘要或缺失凭据自动补记。实现与故障范围以[当前恢复设计](../docs/design/architecture.md#工作空间与恢复接口方案)为准。

中断测试使用父子进程通信或明确的检查点信号定位故障窗口，再结束子进程；不能只用同一进程抛异常或固定睡眠模拟全部场景。故障注入位于测试适配器或明确的合成入口，不进入正常用户流程。A17 的模拟服务调用日志独立于客户端事务和备份，以免客户端回滚抹掉已经发生的外部调用事实；不要求保留旧模拟金额或 SQLite 账本迁移协议。

通用检查遵循 [验证要求](../CONTRIBUTING.md#验证要求)，并检查锁文件同步及科学规则、记录格式的生成一致性。Python 3.12 发行验证须覆盖 R05 公共接口的仓库外完整链路，仅运行一个演示命令不算 A22；新增代码还须检查包声明的最低版本 Python 3.11 的兼容性，平台结果据实报告。生成来源变化时重新生成对应产物，禁止手改生成文件或放宽既定校验来通过测试。



## R06

**Gold 迁移、草稿检查与受控保存工具**

**目标与交付：** 用合成材料交付 Gold 迁移、逐项比较、草稿检查及获准保存工具，同时支持没有旧答案的全新草稿。

**执行与开始条件：** 主 Agent 明确新旧格式的对应关系和允许进行的科学修改，人类专家审定科学含义后，主 Agent 实现工具并自检，交人类专家验收。开始前需完成 R03–R05。

**关键要求：** 按 [Gold 标注、迁移与保存设计](../docs/design/evaluation.md#评价gold-与持续改进) 实现工具。本关在主仓开发，读取旧格式定义及工具代码，以合成材料验证；明确字段对应、差异报告和不能直接转换时的处理方式。[旧状态含义的变化](../docs/design/extraction.md#旧规则对照与调整) 由工具保留旧内容并标记待核查，真实答案的原文复核及科学裁定在 R07 执行，不能只批量替换名称。本关不读取或迁移正式 Gold，不查真实论文，不向 Gold 私库写入答案。全新草稿的接收、检查和模拟保存同样用合成材料验证。

**验收标准：** 既有答案迁移和全新草稿都能完成检查及模拟获准保存。输入损坏、版本不符、必要证据缺失、未批准或内容变化时拒绝保存，旧输入始终只读。保存按现行 [Git 维护约定](../docs/design/evaluation.md#gold-的局部修正与-git-历史) 验证：中断不能使半份内容成为有效答案，保留完整可回退成果并允许人工恢复；重复相同内容核对实际结果，不创建第二份版本，也不以旧批准覆盖新修订。不再要求逐版操作标识、日志重放或自动恢复；既有验收不替代修改后版本的验证。

实施依据见 [Gold 工具的格式对应方案](../docs/design/evaluation.md#gold-工具的格式对应方案)。其中十个合成场景及本关要求均需有可执行检查；另验证完整模板可解析、标注身份可追溯、材料对应完整及私仓 data/ 目标隔离。实际验证与未决事项由 progress 维护，证据位置由 progress 提供，仅在需要追溯时读取。

## R07

**正式 Gold 迁移与科学审定**

**目标与交付：** 在获准范围内建立正式 Gold，保存材料清单、审定与来源依据，固定供 R09 使用的答案版本、文件指纹、覆盖范围及已接受的未决状态。

**执行与开始条件：** 主 Agent 使用 R06 已验收的工具执行迁移核查和科学复核，并修复并验证已明确的工具问题，人类专家验收科学内容及结果。开始前需完成 R06，并取得读取、迁移及保存 Gold 的具体授权。

**关键要求：** 先核对正式输入版本和审定依据，再使用 R06 工具逐项比较，处理迁移报告中待核查的项目；含义变化、证据缺失及其他科学疑点在本关按获准范围回查原文。科学修改须依据原文并由人类专家裁定；具体材料与保存内容另行批准。答案和详细分析留在 Gold 私有空间，获准保存时再建立所需正式目录。正式新标注由主 Agent 根据原文制作草稿、人类专家审定。

**验收标准：** 条目、身份、来源及科学内容能够逐项核对；含义未变的部分一致，修改有批准依据，未决项按规则保留。保存结果与批准内容一致，R09 能定位并校验这一固定 Gold 版本及其适用范围。评分核对样例及预期分数由 R09 在评分规则审定后制作。

## R08

**独立最终评价材料的准备与隔离**

**目标与交付：** 提前选出少量未用于开发的最终评价论文，交付固定编号与题名清单、用途、选材理由和专家工作量估算。来源版本在后续准备实际标注与提取材料时固定。

**执行与开始条件：** 主 Agent 选材并评估隔离条件，人类专家验收名单与工作量。开始前需完成 R03、R07，并取得选材资料读取授权；后续实际获取论文材料按具体范围授权。

**关键要求：** 核对材料是否参与过提取开发、提示或模型调整、案例积累。R08 在 Gold 私仓保存预留名单，开发期间排除这些论文，不提前复制旧仓论文材料。后续准备实际标注与提取时获取材料，固定来源版本、核对 PDF 与源码对应并记录文件指纹；正式标注安排在 R28。

**验收标准：** 能核查材料独立性和访问范围，已知限制明确，专家认可选材及工作量。样本规模在本关确定；开发期间不使用这些材料调试方法或配置。

## R09

**共享提取入口与独立评分基础**

**目标与交付：** 交付日常运行与评测共用的提取入口、方法与步骤约定、专家裁决开关，以及 L0/L1/L2 独立评分和报告功能；制作固定评分样例及人工预期结果，定义辅助评分 Agent 的输入输出、验证样例和启用条件。

**执行与开始条件：** 主 Agent 明确指标定义、失败和部分结果计入分母的规则、评分器无法判定的处理及科学通过条件，交人类专家审定后实现、自检并核对科学评分含义，最终交人类专家验收。开始前需完成 R04、R05、R07。正式评分另须完成 [Gold 核对](../docs/design/evaluation.md#正式评分前的-gold-核对)，保持现有 PDF 标注格式，不为排版对齐重写 Gold。

**关键要求：** 按 [分层评分与匹配](../docs/design/evaluation.md#分层评分与匹配) 和 [排版等价与辅助评分模型](../docs/design/evaluation.md#排版等价与辅助评分模型) 审定具体比较规则与通过条件，再固定样例和预期分数。样例覆盖遗漏、多报、数值及误差错误、条件错配、排版等价与非等价、空预测、失败、部分覆盖及无法判定，绑定 Gold、规则和评分方案版本。公开测试只用合成资料，真实 Gold 样例仅放获准私有空间，不当作提取效果证据。用模拟方法验证共同入口、[裁决配置](../docs/design/review.md#专家裁决开关) 和名单到数值步骤的数据传递；实际提取在 R14–R16 完成。评分独立读取 Gold，答案不进入提取请求。

本关实现评分必需的有限排版等价比较与 Agent 判定协议，验证冻结判定的保存、复用和隔离；不建设通用星表清理系统。辅助模型的真实识别能力在 R12 接入后、首次正式评分前单独获准检验，R17 开始评分前核对这一条件；模拟通过不能授权未验证模型参与正式评分。通用派生格式、批量清理、困难表达的 Agent 提案及专家审核后纳入程序规则，由 R22 接续。

**验收标准：** 程序评分与固定样例的人工预期一致；所用正式 Gold 与 R07 固定版本及范围一致，修订或目标变化有说明。空预测、失败和部分结果按规则计入分母，评价输入变化可被发现。程序无法判断与模型失败不会伪装成正确匹配；本关明确报告辅助模型尚未实测的范围。运行和评分入口可用，用量与历史费用读取按 [运行记录要求](../docs/design/architecture.md#保存恢复与版本)，不改写旧数据。

模拟同一输入的两组执行，验证裁决开关独立于名单方法和模型配置，关闭时不会请求或等待专家。纯 AI 实验组可由模型尝试处理解释歧义，也可保留未决；日常运行不能误用这一实验例外，模型结果不能记为专家裁决。报告按论文比较两组质量、完成情况、调用用量及专家用时，未决与失败不遗漏。正式评分不现场逐项人工裁分，但评分前的科学审定和评分后的结论审核仍须完成。

**合成例子 E20（纯 AI 实验）：** 纯 AI 对照组遇到 [E08](../docs/science-rules.md#e08) 的解释歧义。

**预期：** 允许模型尝试判断；仍不能判断时，记录问题尚未解决。结果保存为纯 AI 组的模型结果，不能记为专家决定，也不能直接放入已审定判例库。此例为虚构材料，不是真实论文、Gold 或正式专家判例。

## R10

**文献发现、导入与获取**

**目标与交付：** 通过 CLI 与 Python 接口交付按专家条件从 arXiv 发现论文、按标识获取 LaTeX 源码包和导入同类本地包的能力，保存元数据、来源版本及每轮处理进度，支持查询和恢复。只依赖 arXiv，不接入 DeepXiv 或 ADS/SciX，不做获取网页、模型提取或正文表格解析。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R03、R05、R07。每轮检索范围由人类专家决定，服务调用取得具体范围授权。

**关键要求：** 按 [文献检索与材料获取](../docs/design/workflow.md#文献检索与材料获取) 使用 arXiv API 和源码下载入口，无需 DeepXiv；具体接口与服务限制在开工前核实。保留专家指定的查询条件、时间、材料版本和进度，处理分页、论文修订与重复输入；下载失败不能表示论文不相关，论文标识不能编造。

**验收标准：** 离线验证指定日期与检索条件、完整分页、修订、重复、源码不可用、限流、无权限和无结果的处理；覆盖本机跨进程共用节流、重试与服务端冷却、本地导入身份及内容冲突、异常材料安全检查、独立进程恢复和仓库外安装。多轮运行和重叠时间范围能回查覆盖情况；中断或未取完分页不记成完整检索，重复输入不会混淆材料版本。在批准的小范围内实际获取源码包，确认满足检索要求，能回查标识、版本与来源。

验证首次选定最新版后，运行期间发布新版也不改变已固定输入；已收录论文的首次提交日期在本轮新文献检索范围外时，仍能发现其新版。向每次提取任务只交付选定版本的材料及来源信息，版本选择和修订管理由程序完成。新版下载失败保留待处理记录及旧版材料。

遵循 R05 同空间串行执行，验证竞争写调用返回忙、退出后释放锁及重启恢复，不要求同空间多个获取任务并发完成。归档兼容范围按获取设计明确支持的常规形态及有界扩展子集验收，特殊变体可报告不支持；保留版本、来源历史、资源限制和失败恢复行为。获取工程状态与重试按[当前获取设计](../docs/design/workflow.md#文献检索与材料获取)验收，不要求保留历史实现的逐步回执或重复状态机制。

## R11

**来源包、正文与表格解析**

**目标与交付：** 交付版本固定的 arXiv LaTeX 来源包，解析包内正文及表格，使证据对应原文位置和正确对象。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R04、R10。来源解释中的科学歧义由人类专家裁定；实际验收见 [progress](progress.md)。

**关键要求：** 在 [科学边界](../docs/design.md#产品目标与科学边界) 限定的源码包范围内，按 [材料准备要求](../docs/design/workflow.md#提取材料的准备) 完成表格转换、编号范围展开及原文位置对应，并向提取任务提供已知缺口。开工前确定包内支持格式和解析方法，核对来源与许可；解析结果不能替代原文依据。

转换路线、支持格式、完整结构、映射粒度与统一缺口由 [材料准备正文](../docs/design/workflow.md#提取材料的准备) 维护，外部转换的安全隔离与系统依赖边界见 [技术职责](../docs/design/architecture.md#技术选择与责任)；原支持范围与验收条件不降低。不新增 PDF／OCR／FITS／任意 DAT 提取或包外获取。工程只用合成资料，真实论文回归另取材料范围授权，不读取 Gold 或预留最终评价材料。

**验收标准：** 检查 LaTeX 正文、附录、包内表格与附带资料的证据对应，尤其是 ECSV 异常列名（如 col_001）、YAML 头、多行和同名对象。无法匹配对象时不得默认使用第一行；解析失败、引用损坏和错误对象对应被发现。使用合成的包外资源链接及 PDF-only 材料，验证其保留未处理范围或材料不可用状态，不被记成论文未报告、成功空名单或科学排除；包内未受影响的结果继续保留。

用合成编号范围验证：支持且含义明确时，由程序展开并保留与原文的对应；不支持时保留未列清范围，不交给模型猜补。原文含义有歧义时使用 R05 接口提交问题。核对转换后的表格仍保留标题、表头、单位、注释和对象行；转换差异与已知材料缺口能随输入交给提取任务，原始内容与转换后的呈现能够追溯到同一来源记录。

## R12

**模型接口与完整配置**

**目标与交付：** 交付可配置的模型调用接口，保存实际参数、响应、用量和失败状态。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R05、R09、R11。

**关键要求：** 按实际协议使用模型的完整配置，核对支持的参数；不强制不同模型采用同样设置，不擅自更换模型。对技术故障限制重试次数，日志与运行记录去除密钥。

**验收标准：** 模拟验证超时、限流、错误格式、截断、空响应、未知参数及用量缺失。能区分失败和无法确认调用是否完成的情况，未公开的默认值保留未知；真实服务调用另按范围授权。

## R13

**为各步骤选择模型、组合提示并保存运行配置**

**目标与交付：** 交付默认模型与按步骤指定模型的能力，保存实际完整提示及配置，供日常运行、恢复和评测共同使用。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R12、R03，并具备 R09 定义的方法与步骤接口。

**关键要求：** 按 [提示组装与选例设计](../docs/design/extraction.md#提示的组装与例子选用)，从结构化规则材料的英文正文组装本次提取需要的规则、定义和例子，并使用 R04 定义生成的填写格式；版本及审定状态等维护信息不发送给提取模型。共同科学要求、方法必需提示和模型补充提示职责清楚。关闭补充提示后科学要求仍完整；更换一步模型不改变其他步骤。恢复沿用固定输入，材料、规则、方法或配置变化后不能误用旧结果。

**验收标准：** 模拟验证多步骤模型组合及逐步用量。不存在的步骤会报错，不混用不同协议参数；恢复后模型和提示正确。真实组合在实验前选定，不自动遍历付费组合。

检查实际组装的提示，不含版本管理、材料转换、判例制作、任务恢复、旧规则迁移和维护命令。按 [裁决配置](../docs/design/review.md#专家裁决开关) 验证日常提示要求提交歧义；纯 AI 实验提示仅替换相应的歧义处理要求，其余科学要求一致，完整实验安排不进入提取提示。

按 [语言设计](../docs/design/extraction.md#审阅语言与发布语言) 检查实际发送的任务说明、规则、方法与模型提示、字段说明、例子及判例均为英文，原文材料与证据保持原样。缺少必需的英文内容时明确报错；修改实际英文输入建立新执行。验证名单与数值步骤按配置选用相关例子、共同例子可重复使用、实际选例可回查，选例不改变科学要求。本关用合成判例输入验证组装及固定输入恢复，实际判例的制作、审核、查找和复用仍在 R21 交付。

## R14

**统一名单格式与直接提取**

**目标与交付：** 实现 direct 名单方法，按规则直接提取对象、本篇研究摘要、贡献类型、作者判断和证据，输出两种方法共用的名单格式。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R03、R04、R09、R11、R13。科学质量由 R17 的真实实验检验。

**关键要求：** 使用固定来源、规则和步骤配置，按 [自动判断与专家裁决边界](../docs/design/review.md#自动判断与专家裁决) 处理结论，保留未决项，检查证据对应。研究摘要与贡献类型分别核对，直接按规则判断时不附加规则编号或额外理由。方法不得按论文标识预置答案，格式修复有次数上限。

**验收标准：** 用模拟服务和 R03 样例检查贡献与引用、单个对象与群体、条件及后续否定。覆盖五种作者状态、单一方案中的保留措辞、作者明确总结不同条件结果、未讨论，以及讨论后没有总体结论或倾向的情形；原文含义清楚时自动记录。启用专家裁决时，模型无法确定作者意思则保存证据交专家，不能记成论文“无总体结论”，也不能将待决对象直接排除。验证明确束缚不进入 candidates_found、历史后随仍保留否定结果，可能束缚也须另有合格收录依据。失败或截断不表示成功空名单。通过 R09 模拟步骤检查后续输入要求，R16 再验证与实际数值提取的连接及裁决开关。

## R15

**候选发现与逐项模型判定**

**目标与交付：** 实现 candidate_review 名单方法：先发现候选，再由模型逐项判定，保存每项判断结果、证据和进度。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R14、R02，以及 R05 的共同裁决接口。

**关键要求：** 发现和判定都能查看原材料。每个候选得到对应结果，尚未完成的候选不能自动排除；疑问按 R09 共用入口的裁决配置处理，启用专家时使用 R05 共同裁决接口，输出与 direct 共用后续流程。

**验收标准：** 发现重复或同名候选、无效证据、单项失败及分批结果错配，并覆盖 [R14](#r14) 中明确结论与科学歧义的相同样例。进程退出后能恢复部分结果，通过共同接口保存模拟决定并继续正确候选。候选遗漏单独检查，真实论文上的覆盖由 R17 评价。

## R16

**数值提取、自动检查与部分结果保存**

**目标与交付：** 交付完整论文提取流程，连接来源、两种名单方法、共同数值提取和自动检查，并提供日常运行入口。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R14、R15。

**关键要求：** 保留数值、误差或区间、单位、条件、对象及来源。区分技术失败、科学歧义和论文确实未报告内容；有效部分结果保留。逐篇保存进度，未决问题使用 R05 接口，不阻止其他可运行论文。

**验收标准：** 两种名单方法实际进入同一数值步骤，日常运行与评测使用相同配置和服务。模拟两篇论文，一篇等待裁决时另一篇能完成；另用同篇论文的原文数值冲突，验证专家保留未决后，未受影响的已确认结果可继续处理，受影响结果保持未决；冲突影响对象收录或身份时，相应处理不会自动继续。重启后结果与待办正确，已保存结果可复用，决定只恢复对应论文。文献处理、R06 的 Gold 工具和评测入口均可执行。

两种名单方法分别覆盖裁决开关的两种配置，均进入共同的数值步骤；关闭时不会请求或等待专家，科学疑问及其处理结果仍可回查。用相同歧义样例验证专家组提交裁决、纯 AI 组尝试判断，以及模型仍无法判断时保留未决；材料缺失和技术失败不因实验例外变成成功结果。验证两组记录、缓存及恢复互不串用，原文数值及证据要求一致。

用合成材料检查同一结果在原表和转换数据中重复出现、转换内容与原文不符的情形：重复呈现不增加科学记录，转换错误不作为作者结果保存；来源、条件或表示方式不同的科学结果仍分别保留。

## R17

**首轮真实提取实验与结构问题复查**

**目标与交付：** 交付首轮小范围真实提取实验，比较两种名单方法、科学质量、失败原因和多次运行稳定性。

**执行与开始条件：** 主 Agent 设计并执行实验、分析结果和修复并验证已明确的工程问题，人类专家验收科学结论。开始前需完成 R07、R09–R16，并取得本次实验授权。

**关键要求：** 按 [实验安排](#验证与实验安排) 固定并批准本轮方案。比较方法遵循 [方法与模型选择](../docs/design/extraction.md#名单方法和模型选择)，保持模型配置组合及其他输入相同；先复查已知失败情况，保留全部轮次和调用用量。正式评分前完成 [Gold 核对](../docs/design/evaluation.md#正式评分前的-gold-核对) 及实际 [辅助评分模型验证](../docs/design/evaluation.md#排版等价与辅助评分模型)，冻结本轮评分规则和判定配置；不能用 R09 模拟结果代替模型能力验证。本轮明确裁决配置并保存未裁决的自动结果；专家裁决的独立最终对照在 R28 固定方案、R29 执行。

**验收标准：** 按 [评价设计](../docs/design/evaluation.md#评价gold-与持续改进) 报告各项指标、复验及结论范围，逐项对照通过条件。

## R18

**稳定对象身份与合并拆分**

**目标与交付：** 交付跨论文对象关联、稳定身份以及合并、拆分和更正能力，保留依据与原有论文贡献。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R03、R04、R05、R17。对象关联规则及科学分歧由主 Agent 分析、人类专家审定。

**关键要求：** 由确定性程序按 R03 审定的 [跨论文对象关联设计](../docs/design/workflow.md#跨论文对象关联) 使用已确认的标识和对应关系处理关联，名称或位置相近等不确定情况按设计保留候选关系；无法确定时通过 R05 保存待办，交专家裁决。

**验收标准：** 同目录同版本标识一致或论文明确给出对应关系，且无相反证据时，能按规则关联并保存依据；仅有跨版本同号、坐标接近、名称相似或含糊别名时，不会自动关联，标识一致但有相反证据时转交专家。同名不同对象保持区分，改名不改变稳定 ID；合并拆分后贡献不丢失、不重复，旧链接和引用仍可解释。根据保存记录重建得到一致结果，未决关联可回查。

**合成例子 E21（关联阶段）：** 两篇论文的对象坐标接近，但只有不同目录版本中的相同数字编号，原文未建立对应关系。

**预期：** 记录这两条记录可能指向同一个对象，交专家判断。不能仅因坐标接近、不同目录版本中的编号相同，就自动将两条记录归到同一个对象。此例为虚构材料，不是真实论文、Gold 或正式专家判例。

## R19

**来源明确的外部资料补全**

**目标与交付：** 从审定的外部来源补充允许使用的观测、标识和质量信息，保留匹配及来源依据。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R03、R18，并取得具体服务调用授权；科学字段与匹配解释由人类专家审定。

**关键要求：** 由确定性程序按 [外部资料补全范围](../docs/design/workflow.md#外部资料补全) 通过 Astroquery 查询 SIMBAD 和 Gaia Archive；具体目录版本、字段映射和查询范围在开工前核定。保留查询、返回条目及版本，不覆盖论文值；计算与参数选择遵循 [科学边界](../docs/design.md#产品目标与科学边界)。

**验收标准：** 离线验证多匹配、无匹配、来源版本变化和服务故障；确认补全仅在论文提取后执行，匹配确定后外部记录与论文记录并列保存，原始提取内容不被改写。在批准范围内核对少量真实条目的字段、单位与出处。调用失败不表示数据库没有该对象，匹配不确定时保留待决状态。

## R20

**本地裁决网页、CLI 与恢复**

**目标与交付：** 将 R05 的共同裁决接口接入本地网页和命令行，让专家查看证据、保存决定并恢复任务。

**执行与开始条件：** 主 Agent 设计操作流程及允许保存的内容，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R02、R05、R16、R18、R19。

**关键要求：** 两种入口共用 [裁决功能](../docs/design/architecture.md#业务架构与依赖)，遵循 [保存与恢复规则](../docs/design/architecture.md#保存恢复与版本) 和 [本地用户流程](../docs/design/workflow.md#用户工作过程)，按运行固定的裁决配置处理请求；页面操作不自动公开数据。

**验收标准：** 真实浏览器验证待办与证据展示、刷新、关闭和重启，并核对裁决服务默认仅允许本机访问。重复决定只生效一次，过期证据或规则对应的提交被拒绝，裁决后从正确步骤继续；网页和命令行行为一致，不同工作空间互不影响。关闭专家裁决的对照运行不能接收本轮专家决定，改变裁决配置须建立新执行。

## R21

**裁决案例积累、复用与汇总**

**目标与交付：** 交付裁决案例的模型起草、专家审核、保存、查找、按条件复用和问题汇总，记录专家投入的时间。

**执行与开始条件：** 主 Agent 设计复用规则，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R20。

**关键要求：** 按 [判例录入与复用设计](../docs/design/review.md#判例的录入与复用) 检查并审定英文案例，保留材料、证据和原决定，按设计提供简短复用说明。科学疑问触发按需查找，明确的问题直接处理；实现前由主 Agent 明确筛选方式、数量与总长度上限以及无结果和查找失败的处理，交人类专家验收。产品不自行调用开发 Agent 修改代码或启动实验。

**验收标准：** 个案决定保存后可恢复原任务，判例起草失败、待审或未获通过不阻塞该恢复；草稿保留原裁决关联，审核前不能复用。与主规则冲突或一致性未确定的案例不能进入可复用判例库。明确符合条件的案例可复用，条件变化后重新检查；需要揣摩作者倾向或判例适用性时仍交专家。复用引用原批准，不生成一次虚假的新批准。直接依据规则的结果无需额外判断说明，参考判例的结果能由简短说明回查原案例。新增案例不改变当前评测，重复问题、待办和专家用时能够导出查看。验证不发送整个判例库、数量和总长度限制生效、所选判例保留完整适用条件、无相关判例仍保留科学疑问；技术查找失败不能变成科学排除。保存查找及实际提供的英文判例和版本，重启后复用固定内容。

## R22

**正式星表候选与数据导出**

**目标与交付：** 从工作结果生成版本明确、来源可查的星表候选和下载表格，支持新增论文与修订；交付原报记录与机器可读派生值分层、批量格式清理及困难表达的审核入口。

**执行与开始条件：** 主 Agent 明确入库条件和导出内容，经人类专家审定后实现与自检，交人类专家验收。开始前需完成 R18–R21。

**关键要求：** 按专家审定的入库与导出规则、[科学边界](../docs/design.md#产品目标与科学边界) 及 [星表维护流程](../docs/design/workflow.md#单轮处理与星表维护) 准备候选。[格式清理](../docs/design/workflow.md#星表格式清理与机器可读导出) 优先复用程序规则，Agent 对困难表达的提案经专家审核后使用；可推广解释补齐适用范围与回归样例，完成工程验证并经人类专家验收后纳入程序，不覆盖原报记录。不同来源测量不能合成推荐值，正式保存须批准准确内容。

**验收标准：** 相同固定输入（含获准的 Agent 解释）产生相同候选及哈希，贡献和引用不丢失、不重复；关键证据损坏或身份修改未决的记录不能进入候选。覆盖数值、误差、端点与单位的排版清理、拒绝科学换算、未知宏、Agent 失败/歧义、审核拒绝及规则升级；实际清理模型须通过获准能力验证，评分模型验证不能替代。未确认派生值不宣称可机读。用合成星表验证多轮新增、重叠检索、重复处理与修订，既有未受影响的记录保持不变，修改摘要准确；修订前后内容、原始依据、转换版本和审核决定可回查。

同一 arXiv 论文的 v1、v2 按修订处理，不能作为独立论文重复入库；新版结果经专家确认后纳入正式星表，旧版仍可回查。新版处理失败或尚待确认时，已保存的旧版结果不被覆盖。

## R23

**静态星表网站与独立下载**

**目标与交付：** 生成可浏览、搜索并查看来源和修订的静态星表网站，提供程序与数据的独立下载入口。

**执行与开始条件：** 主 Agent 实施并验证技术与内容一致性，人类专家验收呈现及结果。开始前需完成 R22。

**关键要求：** 页面、表格和下载采用同一固定数据版本。保留多来源测量及版本导航，社区建议通过 GitHub issue/PR 提交；本关仅准备本地或获准私有预览。

**验收标准：** 在桌面与窄屏真实浏览器中检查搜索、导航、来源和下载。内容与版本一致，不误呈现唯一推荐参数；程序可独立安装，预览不会自动公开网站。

## R24

**项目与数据指南**

**目标与交付：** 为新用户制作便于专家审阅的指南，解释项目如何用 AI 从文献提取数据、设计原则如何影响结果，以及如何浏览、理解和使用最终星表。指南作为 R23 星表网站的一部分交付，链接来源记录、字段说明和下载入口；审阅与发布语言遵循 [语言设计](../docs/design/extraction.md#审阅语言与发布语言)。

**执行与开始条件：** 主 Agent 设计、制作并核对技术与科学解释，人类专家验收可理解性和使用指引。开始前需完成 R23；本关在 R23 后、R25 前执行。

**关键要求：** 制作前与人类专家确定内容提纲，以及对自行安装和处理文献的讲解深度。根据已实现并验证的流程，使用合成或获准公开的例子，说明 AI、自动检查与专家裁决的作用，以及多来源测量、原文证据、版本和使用限制。内容归属与更新遵循 [文档维护规范](../CONTRIBUTING.md#文档维护与防止漂移)，页面路径和源文件组织结合实际网站确定。演示无需真实模型调用，不使用私有 Gold 或最终评价预留材料；尚未完成的功能和评价明确标注。

**验收标准：** 人类专家能沿例子说明一条数据怎样从原文进入星表，找到测量的来源、条件与版本，并完成浏览和下载。桌面与窄屏真实浏览器离线检查讲解、导航和实际采用的交互；字段、链接和示例与对应版本一致。指南纳入网站构建与后续发布检查，开发阶段交付本地或获准私有预览，最终内容在 R30 核对。

## R25

**整批确认与可恢复发布机制**

**目标与交付：** 交付整批确认与可恢复发布功能，按批准范围更新仓库、网站和下载，并记录各渠道结果。

**执行与开始条件：** 主 Agent 设计确认、事务和恢复流程，经人类专家审定后实施与自检，交人类专家验收。开始前需完成 R22、R23 和 R24。

**关键要求：** 批准对应准确候选内容和目标，数据提交只包含获准文件。重试前核对已完成部分；内容或目标变化重新确认。默认私有，远程冲突不强推覆盖，真实公开另行授权。

**验收标准：** 用模拟远程与发布服务验证内容变化、重复操作、推送失败、远程变化和部分渠道失败。重启后能继续，不重复创建版本或夹带其他文件；标记成功有实际结果依据。

## R26

**完整流程与专家工作量实验**

**目标与交付：** 用一小批获准开发材料运行完整流程，交付科学质量、专家工作量及可审阅的星表和发布候选。

**执行与开始条件：** 主 Agent 设计实验、执行和分析，并修复并验证明确的工程问题，人类专家验收结论。开始前需完成 R17–R25，并取得本次实验授权。

**关键要求：** 按 [实验安排](#验证与实验安排) 固定本轮方案及故障场景，验证获取、提取、对象关联、补全、裁决和候选生成。

**验收标准：** 达到预定质量条件，普通正常记录无需逐项批准。一篇等待裁决时其他论文可继续，重启后正确恢复；已有星表新增、修订后只改变应变内容，原有依据可查，修改摘要准确。失败、部分结果、专家时间和调用用量完整报告。

## R27

**最终安装验证、安装包内容与自动检查**

**目标与交付：** 交付最终独立安装验证和持续自动检查，确认代码包、必要资源及文件发行范围正确。

**执行与开始条件：** 主 Agent 实施与自检，人类专家验收。开始前需完成 R26。

**关键要求：** 按 [内容归属](../docs/design/architecture.md#内容进入哪里) 检查安装包，逐项核对规则、提示、模型配置和页面资源均已包含。持续集成按 [验证要求](../CONTRIBUTING.md#验证要求) 执行离线检查，核对版本、生成说明与来源、文档链接及计划与进度的关卡对应。

**验收标准：** 在无旧仓、专用路径、Gold、密钥或网络的全新环境中，从仓库外安装构建产物，完成初始化、指定快照导入、离线示例、网页及独立子进程操作。测试隔离实际生效，支持平台和安装说明有实测依据。

## R28

**最终评价 Gold 标注、裁定与版本固定**

**目标与交付：** 为 R08 预留名单中的论文获取并固定评价材料，完成 Gold 标注、专家裁定及获准保存，固定最终评价答案和方案。

**执行与开始条件：** 主 Agent 制定协议、标注和复核，人类专家验收协议并裁定草稿。开始前需完成 R06、R08、R27，固定待测代码及案例的版本，并取得材料获取与私库操作授权。

**关键要求：** 按 [评价材料要求](../docs/design/evaluation.md#评价gold-与持续改进) 固定论文版本、核对 PDF 与源码对应并记录文件指纹。标注前固定待测代码、方法、模型、提示、规则、依赖和案例，包括实际发送的英文文本、步骤选例和判例查找配置。使用独立标注上下文，标注者不看历史提取或待测预测；用 R06 工具检查新草稿，具体内容获准后保存。

**验收标准：** 材料未用于开发，来源、证据、科学审定与保存结果可核对，答案留在私有空间。未决条目处理规则明确，不为提高分数排除难例；R29 的轮次、模型组合及通过条件在本关固定，并完成 [正式评分前的 Gold 核对](../docs/design/evaluation.md#正式评分前的-gold-核对)，固定经过验证的程序与辅助评分模型、规则和配置。按 [专家裁决对照设计](../docs/design/evaluation.md#专家裁决的对照实验) 固定两组配置、歧义处理、判例条件、配对方式及专家可操作范围，说明答案与裁决的隔离方式。

## R29

**对固定版本进行独立最终评价**

**目标与交付：** 对固定版本开展独立最终评价，包含关闭与开启专家裁决的对照，交付分项质量、失败情况、调用用量和专家时间，并说明结论适用范围。

**执行与开始条件：** 主 Agent 执行与分析，人类专家验收科学结论。开始前需完成 R28，并取得明确的实验授权。

**关键要求：** 严格使用 R28 固定的材料、答案和运行方案，分别评价自动与人工处理后的结果。若根据结果继续调参，注明材料已参与开发，并重新安排受影响验证。

**验收标准：** 实际运行与预定方案一致，失败和部分结果按规定计入分母；逐项对照科学与工程通过条件，未满足项明确阻止通过。逐篇配对报告专家裁决带来的质量、完成程度和专家工作量变化，核对两组结果及新增判例没有串用。科学结论经专家验收，不能超出小样本和实际测试范围。

## R30

**私有发布候选与最终操作说明**

**目标与交付：** 按实际系统及最终评价结果更新 README、产品设计和星表网站中的项目与数据指南，将 [当前操作说明](../docs/operations.md) 补齐为完整系统的最终用法，并交付可审阅的私有发布候选。

**执行与开始条件：** 主 Agent 整理工程与操作文档、更新项目与数据指南，核对技术内容、架构、科学含义及原始需求，人类专家验收可用性。开始前需完成 R29。

**关键要求：** 按 [文档职责](../CONTRIBUTING.md#文档维护与防止漂移) 说明安装配置、运行、裁决、恢复备份、故障诊断、候选审核和获准发布的步骤与预期结果。补充已确定的协作及发布规则，核对来源与许可。

按 [审阅与发布语言维护](../CONTRIBUTING.md#审阅与发布语言维护)，正式发布前将专家文档统一转为英文，核对公开文档、规则阅读版、字段说明及例子的语义与版本。公开说明准确标明提取模型使用英文指令，原文证据保持来源语言；若改动已固定的英文规则或提示，须完成受影响的重验后再作为发布依据。

**验收标准：** 人类专家按文档完成启动、恢复、待办与候选查看、备份和发布准备。文档对应已测试版本，指南中的能力和使用限制与最终验收结果一致，示例、字段说明、来源链接和下载与发布候选对应。必要成果都有验收结论，阻止发布的问题已解决。交付保持私有，实际公开、渠道和许可由专家决定；运行代码变化须重验受影响部分。
