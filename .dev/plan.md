# 项目开发计划

本文件保存人类确认的目标、开发规则和任务验收条件；实际状态与接续入口见 [Progress](progress.md)。按当前任务读对应章节，不默认通读。代码、测试和生成合同用于核对实现，不能代替需求审定或人类验收。

## 产品目标与科学边界

- 从文献整理银河系非束缚候选及其后续实质研究，保存论文提出的判断、测量和原文证据；后续否定也保留。跨论文关联同一天体，补充来源明确的外部资料，形成可回查来源和修订的星表。收录细则由已审定的科学规则决定。
- 保留本篇与引用研究的区别、作者原值、误差或区间、单位、条件、缺失原因及证据。记录论文的动力学、束缚概率或起源结果，不自行做物理计算、用自有物理模型决定收录或选择“最佳参数”。
- 提取、标注与原文核对以同一固定版本 PDF 为依据；解析结果辅助阅读，不能替代原 PDF。默认只下载 PDF，LaTeX 仅可选存档；附表须明确登记批准范围，被引用的论文、链接和数据库不自动成为本篇材料。
- 人类确定论文、版本和运行范围，Agent 通过共同业务接口执行获取／导入 → PDF 解析 → 名单 → 数值 → 必要的跨论文关联与 SIMBAD 补充 → 固定版本星表，提交报告供人类审阅，最终由人类确认与上传。名单与歧义处理各只有一种方法，日常和评测共用全自动实现。
- 解释歧义由模型根据本篇证据和科学规则选择最合理的解释并简短记录依据。材料缺失、解析失败、原文错误／冲突、论文未报告和作者无总体结论分别表达。明显作者错误须由原文、定义或明确逻辑矛盾支持，不能仅凭常识排除异常但可能成立的值。无法解释的同对象、同条件数值冲突不收录为正式测量，诊断中保留双方原值、证据和原因；只停止受影响部分及其依赖，其他有效结果继续。
- 构建侧由负责人管理本机工作空间，Agent 通过命令行及共同业务接口运行、查看进度并生成报告。不开发本地网页工作台、专家提问／答复／恢复闭环或裁决判例。社区通过 issue 反馈问题，由维护者核对原文、手动更正并生成新数据版本，修改历史由 Git 保存，不建设系统内人工修复平台。
- 对外首版交付固定版本星表：人在 GitHub Pages 静态网页搜索、浏览与下载，Agent 按 Skill 下载完整数据和 SQL 后在本地分析，也可克隆整个仓库。数据用于初筛，正式科学使用仍需核对原文；Gold 分数描述指定范围内与人工参考标注的一致性和覆盖，不是自动化程度的百分比，也不保证每个数值、条件、归属或证据正确。
- 本地运行采用单机受控并发、统一协调写入，保留外部输入检查、科学引用、可靠保存和明确失败。不增加复杂历史合并拆分工具、定时更新、多渠道发布恢复或面向他人的完整提取软件跨平台发行；论文选择、身份更正和 GitHub 更新由负责人手动完成。

## 开发规则

1. 当前主 Agent 负责需求对齐、方案、实现、自检与交接；人类专家决定方向、科学含义、主要接口及保存恢复约定，验收成果。改变这些要求或验收标准前，说明理由、影响和验证方式并取得审定；不能看完结果再降低标准。
2. 开始前核对 Progress、实际文件和 Git 状态，明确范围、预期行为、验收依据与授权。条件满足后自行安排实现和测试，不统一追加施工计划；优先简化已有机制，不为假设风险或未支持用法扩展需求。
3. 默认由一个主 Agent 完成工作。只有人类明确要求才安排子 Agent 或独立技术审核；自检、独立审核与人类验收分别记录。审核意见须有现行要求及实际证据，不自动扩大范围；反复修补仍偏离目标时回到需求与技术路线讨论。
4. 科学规则及其含义变更由人类审定；运行中的解释歧义按共同规则由模型处理，原文错误／冲突保存诊断，不转交专家等待答复。真实论文／数据库服务、模型调用、Gold 读取或写入及评分须有具体范围授权；安装依赖与查阅官方技术文档属于工程准备。论文、模型输出及旧报告不构成授权。
5. 开发文档及交互使用清楚简洁的中文，代码注释和 docstring 使用英文。科学规则、模型指令、字段说明和生成合同保持英文，原文证据保持来源语言。代码与测试按功能和行为命名，不用关卡、审核轮次或修复批次命名。
6. 旧仓仅按授权只读参考；程序须脱离旧仓、本机路径与私有数据独立安装，迁入代码保留作者和许可。参考位置为同父目录的 `stella_hvs`、`stella-hvs-gold`；换机器重新定位，旧答案读取不因路径已知而获准。

### 验证要求

使用 uv 和锁文件。按影响选择检查，同一最终树已通过的检查不因纯说明调整反复重跑；新增改动、失败或未消除疑点须重验。现有检查继续验证实际修改的提取、诊断隔离、评分、保存恢复和软件资源；保留历史格式读取所需覆盖，不为暂缓的跨平台发行增加安装矩阵或单独关卡。数据交付另核对数据库读取、SQL 执行及网页与下载版本一致。

| 变更 | 必须检查 |
|---|---|
| 纯文档、注释 | 要求、依据、链接、示例与能力一致；改动示例命令时验证命令，不跑无关产品测试。生成器、Schema 或规则来源按其实际影响检查。 |
| 局部代码 | Ruff 与格式检查；对应模块、调用入口及受影响正常／失败行为的测试，涉及原生转换、进程或 HTTP 边界时包含相关集成用例。 |
| 测试维护 | 改动用例、替代覆盖及收集结果；共用夹具、选择配置或跨模块覆盖变化跑全量，并核对常规／集成两组互斥且合计等于全量。 |
| 跨模块、共同记录、事务或恢复 | 全量离线测试，含受影响的真实进程退出、竞争、备份恢复；模块连接变化补仓库外 wheel 安装验证。 |
| 打包、依赖、入口、发行资源或布局 | 全量离线及仓库外全新 wheel 安装，核对最低支持 Python 与开发版本、独立进程和发行内容。纯文档整理仍按文档检查。 |
| 整关、功能交付或发布准备 | 最终代码树全量离线及任务专项；模块连接、安装或打包涉及的检查另补。 |

常用命令：`uv sync`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest -q`。局部测试直接指定文件；`-m "not integration"` 与 `-m integration` 分组不代替全量触发要求。发行检查用 `uv run python tools/check_distribution.py 3.11`／`3.12`，不能以 `PYTHONPATH` 指向源码通过。

离线测试只用合成或获准公开材料，不读私有 Gold、不访问外部科学服务或模型；HTTP 用回环模拟，网页用真实浏览器。合成预期独立固定，不从被测输出反造答案；主要集成测试与演示共用业务流程，底层保留独立适配器。精简测试不删除有效覆盖；实际进程中断以通信或明确检查点定位故障窗口，不能只用固定睡眠或同进程异常替代。模拟服务调用事实独立持久保存，不能随客户端备份回滚。

交接记录实际命令、选择范围、通过／失败／跳过与未验证内容。生成同步、结构检查和接口接通均不证明科学质量；局部通过不写成全量通过，历史日志不代替当前检查。

### Git 操作

提交或推送前，以简明中文展示准确改动、理由、检查、限制和拟执行操作，再取得对具体内容与操作的明确授权；验收不授权 Git。可同批批准提交和推送，内容改变须重新核对授权。只暂存获准文件，不默认生成 HTML diff。

提交主题使用 `feat:`、`fix:`、`refactor:`、`test:`、`docs:`、`data:` 或 `chore:` 加英文具体说明，不含关卡号。推送另核对并说明仓库、远程、分支和提交；强推、历史重写、破坏性清理及公开发布另需特定授权。仓库保持私有，临时输出不入 Git。

### 逐关实施与交接

按 R00–R21 顺序推进，每关完成人类验收及获准 Git 交付后才进入下一关；R01 起分别完成本地提交，推送另行授权，不以未获准推送阻塞下一关。并行实施、合并关卡或分阶段交付须由人类确认。整体计划批准不等于具体科学方案、真实实验或 Git 已获准。

完成当前整关已批准可执行范围，包括接口、集成和验证后交验，未获准部分明确列出。科学任务先审定规则与预期，再据此编码。关卡外维护只读受影响要求，不启动下一关；本次维护的状态与授权写入当前交接，不增设虚构关卡。

Progress 保留任务总表和当前交接：任务／范围、已完成、验证结果、待解决、接续安排、Git 与授权。总表每关一行，状态为未开始、进行中、待验收、需修改、通过；只有人类确认才标通过及日期。暂停、完成或换 Agent 时更新，区分本次检查与沿用结果。当前交接原则上不超过 2,500 个非空白字符；必要未决或恢复信息超限时说明原因和删减条件，不靠另建交接文档转移篇幅。

需求和长期决定写入本计划或对应科学来源；Progress 只记实际事实和必要证据链接。历史已解决过程用 Git 回查，当前提交和暂存以实际 Git 为准，不另维护 SHA 台账。换机器／工作树先同步对应版本及必要未提交改动，再核对交接。

### 文档与工作材料

- 手写开发管理只维护 AGENTS 路由、Plan 要求与任务、Progress 状态。README 保留用途、开发状态、最小安装与导航；开发侧在 R21 提供准确的字段说明、数据版本、下载用法、SQL 示例与 Skill 使用资料。产品解释、最终发布说明和科学结论由人类负责，不设完整系统介绍或运营文档关卡。不另维护目录树、接口清单、命令大全或第二份当前能力表。
- 当前任务及临近任务写清范围与验收，远期任务实施前细化；完成任务删去施工与逐轮过程，仍生效的要求归入共同要求。读取链接按影响扩展，不递归通读；历史设计仅供追溯，不自动恢复已取消的机制或授权。
- 科学规则、提示配置、生成合同、合成样例及必要证据按各自来源维护，不因三份开发文档而合并或删除。修改源定义后生成并核对产物，不手改阅读版；科学含义变更仍须审定。只更新本次影响的正文和引用，不为普通检查另写报告。
- 仅需要持久保存实验、报告、日志或恢复现场时创建 `.work/<任务名>/`，同一未结束任务复用原目录；普通问答、检查和无需留存材料的小改动不建目录。`.work/` 是容器，产品使用操作者明确指定的独立业务空间，不依赖开发草稿。
- 收尾清理本任务不再需要的临时日志、重复副本及可重建合成现场；保留必要方案、审核／验收证据、未决及恢复材料，只有仍有追溯价值的内容才移入 `.work/archive/`。待审、待恢复和持续业务空间留原位，用途不明先核实。真实论文、Gold、业务数据库、检查点及必要备份的迁移／删除须具体授权。
- 不默认扫描归档。移动材料同步有效引用、不覆盖同名文件；旧报告和回执保留当时事实，复现另核对授权与新恢复位置，不直接执行归档。不为清理另建台账、报告或兼容软链接。
- Gold 仓保留独立使用所需的资料与隐私摘要，引用主仓规则，不另建计划或进度。两仓默认同父目录，其他布局先定位对应版本；修改跨仓入口限获准范围。开发完成后的文档组织由人类确认。

## 共同要求

以下保留不能从当前实现反推的产品约束。具体字段、函数、参数默认值与已实现故障检查由代码、生成合同和测试维护；修改行为时核对这些来源及相关要求，不能因旧关卡已通过而免验。

### 资料与发行

主仓保存程序、运行所需规则／提示／配置／界面资源及获准正式星表；Gold及其私有工作材料在私仓。真实论文、Gold 草稿和逐项评分报告留获准私有工作空间，不进入主仓、公开测试、提取请求或发行包；主仓只记录概括结论。凭据、本机环境、缓存和运行产物不入 Git。

wheel 仅含程序及必要运行资源，正式星表独立下载；README 可作为包元数据，开发文档不是运行依赖。主仓 `.dev/` 只纳入 Plan 与 Progress，Gold 仓忽略 `.dev/`。初始化空白空间不自动导入正式数据；导入须明确请求。完整 Git 克隆可能包含已纳入的正式星表，不能与代码包混淆。

保持一个 Python 应用和共同记录定义；业务模块依赖基础接口，基础模块不导入提取、网页或评分内部实现。Agent 使用共同命令行与业务接口，不直接写库或另建提取后端。公开静态网站从获准固定数据快照生成，不依赖常驻在线数据库服务或本地提取服务。LangGraph 管流程，业务库管结果，不能将框架状态当作另一套科学数据。版本以 `pyproject.toml` 为软件唯一来源，科学规则、记录格式和数据版本分别管理。

### 科学规则与模型输入

- [rules.toml](../src/hvs_catalog/resources/science/rules.toml) 是唯一的模型科学规则来源。0.6.1包含已审定的四条英文规则及11个物理量的简短定义和常用单位；不保留旧作者状态、解释、合成例子集合或旧规则映射。日常和实验使用同一套要求。版本及审定状态是维护信息，不进入科学正文；科学含义修改仍须人类审定。
- 科学正文沿用审定文本，不重复科学解释。两阶段system只保留任务、科学规则、材料说明和提交行为；字段填写、空值及组合要求放入工具说明和Schema，不额外重复强调。流程接通与离线验证不代表真实科学质量通过。
- 模型材料标签只保留文字／图片位置标识及文字块类型，不重复发送已由位置编号表达的页码和块编号；完整定位映射由程序保留。补充上下文只发送非空对象与材料缺口，全部为空时省略整个 `SUPPLIED CONTEXT`；正文、表格、作者图注、原图附件及引用核验保留。

### 评价与实验

工程提供全自动运行、固定配置、程序评分和报告；Agent在人类事先确定的实验材料、样本量、运行安排、预算和通过条件内执行，最终实验分析与科学结论由人类负责。日常和实验共用正式提取路径，不恢复专家辅助组或裁决对照。开发材料可以从获准的现有Gold50等范围选定，不默认选十篇或跑满五十篇；已结束实验不构成新调用授权。

真实提取实验以已审定 Gold 和核对过的评分器为基础；每次先固定材料、代码／依赖、规则、实际英文提示、步骤选例、各步模型参数、轮次、并发、重试、指标、预算、停止和通过条件并获准。总体 API 实验预算参考 1000 RMB，单次预计可能超过 100 RMB 先提醒并等待确认；估算包含重试、核实路由报价，未知用量／费用不填零。小范围不自动扩大为 Full50 或更多组合。

#### 分层评分与比较

使用当前完整提取输出和 Gold，不另造简化提取流程。评分完全由程序完成，不开发或启用真实辅助语义模型；只报告一套 L0／L1／L2，不合成总分。2026-10-16人类批准按当前合同重构：仅严格匹配或已批准的有限格式等价计为匹配，其余表达全部计为不匹配；取消无法判断、辅助模型及暂定分数分支。输入损坏、版本／材料错绑属于输入错误，明确拒绝评分，不能冒充模型科学错误。此约定替代下文历史评分版本中的未决／暂定机制。失败、空预测和部分结果计入预定范围；后续失败不抹掉已验证名单，解析问题按端到端错误计入。

| 层级 | 要求 |
|---|---|
| L0 交付 | 分别报告交付／计划、格式合格／交付、格式合格／计划，区分完整、部分、失败和未完成。完整流程以已提交科学文件为交付；仅名单以合法名单快照为交付。部分结果也可格式合格；complete不认证科学正确。 |
| L1 对象 | 按本篇原文标识、明确别名及受限排版一对一匹配，报告 TP／FP／FN、精确率 TP/(TP+FP)、召回率 TP/(TP+FN)、F1=2TP/(2TP+FP+FN)。不按内部编号、顺序、坐标或联网补全纠错。 |
| L2 数值结构一致性与覆盖 | 同篇、同星、同一quantity内最大化整条value的一对一匹配。比较value、error、lower_error、upper_error、lower_bound、upper_bound、lower_inclusive、upper_inclusive、unit；只读当前11类量，不恢复旧结构。正确数C、范围内全部保留预测数P、全部Gold数G；精确率C/P、召回率C/G、F1=2C/(P+G)。字段错误不能抵消。 |

在已匹配星内另报漏提／多提标识数及贡献类型正确数／已匹配星数，不改变身份或数值匹配。身份不能唯一确定时不匹配，计FP和相应FN，不按数值消歧。重复星在L1计多报，其数值共用同一身份池，每条Gold只能匹配一次；附加标识和贡献类型只按第一条身份匹配记录比较。

评分输入固定清单中的全部论文；完整范围参考缺失／未审定时拒绝评分，缺预测保留分母。默认完整流程及11量，可事先限定quantity列表；仅名单scope不产生L2。已发布科学结果绑定该代准确快照；没有最终科学文件时仍读取当前已保存的合法阶段快照，不补造科学交付、不重新校正或拼接原始回复。复用名单沿原引用读取，评分不要求提取代码仍与当时一致，不启动恢复。保存冻结答案、预测、运行与引用事实、比较规则及程序指纹，离线重评不依赖原工作空间或Gold仓。

分母为零标不适用，有 Gold 无预测时召回率和 F1 为零；完整空名单另报。遗漏对象的量仍计入 G，多报对象的量在完整范围内计入 P，不以双方空栏加分。历史结果中的结构化冲突备选值按原冻结口径保留，重复候选不能重复消耗同一 Gold 记录；新规则下被隔离的诊断值不伪造为正式预测，受影响的 Gold 项也不能在看预测后临时删除。新规则与 Gold 的适用范围在新实验前核对，不改变旧报告。同对象、同物理量内先最大化完整数值的一对一匹配，再以固定顺序为剩余项配对并列出差异、遗漏和多报；剩余项诊断不增加 C，不根据条件措辞限制配对。对象标识仅按 NFC、Unicode 负号和空白折叠处理，不删连字符或忽略大小写。该配对口径于 2026-10-06 获人类确认；新增数值排版等价仍须事先审定。

已批准的单位／数字排版边界：`deg ± mas` 与 `deg; error mas` 都明确中心单位deg、误差单位mas；角色反转、mas／arcsec及实际尺度差异不等价。`s\^{-1}`只读取完整整数指数-1，不扩展数值字段语法。完整单个整数中均匀分隔的单个数字可拼接，保留正负号、全部数字及近似标记；不拼接多位数字组、列表／元组、算式、十进制或指数碎片。这些v4／v5已审定比较规则只在内存比较时解释，原Gold、预测及证据不改写。

condition中的明确数值近似／界限标记仍按当前评分器处理；2026-10-18提出的“不再从condition推导近似标记”调整尚未实施。本次整合保留现行代码与旧评分，后续修改须单独确定范围及重评安排。

- 导出只依赖明确固定的输入与数据版本，保留来源追溯。原报字符串与程序解析的机器可读值分开，派生值记录对应原修订及解析规则；只做已审定的排版清理，不换单位尺度、不推导物理量或统计解释。不另开发困难表达的模型解释／案例复用机制；未支持表达保留原值及解析状态，不声称已机读。
- 数据格式、SQL／表格结构和字段在本关确定，不预先把示意文件名当作合同。明显作者错误和无法解释的同条件冲突保留诊断及原文证据，不导出为正式测量，也不静默修正原报值。社区可提 issue，维护者核对原文后手动更正公开数据并保留出处，再生成和确认新快照；同一 arXiv 论文 v1／v2 不重复计为独立贡献，旧结果不因新版失败被覆盖。更新历史由 Git 保存，不开发系统内人工修复平台、定时更新或多渠道发布恢复。

**验收标准：** 离线验证明确关联／含糊关系／相反证据、同名不同对象、SIMBAD 多匹配／无匹配／故障和原值保持；固定输入生成一致数据内容及哈希，有效测量、贡献与来源不丢失或重复，错误／冲突诊断不会流入正式测量。验证数据库／表格能读取，机器可读值的排版解析符合独立预期，未知表达与未决身份有明确状态。用人类事先选定的小批获准材料和少量 SIMBAD 条目，核对从 arXiv 获取／固定 PDF 导入、解析、全自动提取、诊断隔离、关联／补充到导出的端到端流程，不再另设晚期实验关卡。

## R21

**GitHub Pages、独立数据下载与 Agent Skill**

**目标与交付：** 从同一获准星表快照生成 GitHub Pages 静态网页，提供搜索、浏览、来源和下载；交付可单独下载的完整数据、配套 SQL、字段／版本说明及指导 Agent 本地分析的 Skill，也支持克隆整个仓库。

**执行与开始条件：** R20 验收及获准 Git 交付后，结合实际数据规模确定静态网页、独立下载命令及文件布局，实施与自检，由人类验收。直接文件或其他 GitHub 下载方式在本关确定，“下载包”不要求压缩包、安装器或完整提取环境。公开仓库／Pages 目标与许可由人类决定，实际上传与更新由人类手动完成，开发交付不自动公开。

**关键要求：** 页面、完整数据、SQL 和 Skill 使用同一明确数据版本，可查各来源、条件和出处，不把多来源结果展示为唯一推荐参数。网页从固定快照生成，不建设常驻在线数据库服务。Skill 说明怎样下载完整星表、读取字段／关系、执行 SQL、在本地分析和回查原文；使用者无需安装提取系统。公开资源仅含获准星表与必要使用资料，不含私有 Gold、逐项评分反馈、原始业务空间或凭据。产品叙事、最终发布说明和科学结论由人类完成，开发侧只提供与实际实现一致的必要技术资料，不另设指南或运营系统关卡。

**验收标准：** 桌面与窄屏真实浏览器验证搜索、浏览、来源链接和下载；在独立目录仅下载完整数据和 SQL 即可读取与查询，Skill 指引能使 Agent 使用同一版本完成本地筛选并找到来源，克隆方式也可取得相同数据。核对页面、文件、版本与字段一致，公开候选范围正确；只做所需数据使用检查，不增加完整提取软件的跨平台发行矩阵。交付可审阅的网站与数据候选及必要使用资料，由人类确认并手动发布。
