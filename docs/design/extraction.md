# 提取方法与模型输入

说明提取流程和模型输入的目标设计，包括规则来源、语言约定、模型选择和提示组装。当前能力与配置见 [README](../../README.md#当前可用能力) 和 [操作说明](../operations.md#提取配置与提示预览)，填写结构见 [记录设计](records.md#英文填写要求与生成范围)。

返回 [设计总览与阅读入口](../design.md)。

## 科学规则的维护来源

文献提取规则以 [英文 TOML](../../src/hvs_catalog/resources/science/rules.toml) 为唯一来源，[专家辅助阅读版](../science-rules.md)与[全自动阅读版](../science-rules-automatic.md)从中生成。收录资格、贡献类型、作者状态、物理量范围、数值处理与科学疑问的具体要求均由规则定义。实际提示读取同一来源，完整阅读版不等于每次调用的完整提示。

两版规则共用科学正文，只替换“解释歧义的处理”策略段，供人类审阅和模型使用。材料范围、收录条件、作者状态、18类量定义、原值／误差／条件／证据要求及完整性要求保持一致；策略的具体行为由 [裁决配置](review.md#专家裁决开关) 维护。

专家求助与模型自行解释的指令集中在策略段；各条规则、定义、合成例子和填写说明共用科学内容，不另维护两套例子，也不靠提示组装时搜索替换规则句子。生成检查核对策略段之外的两版内容一致，并检查实际模型请求不存在冲突指令。具体规则文本及易混例子经科学审定后生效，设计要求不代替规则审定。

提取者接收已准备的本篇材料及本次可用判例，完成原文判断、对象与数值提取和证据记录，按所选策略处理解释歧义。材料获取与准备、版本管理、裁决恢复、判例制作及提取后的关联和维护，由 [用户工作过程](workflow.md#用户工作过程) 与 [专家裁决与判例](review.md#专家裁决与判例) 规定。规则与方法提示、模型配置分别管理，维护信息不发送给提取者。

规则变更的科学审定、旧规则对应和生成操作见 [科学规则维护](../../CONTRIBUTING.md#科学规则维护)。

## 旧规则对照与调整

当前作者状态相对旧规则增加“可能束缚”，并将 `not_assessed` 与 `no_overall_conclusion` 合并为“无总体结论”。迁移旧结果时，含义发生变化的记录须对照原文重新核对，不能只批量替换状态名称。旧规则及数值字段的对应保存在规则来源的维护信息中。

## 审阅语言与发布语言

提供给提取者的规则、任务与方法提示、模型补充提示、填写模板、字段说明、合成例子和判例统一使用英文。字段名、状态编码和新写的研究摘要、疑问及判例说明也使用英文。论文材料、原文证据、对象名称和原始数值按来源保留。回传提取者的专家决定提供与原决定一致的英文内容，同时保留原决定。

首版不提供运行时语言选择。实际发送的文本按 [保存要求](architecture.md#保存恢复与版本) 固定，科学效果按 [英文输入评价](evaluation.md#英文输入的核对与评价) 检查；统一语言本身不构成效果提升的证据。专家文档语言、临时中文解释与发布前翻译见 [审阅与发布语言维护](../../CONTRIBUTING.md#审阅与发布语言维护)。

## 名单方法和模型选择

产品采用一种“名单提取”流程，直接依据原文和科学规则形成对象名单，再进入数值提取；名称不加方法前缀，不设置方法选择。

S02要求模型结合对象语境理解明确的编号范围，逐个提交对象，并引用原范围证据。例如HVS4–6提交HVS4、HVS5、HVS6；S5-HVS1仍为单个名称；“and others”不猜补。程序不展开论文范围、不生成成员，只检查格式、证据和模型已列成员与对象条目是否一致。成员身份不明确时按所选歧义策略处理；未具名余项和材料缺失保留未完成范围。

名单保存纳入、排除结果及原文证据，解释歧义按所选策略形成专家待办或模型判断，额外说明按 [判例记录要求](review.md#判例的录入与复用) 提供。全自动结果不能以等待解释裁决为由阻断数值步骤。遗漏的对象不会进入数值步骤，因此仍须单独评价名单完整性；专家辅助流程能检查未被模型主动提问的结果。

科学规则决定应当提取什么，步骤配置决定本次任务和必要提示，模型配置决定使用哪个模型、模式和参数。可以为整个流程设置默认模型，也可以为某一步单独指定完整模型配置。模型补充提示可以调整表达方式，但必须保留科学内容和输出格式。

当前默认模型为 `deepseek-v4.1-flash`；日常与纯AI配置遵循 [专家裁决开关](review.md#专家裁决开关)。当前配置文件、参数、步骤检查和完整请求预览见 [提取配置操作](../operations.md#提取配置与提示预览)。

连接地址、凭据读取、超时、重试、并发与限速属于运行配置；试验配置放在工作空间。资源的发行范围见 [内容进入哪里](architecture.md#内容进入哪里)。

列出允许单独指定模型的提取步骤，给不存在或未启用的步骤设置模型时，运行前报错。不同协议的参数不能混用，也不能根据评测论文ID预置答案。更换模型或解析器时，在固定样例上验证实际效果，不为尚未证明的收益长期维护多套流程。

根据实际服务接口、模型模式和调用方式，核对支持哪些参数，不给所有模型强制设置同样的采样参数。记录实际发送和省略的参数，以及默认值或参数转换的依据；服务端未公开的值标为未知。即使请求中指定了输出格式，也要检查实际结果。输出截断、内容为空和技术失败分别处理，不能擅自套用另一模型的参数或更换模型。

## 模型接口与运行配置

`llm` 提供配置检查、受管理调用、恢复和查询，共用项目请求／结果类型；协议适配器只处理供应商转换，不承担科学判断。当前用 Token Dance 的 `openai:chat-completions`，模型及固定官方上游由 [`ModelProfile`](../../src/hvs_catalog/llm/config.py) 定义，通过 `models list` 查询；用法见 [模型操作说明](../operations.md#模型配置与调用)。后续供应商或 pi-ai 通过可信程序适配器接入，不从记录字符串动态导入代码。

非敏感 JSON 配置分别声明模型参数和运行选项；密钥从环境变量或明确指定的 `.env` 读取，环境变量优先，不修改进程环境。参数使用受限声明，类型、枚举、范围和互斥规则按模型校验；协议的 thinking 对象和 provider.only 数组由适配器构造，不提供自由 extra_body。未显式设置的采样参数不强制补齐，已公开的默认值注明依据，实际服务端值未公开时保持未知。参数配置省略与显式设置分别归档，恢复沿用已固定请求。

所有模型及本机同账户工作空间共用 SQLite 门限，账户额度由操作者配置，不是公开服务承诺。每次物理请求及重试都通过门限，流式连接完整结束或关闭后释放，租约覆盖总时限。连接、流读取空闲和单请求总超时分别配置；仅可确认的发送前连接失败和429允许有限自动重试，鉴权、参数、输出格式及未知完成不自动重试，不自动切换模型、路由或模式。默认数值由同一配置定义维护，具体设置与共享状态调整见 [模型操作说明](../operations.md#模型配置与调用)。

调用与恢复的归档顺序、pending 及 completion_unknown 处理统一见 [保存要求](architecture.md#保存恢复与版本)。默认输出为路由支持的最大值，思考预算和输出上限按协议分别解释；最大参数被接受不证明满上限长输出通过。模型与逐步思考配置的提取质量由后续获准实验检验。

## 提示的组装与例子选用

一次提取包含名单提取和数值提取步骤。每次调用组合当前步骤的任务说明、科学规则及所需定义、填写格式、选用的合成例子，以及本篇材料和必要的已有结果。判例按 [查找与复用流程](review.md#判例的录入与复用) 提供。模型补充提示不能修改科学规则，关闭补充提示后科学要求及填写格式仍须完整。

每步都呈现 S01–S07 的标题和简要正文，再附本步需要的完整解释、定义和相关例子。步骤任务、解释／定义对应和默认选例由 [英文步骤配置](../../src/hvs_catalog/resources/prompts/steps.toml) 维护，规则正文与例子仍只读取科学 TOML。名单步骤提供五种作者状态定义，数值步骤提供十八种物理量定义。选例可按步骤显式覆盖或关闭，科学要求和填写格式始终保留；切换一步模型不改变其他步骤的提示。

名单与数值分别使用按共同科学字段生成的填写格式。模型填写科学内容、疑问及证据位置，内部编号、修订和引用装配由程序管理；受限取值与保存校验一致，避免让模型填写自由组件名或猜测内部对象编号。证据位置须能回到固定原PDF，不能仅依赖解析文本行号。正文、表格文字与作者图注和原始图片共同提供给模型；解析器生成的读图描述不进入输入。文字证据与图片证据分别按其可核验范围保存，见[来源与证据](records.md#论文来源与证据)。收尾是确定性程序步骤，不接受模型或选例设置。

提示按 [裁决配置](review.md#专家裁决开关) 选择科学规则中的策略段，填写结构共用科学字段，不向全自动版另加等待专家或因解释不确定放弃处理的指令。定义、例子、格式纠正和收尾提示同样不得覆盖所选策略。模型补充提示单独维护，当前没有附加模型专属文字。显式提供的已审定英文判例保留说明、适用条件和边界，版本与审定信息只进入归档。接口检查输入声明与内容，实际判例审批与查找遵循 [判例生命周期](review.md#判例的录入与复用)。

填写格式依据共同的数据定义生成，说明字段、允许取值、多个结果及缺失或未决的表示；只要求提取者填写当前步骤的科学结果，运行信息由程序记录。

合成例子用于专家核对规则预期、程序检查及模型示范。名单阶段主要解释收录、贡献类型和作者判断，数值阶段主要解释物理量、条件、误差、重复与冲突；共同适用的例子可以在多个步骤使用。选择由步骤配置完成，模型不自行从全集挑选；实际编号与文本随输入保存，供恢复与核对。

合成例子与已审定判例分别标明用途，都不能替代本篇原文证据。能够重现提示中已有例子的答案，不能作为真实论文提取质量的独立证据。提示的实际效果在后续获准实验中检查。

## 提交与局部补正

名单提交只让模型填写科学内容与简短引用；技术定位及内部记录由程序装配。JSON不可解析时反馈具体语法位置；可解析后只开放程序选定的修复项，由局部补正工具提交替换值。未开放的字段保持原值，不靠模型重新誊写来保护。已经列名却漏交的对象只允许追加指定成员；程序不从论文推演新对象。保留最多两次补正及完整请求历史，原文引用继续校验，图片读数的能力边界不变。科学规则、科学评价与技术格式验证分别处理。
