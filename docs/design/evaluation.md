## 评价、Gold 与持续改进

在获准范围内核对 Gold 的正式版本和科学依据。首次迁移时，先说明新旧字段怎样对应、是否保留原有科学含义，再逐项审定规则变化或已有疑点引起的科学修改。格式转换成功后，仍须完成科学审定，并取得对具体保存内容的批准。

新 Gold 由获准的标注者根据原文制作草稿，提交人类专家审定。产品提供接收草稿、检查格式与必要来源信息、保存获准内容的工具；新草稿无需提供旧答案或迁移记录。检查通过后仍须取得对具体内容的科学审定和保存批准。新标注与迁移草稿共用检查和保存工具。已明确裁定的局部修正按下文 [Git 维护约定](#gold-的局部修正与-git-历史) 执行。

专家标注与审定继续以 PDF 为依据，正式提取模型使用 LaTeX 源码包。Gold 保留现有 PDF 标注格式、材料版本及原文定位，不为与 LaTeX 对齐而重写答案或证据；两种载体的排版差异由下文 [排版等价比较](#排版等价与辅助评分模型) 处理。正式评价前按 [Gold 核对要求](#正式评分前的-gold-核对) 检查版本、范围及科学内容，不能因源码未覆盖 PDF 内容就自动认定为模型遗漏。

实验前固定 [运行输入](architecture.md#保存恢复与版本)，并记录数据格式、Gold、来源版本、各步骤模型参数、轮次、并发数、重试上限、指标、预算和停止条件。科学通过条件经人类专家审核后固定，不能看到结果后再修改条件来取得通过。

评价关注提取的忠实与完整、自动判断边界是否可靠，以及专家负担是否下降。分别报告处理完成的论文、名单精确率和召回率、候选是否找全、从名单到数值的整体正确性、证据是否对应、自动完成比例、应裁决的问题是否发现、未决数量、裁决次数和专家用时；同时报告失败、部分结果、多次运行稳定性及调用用量，不记录或比较货币费用。数值评价使用预定的严格要求，覆盖规定物理量及其不同条件，不能只看成功提取的字段。判例效果包括是否减少重复处理同类问题。

空预测、整篇失败和部分结果，都按事先规定计入分母，不能为了提高分数而删去；用手算样例核对评分。评分规则经审定后，制作固定样例输出并记录人工预期的匹配结果与分数，用来核对评分程序。样例绑定答案、科学规则和评分方案的版本及适用范围；已审定 Gold 的交接固定这些答案及范围。公开测试使用合成资料，含真实 Gold 的样例留在私有空间；人为构造的样例不作为模型效果的实验结果。分别展示自动结果和人工裁决后的结果。更换 Gold 或科学目标后，明确说明新的评价目标。

实验失败时保留必要原始结果与失败轮次，在同一评价目标下修复并复验。报告注明是重新处理已有结果、假设改变条件的分析，还是实际调用服务的新实验。最终评价输入固定后，运行代码、规则、方法、提示、依赖或案例变化须重验受影响部分；只整理说明文字时，不重复无关的付费实验。

已用于开发的论文用于检查修改后是否仍能正确处理，即使经过迁移也不能当作独立测试材料。前期另选少量未用于开发的论文，在 Gold 私仓保存编号、题名、用途及使用限制，开发期间排除这些论文，不提前复制旧仓归档材料。准备实际标注和提取时再获取材料，固定来源版本、核对 PDF 与源码对应并记录文件指纹；后期按审定规则进行标注和裁定。标注者不查看历史提取或待测系统的预测。若根据评价结果继续调参，须注明这些材料已经参与开发。小样本得到的结论只适用于实际测试过的范围。

### 分层评分与匹配

提取评价只检查同一篇论文的原报内容，不判断换算后是否物理等价。分别报告三层，不合成总分；专家用时、调用用量和失败诊断不混入质量分。

| 层级 | 评价单位与指标 |
|---|---|
| L0 交付 | 以计划处理的论文为范围，报告交付数、格式合格数及完整、部分、失败、未完成、待决状态；分别计算交付/计划、合格/已交付及合格/计划的比例 |
| L1 对象 | 本篇论文与对象的对应；一对一匹配后报告正确对应 TP、多报 FP、遗漏 FN，以及精确率 TP/(TP+FP)、召回率 TP/(TP+FN)、F1=2TP/(2TP+FP+FN) |
| L2 完整数值记录 | 同一对象、物理量及条件下的一组原报结果，包括中心值或端点、误差及其形式、单位、区间解释、覆盖概率、分位点、具名分量与科学归属；以完整正确数 C、可评价预测数 P 和应交付 Gold 数 G 计算精确率 C/P、召回率 C/G、F1=2C/(P+G) |

公式的分母为零时标为不适用，不补满分；有 Gold 而预测为空时召回率与 F1 为零。正确的完整空名单另行报告，不能与失败混淆。遗漏对象下的应有数值保留在 L2 的 G 中，多报对象的数值在完整评价范围内进入 P；不以双方皆空的物理量栏位增加正确数。部分结果保留已验证成果，后续数值步骤失败不抹掉有效名单。整体结果同时展示逐论文、逐物理量明细及分项错误，不能只展示成功配对部分的准确率。

L1 使用本篇原文标识、明确的别名及受限排版整理建立对应，不按内部编号或数组顺序配对，不以坐标后备匹配或联网补全修复提取错误。L2 先限定对象和物理量，再确认条件、来源、历元和表示方式等科学归属，最后在允许的关系内一对一配对并比较内容；不得为提高数值一致率跨条件配对。明确的结构由程序核对，条件的同义表达按下节处理。不使用 Embedding 匹配条件。

一个关键组件错误或缺失，该记录就不算完整正确；分项结果用于说明错在哪里，不能相互抵消。移除 `within_gold_error`，测量不确定度不作为抄录容差；也不使用坐标跨格式转换或角距离容差。同一论文报告的不同条件或不同表示结果分别比较。贡献类型、作者判断、候选发现召回及证据支持关系另列诊断，不以引文相似度证明科学正确。

### 排版等价与辅助评分模型

评分允许数值、误差、端点和单位的无害排版等价，例如 PDF 的上标与 LaTeX 指数语法。它只产生比较用的临时解释，不改写提取记录或 Gold。不得借此换算单位尺度、坐标格式、线性/对数/距离模数、概率表示或统计意义，也不补误差、合并误差分量或计算新的物理量。原报精度和表达不能被无条件清理掉；各类允许等价需用审定样例固定。面向展示与下载的派生值按 [星表格式清理](workflow.md#星表格式清理与机器可读导出) 另行生成。

#### 排版与条件的边界样例

以下均为合成材料，用于固定比较规则，不是模型能力已通过的证据。除明确展示的差异外，两边的对象、物理量、来源及其他条件一致；组合表达在实际记录中仍按数值、误差、单位等字段分别保存。

| 编号 | 两边表达或情形 | 预期判定 |
|---|---|---|
| A1 | `km s⁻¹` 与 `\mathrm{km\,s^{-1}}` | 一致：只有单位排版差异，无尺度转换 |
| A2 | `−8.2` 与 `-8.2` | 一致：Unicode 负号与普通负号 |
| A3 | `1.20 × 10³` 与 `1.20\times10^{3}` | 一致：系数、尾零和指数均保留 |
| A4 | `12h34m56.7s` 与 `12^{h}34^{m}56.7^{s}` | 一致：同一种时分秒表达，不转换成角度 |
| A5 | `under Galactic potential M1` 与 `assuming potential M1` | 条件等价：上下文明确指同一模型，且没有遗漏其他限定 |
| B1 | 原报 `8.2 ± 0.3 kpc`，预测 `8200 ± 300 pc` | 不算完整正确：正确换算也未保留原报表达 |
| B2 | 原报 `600 ± 20`，预测 `610 ± 20` | 错误：中心值不同，落在误差内不能算正确 |
| B3 | 原报 `8.2 ± 0.3`，预测 `8.2` 或 `8.2 ± 0.2` | 错误：误差遗漏或抄错；两个变体分别测试 |
| B4 | 原报 `8.2 ± 0.3`，预测值为 `8.2`，下误差和上误差均填 `0.3` | 不算完整正确：对称误差改成非对称字段，改变原报形式 |
| B5 | 原报 95% 置信区间 `[7, 9]`，预测 95% 可信区间 `[7, 9]` | 错误：端点相同不代表统计解释相同 |
| B6 | 原报纯区间 `[7, 9]`，预测 `8 ± 1` | 错误：自行补中心值并改变表达 |
| B7 | 原报 `< 600`，预测 `≤ 600` | 错误：端点是否包含发生变化 |
| B8 | Gold 中 M1 下为 8、M2 下为 10；预测中 M1 下为 10、M2 下为 8 | 两条均错误：按条件对应，不能跨条件寻找相同数字 |
| C1 | 原报 `8.20`，预测 `8.2` | 不算完整正确：数值相等，但原报小数位和尾零未保留；不据尾零推导误差大小 |
| U1 | 未知宏 `\mystery{8.2}`，材料不足以确认它是否只控制排版 | 无法判定：不能删掉宏后直接接受 |
| U2 | Gold 区分 M1、M2；预测只写“采用银河势模型”，上下文仍不能确定指哪个 | 无法确认对应：不能按数值最接近选择模型 |

U1、U2 的能力测试预期是正确拒绝猜测；正式评分中出现这种影响得分的情况，报告仍保持暂定。上表约束判定边界，完整测试还须固定输入材料、原文依据、预期配对、组件诊断及手算分数。

#### 辅助模型的职责与验证

程序优先识别已支持的排版形式和明确条件；无法判断的排版表达或条件对应可交给经过验证的辅助评分 Agent。Agent 只返回等价、不等价或无法判定，以及所依赖的原文依据，不修改数值、不输出总分。程序核对响应结构、允许关系和一对一约束，计算分数。不能仅因数字相同就接受条件等价，不能将程序已经确认的科学差异交给模型改判。无法判定和模型技术失败分别保留，不静默视为正确、提取错误或从分母删除。存在影响得分的未决对应时，保留已确定的明细，整批报告标为暂定，不出具单一最终分数；修复后按新版本重评全部受影响结果，不现场人工改分。

辅助模型启用前，使用人工预定答案的合成或获准开发样例验证。覆盖同数异写、近似但不等、符号与指数错误、单位尺度不同、误差侧别、上下限、模型名/目录版本/否定条件、无对应项、模糊对应及未知宏，分别检查误接受、误拒绝、无法判定和重复运行稳定性。固定提示和模型版本不等于能力已验证；离线模拟只能验证协议，不能替代实际辅助模型测试。辅助模型在事先固定的能力验证样例上须 100% 通过，每次预定复测均须满足，不能挑选成功轮次。预期明确的样例返回无法判定也算未通过；只有预期本就无法判定的样例，正确拒绝判断才算通过。全部样例通过不证明对未见输入永不出错，正式评分仍保留无法判定出口。样例规模、复测次数和配置在实际测试前固定，真实调用另行授权。

正式评分冻结比较规则、程序和辅助模型、提示、参数、调用与重试上限，保存具体输入、原始响应、对应关系、依据和最终判定；评分模型不按待测方法名称偏向某组，重算复用已固定判定而非重新抽取一个有利结果。Gold 与逐项评分输入只在获准私有评分空间使用，不回流到提取请求或同轮提取修正。

人类负责评分前的 Gold 审定、参考样例与评分器验证，以及评分后的结论审核；正式评分不现场逐项人工裁分。Agent 识别的新表达可在开发阶段或本轮结束后由专家审阅，明确适用范围、制作正反回归样例，再通过工程审核纳入新版程序规则。单条识别获认可不等于通用规则获批准；不得在同一轮中边看预测边改规则。需要重评分时建立新版本并重评全部受影响结果，不只修正有利个案。

### 正式评分前的 Gold 核对

在获准范围内核对固定 Gold 的覆盖完整性、科学审定、对象与条件对应、PDF/LaTeX 版本及材料范围，并固定文件指纹。R07 验收不自动证明后续评价的全部范围都已可无歧义判分；影响判分的缺口未解决时，不启动该范围的正式评分，也不因已看到预测而临时删除难例。

Gold 保持 PDF 标注格式，不新增为统一排版而进行的答案重写或整批格式对齐。发现真实科学错误仍按修订约定处理。论文自身未解决的冲突可以有明确的参考答案——保留双方原值并报告冲突；这不同于 Gold 尚未确定应该怎样标注。Gold 准备缺口、提取结果未决和评分器无法判定分别记录，不能相互替代。

### Gold 的局部修正与 Git 历史

已由人类专家明确裁定的局部修正，可以直接维护当前 Gold，用私有仓库的 Git 历史记录修改。专家在会话中对具体对象、数值和处理方式的明确决定就是修订依据；在该范围内完成修改和检查，无需再为相同科学问题制作整套保存批准。科学规则、整批标注范围或材料版本发生较大变化时，先审定方案与影响。Git 提交和推送仍遵循维护规范的操作授权。

局部修正直接修改 `data/annotations/<document_id>/vN/answer.json` 和同目录的 `metadata.json`。沿用已有目录与版本索引，不建立 `current/` 副本，也不为每次修正新增 `vN`。检查通过后刷新原文件的读取指纹，历史内容由 Git 保存。旧批准及操作记录保留其原始含义，只对应当时保存的内容。

读取始终通过已有版本索引定位原文件，检查答案、元数据和索引是否一致。历史保存查询应明确指出内容已经修订，旧保存或恢复操作不得覆盖修订后的答案。更新中断或文件不一致时应报错，修复完成后再读取。

局部检查涵盖受影响的对象身份、数值、条件、原文证据、材料指纹和覆盖说明。元数据保留原标注者及既有材料依据，并记录本次修订者、人类审阅者、日期和简明原因；格式通过不自动证明科学正确，也不自动提交 Git。尚未提交的修改只能作为工作副本，不能声称已经拥有 Git 历史版本。

评价使用固定的私仓 commit、答案与元数据路径及文件指纹，并绑定科学规则和论文材料。运行前核对这些输入；不得只保存一个会随编辑变化的当前路径。历史评价继续使用原快照，不因当前答案修正而改变其依据。分层、匹配与无法判定处理的评分方案见 [分层评分与匹配](#分层评分与匹配)。

以下涉及逐版准备、批准绑定和事务保存的说明适用于既有不可变保存路径；局部修正采用本节约定。

#### 旧格式与可复用部分

只读检查旧仓的 `src/stella/benchmark/hvs_contribution_gold.py`、`gold.py`、`src/stella/lit/hvs_contribution_models.py` 与 `schema_specs.py` 后，首版支持 `benchmark.hvs_contribution_annotation` v4。该版本与新规则使用相同的 18 个物理量编码；更早版本还涉及物理量范围、已移除字段及区间解释的差异，不静默升级。R07 若发现正式输入不属于已支持版本，应先报告并补充对应方案。

以下只说明迁移差异，当前字段与科学含义见 [数据记录与填写格式](records.md)，不在此复制完整定义。

| 旧格式内容 | 处理方式 | 不能由格式转换完成的部分 |
|---|---|---|
| 论文编号、标注者、时间、规则版本和标注过程 | 原始材料及迁移报告留档；正式元数据只保留必要身份、模型和材料版本信息 | 旧规则版本、旧批准记录不能替代新规则和本次批准；论文编号不能补出未给定的版本 |
| 对象名称、贡献类型和研究摘要 | 原样进入草稿；旧条目位置写入转换报告，正式贡献使用论文范围内的技术编号 | 不根据名称相似合并对象，不自动改写摘要；摘要和贡献类型各自所需证据须核对 |
| 18 种物理量及数值、误差、单位、条件和来源 | 保留原始字符串、分组及全部多值；只有明确表示缺值的空字段才转为新格式的空值 | 不补数字、不换算单位、不根据空条件推断“原文未报告条件” |
| 区间解释、覆盖概率、分位点、具名误差分量和表示方式 | 保留已填内容，复用适用的共同科学校验 | 不推算包含关系、置信水平或总误差；旧格式不接受的原文表达留待 R07 核查 |
| 作者总体状态 | 在迁移报告中保留原状态并列出对应建议；正式答案只保存获审定的新状态及其证据 | `not_assessed` 与 `no_overall_conclusion` 涉及规则变化；不能由程序确认作者含义或推导新增的 `possibly_bound` |
| 数值及其 PDF 位置、可选引文 | 原样保留，作为新 Gold 的 PDF 证据输入；另记旧条目对应 | 不能虚构文件哈希、页码、缺少的引文或每个数值组件的直接证据；不要求转换成源码行号 |
| 数值冲突的原因和证据列表 | 保留冲突及所有旧证据，列出结构缺口 | 旧格式没有要求冲突双方的完整数值结构，不能凭原因文字编造双方数值 |
| `reviewed_exclusions` 的原因和证据 | 完整保留为待对应项目 | 旧结构没有独立对象标识字段；不能根据自由文本自动制造被排除对象 |
| `contributions_found` / `no_contributions` | 保留为旧标注结论 | 不能据此声明新材料名单完整或 18 种物理量全部检查完成 |
| 旧 `canary` 等归档信息 | 在原始输入中保留并检查完整性，不复制到正式答案或元数据 | 不当作科学审定凭据，不复制为新答案的批准标记 |

迁移结果先形成可继续补充的草稿和逐项报告。缺少新格式必填信息时保留原始输入及待办，不为通过校验创建伪造的有效记录。报告定位旧条目和拟对应的新条目，覆盖保留、格式调整、待补资料和科学待核查项目；任何未处理字段都须显式报告。技术缺口不自动转成论文材料缺失、科学未决或排除结论。

#### PDF 证据与共同定义的边界

旧 Gold 的 `evidence_basis` 固定为 `pdf`，证据只有自由文本位置和可选引文。当前共同证据记录要求固定来源、文件、非空原文摘录及文本行、表格单元格或数据元素定位，没有 PDF 页定位类型。共同名单的 `method` 还表示两种自动提取方法，不能给专家标注随意填写一种方法。

专家审 PDF、模型处理 LaTeX 是新旧项目延续的分工。Gold 在 `evaluation` 中使用独立的标注外层和 PDF 证据结构，复用科学词表、数值表达规则及适用的校验逻辑；不直接套用完整的提取运行记录。旧仓代码只读参考，新工具不依赖旧仓运行环境。

保留旧证据的位置说明和可选引文，增加对固定 PDF 文件的引用；另设可选的 PDF 文件页序号，明确与书页上印刷页码的区别。旧位置中的页、表、节或对象行说明逐字保留，不通过正则猜出页序号。位置明确时不强制为每条旧证据补引文；缺失必要定位或无法绑定 PDF 文件时，草稿报告待补信息。

PDF 检查包括文件是否存在、哈希是否匹配、能否打开，以及已填写的文件页序号是否越界。表格、公式和扫描页面可能无法可靠提取文字，引文匹配只提供辅助检查结果；不能用全文搜索命中证明对象、物理量或科学判断正确，也不能把不能自动检查写成检查通过。R06 用生成的合成 PDF 覆盖上述行为，R07 由专家核对真实证据含义。

新旧材料范围的核对独立于 PDF 定位。Gold 保存已知的论文版本、PDF 与提取材料的对应及差异；未给出的版本和对应信息保持待补。保存旧答案本身的记录不能证明已核对新评价输入。

论文版本与 Gold 修订版本分开记录。材料对应保存所覆盖的 PDF、固定 LaTeX 文件或资料包及其版本、哈希，以及人类核对者、时间、依据和已知差异。未完成对应核对时阻断正式保存；已知差异须明确纳入批准，并由后续评价确定适用范围。工具检查记录完整性与材料哈希，不独立判定两种材料的科学内容等价，也不将 LaTeX 用作专家 PDF 证据的替代。

实现时先区分可直接复用的科学字段与依赖源码证据、运行绑定的字段。为共享数值校验而作的内部整理须保持 R04 既有格式及行为，并回归其生成检查和测试。Gold 的名单、未决问题和审定记录不填写虚构的自动提取方法、执行编号或框架进度。

#### 检查与保存行为

迁移草稿和全新草稿共用检查、批准内容绑定、保存与结果查询入口；全新草稿不要求旧答案。普通函数即可组织这些顺序步骤，无需新增 LangGraph 流程。共同数值定义及适用的引用校验尽量复用，Gold 专有的版本、审定、材料范围和来源关系由 `evaluation` 管理。

检查分别报告结构与引用错误、材料对应缺口和科学待核查项。科学待核查项由 R07 专家处理；按规则明确保留的科学未决状态可以接受审定，不能把“未决”一律强行改成确定答案。工具不把结构检查通过自动解释为科学审定通过。

获准保留的科学未决状态和未覆盖范围进入正式答案，使用简明的英文说明，并与具体审阅内容一起固定；已经解决的待办及迁移核对编号留在工作报告中。部分范围内没有贡献，不代表整篇论文已经确认零贡献。材料检查覆盖所有 PDF 证据，包括排除记录和冲突备选中的嵌套证据；文字提取能力按实际检查的页面范围报告。

批准应绑定具体答案内容、材料与规则版本、目标位置和预期旧版本；批准后改动这些内容须重新审定。旧批准保留为来源，不能自动变成本次批准。保存前在锁内再次检查输入及目标，使用稳定操作标识识别重试；同标识异内容拒绝。保存需一起保证答案、审定及来源记录的一致性，旧输入只读。

第五关已有事务、操作回执和恢复能力可供复用，但 Git 中正式 JSON 文件的多文件保存不能仅凭 SQLite 事务就宣称原子完成。版本入口与恢复顺序见下节；已保存而返回失败时应报告原结果，不再创建第二份答案。接口保存不执行 Git 提交或推送。

#### 草稿、正式答案和接口职责

正式 Gold 每版由两个文件组成：`answer.json` 保存用于评分的科学答案和 PDF 证据；`metadata.json` 保存论文标题与版本、格式和科学规则版本、固定材料对应及文件指纹、简短标注身份和审阅依据。文件格式由 `evaluation` 的有类型定义生成，字段说明、JSON Schema 与英文填写模板见主仓 [生成文档](../../contracts/generated/gold/README.md)，生成检查纳入交付。当前文件名按用途命名，旧输入与工作草稿的格式说明集中在 `legacy/`。文件内部的格式版本用于选择并校验读取规则，与正式 Gold 修订目录、论文版本和科学规则版本分别记录；含义见 [版本说明](../../contracts/generated/gold/README.md#what-the-version-numbers-mean)。旧 v4 输入和第一版迁移草稿仍可读取；转换不能静默丢弃未知字段或科学内容。

贡献编号使用 `<arxiv_id>:candNN`，从 `cand01` 开始；它是技术编号，不要求原文证据。科学字段按 `value` 在前、对应 `evidence` 在后组织，包括贡献类型、摘要、总体束缚判断，以及排除和数值冲突的原因。数值的单位、误差、条件与来源放在同一条值记录中。同一物理量在不同条件下的结果分别保留证据，不合并成唯一值。缺失的可选字段省略，有科学含义的空列表、未决状态和部分覆盖说明保留；空字符串或缺少条件不能被解释成“原文没有条件”。

`legacy_index`、`legacy_status`、原始迁移过程、任务路径和草稿待办不进入上述两个正式文件。转换报告在私有工作目录中保存旧新编号对应、逐项处理依据和输入指纹。证据中的文件引用在元数据中解析；答案和元数据须作为一对检查，不能只替换其中一个文件。

迁移草稿保留旧输入的完整内容和哈希、已能对应的条目、逐项比较及尚未解决的缺口。草稿允许不满足正式答案的必填要求，但必须满足草稿自身的结构约束；不能用伪造证据或默认科学状态补齐。正式答案只接收通过所定格式检查、并获专家审定的具体内容。新的标注者和审定者身份与旧标注来源分别保存。

原始专家按获确认的来源记录填写，例如 will 或 shunhong_deng，姓名不作为默认值。元数据保留原标注者、有可靠来源的协作模型和本次审核者、协作模型。历史日期按实际精度记录，不补造时刻；历史模型无法确认时省略，不把更早版本的协作模型冒充当前来源版本的模型。完整历史记录留在只读原始输入中。

元数据中的内容、材料和范围审阅不等于正式保存授权。正式保存仍要求人类专家对具体准备内容的批准；批准及事务记录由受控操作存储单独保存，绑定答案和元数据，不把冗长操作记录复制进答案。AI 身份不能提交人类批准。身份记录使用声明的稳定标识，不引入登录认证系统。

转换入口按显式对应分配论文范围内的贡献编号，同时保留冲突和排除引用。已经符合当前格式的编号保持稳定；格式读取检查唯一性和论文归属。文件引用和真实身份资料须明确提供，工具不通过编号整理补造科学内容。模板由生成器输出完整可解析的 JSON，测试同时验证模板解析和字段约束，不能只检查生成文件同步。

提供以下 Python 共同接口，并由命令行作薄封装。

| 操作 | 输入与结果 | 写入边界 |
|---|---|---|
| 迁移 | 指定旧文档、版本和可选的已知材料清单，返回草稿及对应报告 | 只写显式指定的草稿工作目录，旧输入只读 |
| 比较 | 固定的旧输入与指定草稿/新答案，返回逐项差异和未对应内容；精简答案须另给显式旧新映射，不能从新编号猜旧条目位置 | 只读；报告包含所比较内容及映射的哈希，不自动修订答案 |
| 检查 | 迁移或全新草稿、明确的材料根目录，返回问题与验证范围 | 只读；结构、文件、定位与科学待审状态分别报告 |
| 准备保存 | 已完成草稿、目标及预期旧版本，生成待批准的完整内容清单 | 保存可审阅的准备材料，不更新正式答案 |
| 获准保存 | 准备清单、针对该内容的科学审定及保存批准、操作标识 | 锁内复核后保存；新建和修订都检查目标前提 |
| 查询/恢复 | 操作标识、目标及已保存的准备材料 | 先核对实际结果；需要继续写入时仍按原批准及前提复核 |

准备保存时先完成确定性的格式整理，随后固定答案、材料、规则、来源与目标前提的完整清单，供专家审阅并绑定批准。不能批准一份草稿后，再让保存步骤自动改变科学内容或补填默认值。检查报告随准备内容固定；修改内容后重新准备。批准记录保存操作者、时间、范围及依据，工具只验证它与具体内容的绑定，不以自动生成 `approved=true` 代替真实授权。

保存采用不可变内容文件和最后更新的版本入口：先写入暂存区并核对答案、元数据及绑定它们的批准记录，再将文件发布到确定的路径，最后在锁内核对预期旧入口并原子更新版本入口。入口引用完整文件清单及哈希；读取者只接受文件全部存在且一致的入口。初次保存要求该文档尚无正式版本入口，受控存储目录可以已存在；修订要求前一版本与批准时一致，保留旧版本。部分写出的文件在入口发布前不算正式答案。

操作日志在任何正式写入前持久化，记录操作标识、准备清单哈希、预期旧入口及新入口。相同操作标识、相同内容重试时查询并返回原结果；相同标识异内容拒绝。在最后入口更新前退出时，恢复核对原批准、文件和目标后继续或报告冲突；入口已更新但回执尚未返回时，恢复根据入口及操作记录确认已保存，不再发布第二个版本。遇到不能解释的文件/日志不一致时保留现场并停止，不覆盖它来宣称恢复成功。中断恢复须用独立进程验证。

查询保持只读。获准恢复或后续修订时，先核对已发布入口及对应操作日志，补全中断留下的操作结果，保证后续修订后仍能核对原回执。

正式文件位置遵循 Gold README，工具目标指定为私仓 `data/` 子目录，仓库根保留文档和 Git 元数据；读旧输入、草稿工作目录和正式目标三者必须可分别指定。初始化、路径越界、符号链接和已有非托管文件的保护沿用工作空间原则，不能仅因给了输出路径就接管其中已有资料。正式答案和含答案报告排除在提取输入、主仓测试及发行包之外；本关全部流程在合成临时目录内验证。

#### 合成例子与预期结果

以下为虚构片段及行为预期。测试以完整合成输入覆盖迁移草稿及全新草稿两条路径；实际验证结果与适用范围见当前交接。

| 情形 | 预期行为 |
|---|---|
| 对象 `SYN-A` 的旧值为 `"612.0"`，误差为 `"8.0"`，单位为 `"km/s"` | 草稿逐字保留，不改成 `612`；证据不全时继续报告缺口 |
| 旧状态为 `not_assessed` | 保留旧状态，列出需 R07 核查的对应建议；不自动审定新状态 |
| 旧证据为 `"Table 2, row SYN-A"`，引文为空 | 草稿保留位置；不生成源码行号或声称引文已验证 |
| 旧答案为 `no_contributions`，没有新材料检查范围 | 保留旧结论，不能生成“新名单完整且为空” |
| 冲突只有两条位置及原因，没有双方数值 | 保留旧冲突并报告待补结构，不猜测两组数值 |
| 全新草稿提供完整合成 PDF 及标注证据 | 无需旧答案即可检查；模拟审定及保存批准后能够保存 |
| 批准 `"612.0"` 后将草稿改成 `"613.0"` | 原批准不再适用，拒绝保存 |
| 保存中断，或保存已完成但调用者未收到回执后重试 | 核对实际结果，恢复到一致状态；成功保存仅一份，同操作标识异内容拒绝 |
| PDF 被替换，或填写的文件页序号超出合成 PDF 页数 | 报告文件或定位错误，拒绝按原批准保存 |
| 有明确 PDF 位置但引文为空，或页面文字无法可靠提取 | 保留位置及已知验证结果；不以空引文单独判错，不声称自动完成语义核查 |

### 专家裁决的对照实验

比较关闭与开启运行中专家裁决的结果，评价其对名单、数值、证据、完成程度及专家工作量的影响。以相同论文版本逐篇配对，固定科学规则、提取方法、模型配置、自动提取提示及评分标准；涉及歧义处理方式的差异在实验前写明。可保存裁决前的同一份自动结果，分别建立两组的后续执行，使比较聚焦于裁决带来的变化。

比较本轮专家介入的作用时，两组使用相同的既有判例快照，也可共同使用空判例库；判例的作用另行比较。实验中新决定及由其起草的判例不加入任一组的固定判例输入。本轮没有专家参与的组若使用了既有专家判例，报告须写明这一条件。既有判例与评价论文的独立性按上述评价材料要求检查。

保留两组完整输出，分别报告质量、覆盖、未决情况、调用用量与专家用时，以及逐篇比较的变化；部分结果和失败仍计入事先规定的评价范围。专家裁决时不查看 Gold 或评分反馈，本轮裁决也不能直接作为同一实验的参考答案。实验方案在运行前明确比较的处理阶段、专家可操作范围、歧义处理方式、轮次、预算和通过条件，再执行获准的真实实验。

### 提取与评分的集成入口

日常与评测共用一个提取入口（`hvs_catalog.pipeline`）：请求为强类型字段，不含 Gold、评分或答案路径，也不接受自由 metadata；方法与步骤经可信登记表查询，当前只登记合成模拟实现，命令行 `hvs-catalog methods` 如实列出实现标记，不把尚未实现的真实名单方法冒称可运行。入口支持专家裁决开关与固定输入冻结恢复，行为遵循 [裁决开关](review.md#专家裁决开关) 与 [保存要求](architecture.md#保存恢复与版本)。

#### Gold 适配与就绪门禁

评分侧（`hvs_catalog.evaluation`）提供既有 Gold 共同定义到评分输入的纯内存适配：原报数值、误差、单位、区间解释、条件与来源逐字保留，证据位置与引文进入诊断 sidecar。数值未给条件（空缺）时拒绝适配并报告准备缺口——字段缺失不等于“原文未报告条件”的科学断言，不能为评分匹配补写条件；原已明确填写并审定的条件说明逐字保留。

compact 配对适配先执行内存可完成的绑定校验（论文、scope、`answer_sha256` 与证据文件声明）并保留绑定供报告与计划核对，再复用 Gold 完整检查器中不读文件的同一准备检查（`pair_preparation_problems`，与正式保存检查共用判定、不削弱）：缺源对应、在案 PDF/源材料差异、数值/对象/作者判断缺证据、缺条件、未决待办、未结构化冲突等材料与科学缺口全部进入就绪缺口并程序化阻止就绪输出（不是文档免责声明）；已审定且结构完整的保留冲突双方不是待办，正常映射。

answer-only 输入不做 metadata 绑定核对，不构成正式就绪：严格条目入口对缺 metadata 的答案程序化拒绝并指向 `adapt_compact_answer` 非正式结构映射（保留 `binding=None`、`formal_readiness=False` 与 `limitations`），不返回可被评分器当作就绪的裸条目；严格入口同时核对绑定与就绪状态，合法已绑定配对与 v1 正式答案不受影响。部分覆盖的 Gold 必须由获准的评分准备方显式声明封闭子范围，不能从自由文本范围说明推导；草稿与带未决待办的标注存在准备缺口，不进入评分。适配不读真实仓、不改写 Gold 文件；真实 Gold 的读取与使用仍按授权边界执行。

#### 合成演示与重评

合成演示入口（`hvs-catalog extract demo` 与 `score demo`）覆盖共享提取、暂停与模拟决定恢复、输出保存、输入指纹核对与新进程重评；评分输入集绑定完整计划（覆盖范围、程序/规则/材料/Gold/辅助引用与版本）的规范摘要，任一内容被改动时拒绝按旧指纹重评。

#### 两组对照实验报告

两组对照实验按 [对照实验要求](#专家裁决的对照实验) 执行：开关是唯一差异，模拟专家决定来自固定合成材料，不从 Gold、评分或诊断读取；报告逐论文给出分层质量、完成/未决/失败、问题与专家次数、调用用量与专家用时，不合成总分，未知用量与用时为 null。

报告的科学完成状态（pending/partial/complete/failed/unfinished）与运行图终止状态分开：图 finished 只说明流程不再执行，存在开放或已答仍未决的科学问题、名单未决条目、未列清的原文范围（unresolved_groups，按既定语义保留未决）或未决作者总体判断时不报 complete，也不得以运行终止状态或交付率冒称科学完成率；名单覆盖不完整（coverage 非 complete）或带未处理材料缺口、作者总体判断仅因材料缺口未完成（status=None 且只有 gap_refs）而无科学待决时报 partial 并列具体原因；科学未决与运行错误分别记录，不互相伪装；单组或两组失败仍生成完整两组报告，已存名单与数值照常计分、分母完整、原始错误与用量保留。

运行不再计算或填报货币费用，兼容边界见 [运行记录要求](architecture.md#保存恢复与版本)：历史有值字段仍可读取，旧账本打开时事务化迁移并保留历史行，持久化演示的模拟账单是明示例外。

### 英文输入的核对与评价

提取实验使用实际准备发布的英文规则、提示、字段说明、例子和判例，按同一科学目标检查质量、完整性、未决情况和专家负担。科学含义由专家审定，文本结构与生成同步检查不代替真实提取效果验证。

最终评价前固定实际英文输入。之后修改英文规则或提示等提取输入，须重验受影响部分；仅将专家文档或网站说明转为英文，检查语义、链接和版本对应即可。未来若另行研究语言效果，再单独审定实验方案与范围。
