# 专家裁决与判例设计

说明自动判断与专家裁决的边界、运行配置和判例复用。问题与决定的字段见 [记录格式](records.md#疑问决定与处理状态)，对照实验见 [评价设计](evaluation.md#专家裁决的对照实验)。

## 专家裁决与判例

### 自动判断与专家裁决

日常运行按提取规则 [S03–S04](../science-rules.md#s03-check-the-inclusion-evidence-and-contribution-type) 和 [S07](../science-rules.md#s07-check-completeness-and-handle-unresolved-questions) 处理收录、作者判断和科学疑问。材料齐全，原文含义、对象归属和规则适用均明确时，由提取者直接处理；参考判例后仍需揣摩作者倾向或权衡相互矛盾的表述时，交人类专家裁定。纯 AI 对照实验的处理方式见 [专家裁决开关](#专家裁决开关)。

系统分别保存论文的作者状态和任务的处理进度。“无总体结论”是作者状态；提取者无法确定原文意思时保存待裁决，材料缺失或解析失败时保存未完成。待决对象不能自动排除。提交裁决时，附相关原文、条件和已提取的数值，简短说明疑问，无需先猜出结论。

按 [S06](../science-rules.md#s06-check-object-assignments-duplicates-and-conflicting-values) 保留数值冲突及其证据。专家仍无法消除冲突时，受影响的测量保持冲突未决；只要对象收录和身份不受影响，其他已确认结果可继续进入关联和星表整理。

### 专家裁决开关

日常运行与评测共用的提取入口提供“是否启用运行中专家裁决”的配置，默认开启，两种名单方法及共同的后续步骤都使用该配置。发现科学疑问、保存证据和处理结果共用原有流程；是否请求专家由统一入口处理，避免维护两套提取流程。裁决开关与名单方法、模型选择分别设置。

开启时，按科学规则提交歧义并通过裁决接口恢复。关闭时，不请求或等待本轮专家裁决，发现的疑问及其处理结果仍须保存。开关控制运行中的个案裁决，Gold 审定、正式星表保存和发布的授权仍按各自流程执行。

纯 AI 对照实验允许模型依据相同论文材料和科学规则，尝试处理日常流程中通常交给专家的解释歧义；仍无法判断时保留未决，不强制给出结论。这一例外仅适用于纯 AI 实验组，提取范围、作者原值和原文证据等要求照常适用；材料缺失或技术失败仍记录为未完成。模型作出的判断按该实验组的模型结果保存，不能记作专家裁决或直接进入已审定判例库。

日常提取指令只说明遇到歧义时提交专家。系统在获准的纯 AI 实验中单独提供相应的歧义处理说明，明确替换这一处理要求，其余科学要求保持相同。实验切换、两组结果隔离与固定判例由程序负责，不把整套实验安排写入日常提取规则。

配置由程序记入运行清单，并参与保存、恢复和结果复用的检查。两组结果分别保存，关闭组不能使用开启组在本轮新增的专家决定或据此产生的结果。改变配置后建立新的执行，不能在原运行中悄悄改变裁决方式。对照方法见 [专家裁决的对照实验](evaluation.md#专家裁决的对照实验)。

### 裁决共同接口方案

`ReviewService` 提供以下 Python 接口，事务、锁和恢复机制见 [工作空间与恢复接口方案](architecture.md#工作空间与恢复接口方案)。网页与裁决 CLI 由 R20 接入，判例由 R21 接入。

| 接口 | 输入 | 返回与行为 |
|---|---|---|
| `create_question` | 执行、步骤、创建请求键、问题内容及预期结果修订 | 由程序生成编号、修订和指纹，问题、执行/步骤绑定与回执在同一业务事务保存；同请求同内容返回原问题（含原绑定）。 |
| `list_questions` / `get_question` | 空间内执行、步骤或准确问题引用，可筛选是否仍需处理 | 返回问题、原文证据、固定版本、已有答复和应用状态；答复后仍未决的问题可继续查到。引用的修订必须存在，查询不隐式回退到最新。 |
| `submit_decision` | 执行/步骤、准确问题引用、指纹、请求键、操作者、原答复、英文答复、理由、证据、结果及可选补丁 | 先校验适用性（含引用修订存在且适用），再可靠保存；返回决定引用和保存回执。返回值明确区分首次保存与重复提交，不承诺流程已经恢复。 |
| `supersede_question` | 原问题当前修订引用、新问题的完整上下文及原因 | 为变化后的问题建立新记录，保存与旧问题的关联并将旧问题追加为失效修订；保留旧答复。只能替代当前修订。 |

问题编号由逻辑空间、执行与完整内容共同派生，防止不同空间中相同的执行编号串用决定。问题必须绑定执行与步骤，缺失绑定不视为通配。核对材料、规则和目标时使用准确修订：首次提交须指向当前修订；已答复问题只接受保存回执关联的答复前后修订，不存在或链外的修订拒绝。

指纹与完整内容摘要共同用于核对，不能忽略正文、上下文或提交所指向的修订。历史修订仍存在不代表它仍接受新答复；恢复前的文件核验见 [保存与恢复规则](architecture.md#锁提交与恢复顺序)。

请求键由调用方在重试时复用，比较内容排除程序生成的编号、时间和回执字段，包含操作者、完整答复、理由、证据和补丁。同一请求同内容返回原回执；同键异内容拒绝。重放入口同样核验提交引用：只承认原成功回执明确关联的原修订与答复修订，不存在或无关的修订不构成同一请求，不能因摘要命中就把任何修订当作重放。对同一执行的同一问题版本，换请求键提交相同内容也返回原决定，提交不同内容拒绝。先查已成功的重放，再判问题当前状态，避免把已经成功的重复提交误报为过期；如果该问题随后失效，回执须同时显示已失效且不可再次应用。

只接受属于本执行且当前有效的问题。跨空间、跨执行、跨步骤、过期材料/规则/目标修订，以及关闭专家裁决的运行提交本轮专家决定均拒绝。专家决定接口只接受人类操作者；纯 AI 合成处理使用 `RunRecord.model_judgments`。已有决定的引用必须来自运行固定的允许集合，不能通过更换 ID 或重写执行标签绕过隔离。

答复与处理状态区分如下：

| 已保存内容 | 问题记录与待办显示 | 结果和流程 |
|---|---|---|
| 尚无答复 | `open` | 保留待裁决。 |
| `outcome=unresolved` | 新问题修订为 `answered`，引用决定；显示“已答复，仍未决” | 不应用结果补丁，不自动排除对象；受影响步骤保留等待，其他独立任务仍可推进。 |
| `outcome=resolved` | 新问题修订为 `answered`；应用回执尚未完成时显示“已答复，待应用” | 受控应用并验证结果，再恢复对应步骤。 |
| 原问题被替代 | 原问题追加 `superseded` 修订，关联新问题 | 旧决定只保留历史，不能应用到新问题。 |

`answered` 只表示收到答复；仍未决的事实来自决定的 `outcome`。`unresolved` 答复携带结果补丁时接口拒绝。需要再次征询或纠正旧答复时，由调用者显式建立后续问题并关联旧问题，不能覆盖旧决定；材料和规则未变也要形成新的问题身份。

当前接口接受论文贡献或名单条目补丁。组合字段先应用到副本，再整体校验目标条目，实际保存前还要核对完整记录集合与当前输出。`resolved` 但没有补丁时，只能由可信步骤适配器使用明确、已审定的确定性处理；如果该步骤无法据此构造结果，保存决定并报告应用受阻，禁止从答复自由文本推断科学修改。跨论文对象合并/拆分的具体处理由 R18/R20 接续。

`records.patches` 提供补丁应用的纯函数，校验和实际应用共用目标定位与字段约束。函数不写数据库、不分配正式修订、不改变输入对象；运行层分配新修订并提交。若需要扩大补丁类型、改变科学含义或填写结构，先交 Astra 评估和专家审定。

对外错误至少区分空间忙、未知空间/格式、记录或材料损坏、预期修订过期、决定冲突、裁决配置不允许和恢复不一致。错误给出执行、步骤和记录引用，保留已经成功保存的决定；不能把保存失败返回成“已裁决”，也不能把恢复失败返回成“决定丢失”。

### 判例的录入与复用

判例解释主规则的适用方式，不改变主规则。专家核对其与主规则一致后，才纳入可复用库。冲突或一致性尚不能确认的内容不能入库；规则需要调整时按 [科学规则维护](../../CONTRIBUTING.md#科学规则维护) 单独审定。

专家保存个案决定后，原任务按该决定恢复。模型另行依据原文证据和已保存的决定起草简短英文判例，保留可复用的理由、适用条件、必要边界及原裁决关联。起草失败、等待审核或未获通过均不阻塞原任务恢复，草稿不可复用。

提取者遇到不能直接依据规则解决的科学疑问时，流程按需查找判例，再让提取者结合本篇证据核对适用性；明确的问题直接处理。查找可先按关联规则和问题类别筛选，只提供少量相关的已审定英文判例。配置同时限制数量和总长度；超出篇幅时减少所选判例，保留每个判例必要的理由、适用条件和边界。

相似判例须经适用性核对，本篇事实和数值仍由本篇材料支持。没有相关判例或仍有歧义时，按 [裁决配置](#专家裁决开关) 处理，日常流程交专家，不能据此排除对象。查找失败保留技术失败信息，不能当成没有适用判例或据此作科学结论。

程序保存本次查找及实际提供的判例、版本和文本，恢复使用固定内容；未选中的库内变化不改变当前执行。提取者的简短复用说明遵循 [S07](../science-rules.md#s07-check-completeness-and-handle-unresolved-questions)，版本由程序统一记录，无需逐项填写。复用关联原决定，不能记成专家本次又批准了一次；本次裁决按 [记录职责](records.md#记录职责) 保存。

程序支持汇总重复问题、待办与专家用时。每次实验固定判例快照，日常新增判例不自动加入当前实验，具体要求见 [专家裁决的对照实验](evaluation.md#专家裁决的对照实验)。后续改进使用哪些开发工具和模型，由人类专家安排。
