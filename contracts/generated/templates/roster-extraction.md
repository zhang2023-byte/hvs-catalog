# Roster extraction filling format

Fill this format for the roster extraction step. All scientific content is in English; object names, values and excerpts keep the paper's original language.

## Provided by the application

Fixed paper and source context (paper key, source package files with identifiers and known material gaps with their identifiers), and all record identifiers, numbering, revisions and execution metadata.

## Filled by the extractor

| Filled by the extractor | Provided or assigned by the application |
|---|---|
| Roster material coverage: state, checked file identifiers, known gap identifiers | File identifiers, gap identifiers, record references |
| Entries: printed identifiers with inline evidence, disposition (`included` / `excluded` / `pending`), inclusion or exclusion evidence | Roster entry numbering (`item_id`), contribution numbering |
| For included entries: contribution summary, contribution type (`candidates_found` / `follow_up`), the authors' overall boundness assessment (one of 5 states or `null`), conditional assessments, each with inline evidence | Bound diagnostic identifiers; no human tasks |
| Unresolved printed ranges: original range expression, evidence, already identified members, reason | Group identifiers; no members are generated by the application |

## Citation and entry shape

Each citation is `{location, quote}`: select a supplied T: text location or I: image location and transcribe the original text. Do not supply file IDs, pages, locator wrappers, parts, or context flags inside citations. The application binds them to the fixed PDF.
Write summary, summary_evidence, contribution_type, type_evidence, boundness, boundness_evidence, conditional_assessments directly on an included entry. There is no contribution wrapper. Use boundness_author_errors or boundness_gap_ids for an assessment blocked by source errors or missing material.
In a correction turn, use only the supplied repair_roster fields R1, R2, etc. They refer to application-selected fields, not names of objects. All other content is retained automatically. Do not resubmit the roster.

## Required behavior

- `included` entries require inclusion evidence and full contribution fields; `excluded` entries require exclusion evidence; `pending` entries require source-error diagnostics or a known material gap. Excluded and pending entries never carry contribution fields.
- An assessment with status `null` must report source-error diagnostics or reference a known material gap; it must not be filled as `no_overall_conclusion`.
- `no_overall_conclusion` is a reading of the paper; the other four states require positive evidence inline.
- Interpret clearly identified numbered object ranges and submit each member as a separate entry with the original range as evidence. Do not expand individual names or physical numerical intervals. Preserve unidentified remainders as unresolved groups; never invent unnamed members.
- A known material gap that names an inclusion or identity judgment keeps the roster coverage partial with that gap referenced; only quantity-scoped known gaps can leave roster coverage complete, and an unknown-scope gap always keeps it partial. A complete roster claim never contradicts an open gap.
- Every identifier must appear in exactly one entry; if two printed names may denote the same object, choose the best-supported interpretation under S07 rather than merging silently.

## Common instructions

> Return only the scientific fields requested for this step. Write new summaries, interpretation rationales and diagnostic reasons in English; preserve printed identifiers, values, units, conditions and excerpts in their original form. Use only supplied paper materials. Provide required lists explicitly; an empty list does not establish that the paper reported nothing. Keep material gaps, parser errors, source errors, conflicting measurements and the authors' assessment distinct. Choose the best-supported interpretation under S07 and briefly record its evidence-based rationale. Source errors require original-paper evidence, definitions or explicit logical contradictions; unusual but possible values are not errors. Preserve errors and unexplained same-condition conflicts as diagnostics, omit affected claims, and continue independent results. Never invent a replacement value. Supply required evidence and use application-supplied identifiers. The application assigns persistent record identifiers, references and execution metadata.

The complete field structure is defined by `schemas/submission.roster.json`.
